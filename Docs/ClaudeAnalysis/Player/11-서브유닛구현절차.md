**핵심 두 가지**

1. **네 에셋은 전부 "보이는 것"만 맡는다.** 데미지·범위·쿨다운은 우리 코드와 `WeaponData`가 정하고, 에셋 프리팹은 풀링된 연출로만 쓴다.
2. **우리 코드는 에셋의 스크립트를 참조하지 않는다.** 에셋을 받지 않은 팀원도 컴파일은 되고 연출만 빠진다.

## 1. 원칙

### 1-1. 연출과 판정을 나눈다

| 구분 | 담당 | 예 |
|---|---|---|
| 판정 | 우리 코드 (`AreaDamage`, `DamageZone` 등, 4장) | EMP 반경 안의 적에게 1.5 데미지 |
| 수치 | `WeaponData` SO + `WeaponModifier` | 반경 2.5m, 레벨당 +0.3m |
| 연출 | 에셋 프리팹의 복제본 (`FX_*`) | 반경에 맞춰 크기를 키운 고리 효과 |

- 에셋을 바꿔도 밸런스가 그대로다. 연출이 마음에 안 들면 FX 프리팹만 바꾼다.
- 에셋 프리팹에는 데모용 스크립트(자동 삭제·충돌·이동)가 붙어 있는 경우가 많다. 이런 스크립트는 `Destroy`를 써서 풀링과 충돌한다.
- 연출 크기는 코드가 판정 반경(`Range`)에 맞춘다. 보이는 범위와 실제로 맞는 범위가 어긋나지 않는다.

### 1-2. 에셋 스크립트를 코드에서 참조하지 않는다

| 에셋 | 우리가 쓰는 것 | 우리 코드가 만지는 것 |
|---|---|---|
| Particle Pack | 파티클 프리팹 | `ParticleSystem`, `Transform` (Unity 기본 타입) |
| Magic Effects FREE | 파티클 프리팹 | `ParticleSystem`, `Transform` |
| plasma Shader | 셰이더 → 우리 재질 | 없음 (재질은 인스펙터에서 지정) |
| Lightning Bolt Effect | `LightningBoltScript` + `LineRenderer` 프리팹 | 시작·끝 **자식 Transform의 위치**만 옮긴다 (6-3) |

`DigitalRuby.LightningBolt` 같은 에셋 네임스페이스를 `using`하지 않는다. 에셋 스크립트를 직접 부르면, 에셋이 없는 팀원의 프로젝트는 컴파일 오류로 통째로 멈춘다.

### 1-3. 원본은 건드리지 않고 복제본을 쓴다

- 원본 프리팹을 `Ctrl+D`로 복제해 `Assets/Prefabs/SubUnits/FX/`로 옮긴 뒤 고친다. 이름은 `FX_서브유닛_용도` (예: `FX_EMP_Ring`).
- 원본을 고치면 에셋을 다시 가져오거나 업데이트할 때 덮어써진다.
- 복제본은 원본의 재질·텍스처·메시를 그대로 참조한다. 그래서 **팀원도 같은 에셋을 가져와야 복제본이 제대로 보인다.** Asset Store 패키지는 에셋 GUID가 고정이라, 같은 버전을 가져오면 참조가 그대로 이어진다.

### 1-4. 저장소 정책

- 네 에셋 모두 Asset Store EULA 에셋이다 (Particle Pack·Magic Effects FREE는 판매 페이지에 좌석 단위 라이선스인 *Extension Asset*으로 표기). Lightning Bolt 스크립트 머리말에는 "재배포·판매 금지"가 적혀 있다.
- 따라서 **공개 저장소에는 에셋 폴더를 올리지 않는다** (`.gitignore`). 무료이므로 팀원이 각자 자기 계정으로 받는다.
- 우리가 만든 복제본·재질·코드(`Assets/Prefabs/SubUnits/`, `Assets/Scripts/`)만 커밋한다.
- 가져온 버전을 부록 A에 적어 둔다. 팀원이 다른 버전을 받으면 프리팹 구조가 달라 참조가 깨질 수 있다.

## 3. 1단계 — 연출 프리팹(FX) 준비

### 3-1. 폴더

```
Assets/Prefabs/SubUnits/
├─ FX/          에셋 복제본 (FX_*) + PoolConfig
├─ Units/       오브·미사일·장판 프리팹 (SU_*) + PoolConfig
└─ Materials/   M_PlasmaOrb, M_Lightning_URP 등
Assets/Prefabs/Weapons/        무기 프리팹 W_* (기존 위치)
Assets/Scripts/Data/Weapons/   WeaponData WD_* (기존 위치)
```

### 3-2. 한 번 터지고 끝나는 효과 (폭발·스파크·방전·예고)

기존 `Hit`·`BombSkillEffect`와 같은 구성으로 만든다. 이 프로젝트의 풀링 효과는 전부 이 방식이다 (`Poolable` + `EffectAutoReturn`, Stop Action = Callback).

1. 원본 복제 → `FX/`로 이동 → 이름 변경.
2. **루트에 ParticleSystem이 있는지** 확인한다. `EffectAutoReturn`은 `[RequireComponent(typeof(ParticleSystem))]`라서, 루트가 빈 오브젝트면 **기본 파티클이 자동으로 붙어 흰 점(또는 분홍 사각형)이 함께 나온다.** 루트가 비어 있으면 가장 긴 파티클을 루트로 올리거나, 자동으로 붙은 파티클의 Emission과 Renderer를 끄고 Duration을 가장 긴 자식 이상으로 둔다.
3. **모든** ParticleSystem의 **Looping 끔**. 확인한 원본은 거의 전부 Looping이 켜져 있다 (데모 씬에서 반복 재생하려고). 루트는 **Stop Action = Callback**, Play On Awake 켬.
4. `Poolable`, `EffectAutoReturn` 추가.
5. 모든 ParticleSystem의 **Scaling Mode = Hierarchy**. 코드가 `transform.localScale`로 크기를 판정 반경에 맞춘다. Hovl 효과는 이미 Hierarchy이고, Particle Pack 효과는 대부분 Local·Shape라서 바꿔야 한다.
6. 끌 것: `Light` 컴포넌트와 Lights 모듈, `AudioSource`, Collision 모듈. 원본에 붙은 스크립트는 삭제한다. (Hovl 마법진 4종·`Laser AOE`에 `Light`가 있고, Hovl 스파크·Particle Pack 스파크·`BigExplosion` 등은 Collision이 켜져 있다. 부록 B 후보 중 스크립트가 붙은 것은 없다.)
7. 색: 3-4 색 규칙에 맞춰 Start Color / Color over Lifetime을 바꾼다.
8. **기준 반지름을 잰다.** 스케일 1일 때 효과가 덮는 반지름(m)을 씬 뷰에서 재어 WeaponData의 `fxBaseRadius`에 적는다. 코드는 `scale = Range / fxBaseRadius`로 맞춘다.

### 3-3. 계속 켜져 있는 효과 (장판·오브 꼬리·연기 꼬리)

- 루프 효과는 `OnParticleSystemStopped`가 오지 않아서 **스스로 풀에 돌아가지 않는다.** `EffectAutoReturn`을 붙이지 않는다.
- 이런 효과는 부모 프리팹(장판 `SU_AcidPool`, 미사일 `SU_Missile`)의 **자식**으로 넣는다. 부모가 수명을 관리하고, 부모가 풀로 돌아갈 때 자식도 함께 꺼진다.
- 끝날 때 갑자기 사라지는 게 거슬리면, 부모가 수명 끝 0.5초 전에 자식 파티클 방출을 멈춰(`Stop(true, StopEmitting)`) 서서히 사라지게 한다.

### 3-4. 색 규칙

어떤 서브유닛의 효과인지 한눈에 구분되도록 색을 겹치지 않게 둔다.

| 서브유닛 | 주 색 |
|---|---|
| 플라즈마 오브 링 | 보라~분홍 |
| EMP 방전장 | 파랑 |
| 수리 나노봇 | 초록 |
| 궤도 폭격 위성 | 주황 (예고) → 흰색·주황 (빔·폭발) |
| 나노 산성 장판 | 연두 |

**판정 규칙 (B1·B2 공통)**

- 대상은 **`Enemy`·`Boss` 태그**만 인정한다 (`Bullet`과 같은 기준). 플레이어도 `IDamageable`이라서, 태그로 거르지 않으면 장판 위에 선 플레이어가 맞는다.
- 레이어 마스크는 검(`WD_Sword`)과 같은 `Default + Enemy` (`m_Bits: 129`)로 시작한다.
- 자식 히트박스가 여러 개인 적은 `GetComponentInParent<IDamageable>()`로 찾은 루트 기준으로 한 번만 센다.
- `DamageInfo.cameraShake`는 0으로 둔다. 항상 도는 서브유닛이 화면을 흔들면 쉴 새 없이 흔들린다 (폭격만 0.05 정도 검토).

**풀 효과를 플레이어 자식으로 붙이지 않는다**

플레이어는 `DontDestroyOnLoad`이고 PoolManager는 스테이지 씬마다 새로 생긴다. 풀 효과를 플레이어 자식으로 옮긴 채 반납하면, 씬이 바뀐 뒤에도 플레이어 밑에 남고 이미 사라진 풀에 반납하려 한다. 따라가야 하는 효과는 B5 `FxFollow`로 위치만 복사한다.

**씬 전환 안전장치**

무기(플레이어 쪽)는 씬이 바뀌어도 살아 있지만, 풀 개체(장판·미사일·예고 마커)는 씬과 함께 사라진다. 코루틴이나 목록으로 풀 개체를 들고 있는 무기는 쓰기 전에 `== null`로 확인한다 (`?.`는 파괴된 개체를 걸러내지 못한다 — 02번 H-2 함정).

> **2026-09-16 플레이 테스트 후 조정 — "파란 장판"**: 산성 장판이 파란 마법진으로 보였다. 원인은 두 가지이며 **에셋 문제가 아니라 설정 누락**이었다.

> 1. **색**: Hovl 재질은 흰색이고 색은 전부 파티클 Start Color 에서 나온다. `Magic circle` 원본의 파란색(`0.33, 0.49, 1`)이 그대로 남아 있었다 → 파란 계열 파티클 6개만 골라 연두(`0.45, 1, 0.2`, 어두운 쪽은 `0.25, 0.85, 0.1`)로 바꿨다. 회색 연기·거품(Particle Pack)은 건드리지 않았다.
> 2. **크기**: `fxBaseRadius` 류가 전부 1 로 방치돼 연출이 판정보다 4배 안팎으로 크게 그려졌다. 실측해서 넣은 값은 다음과 같다.

> | 대상 | 기준 반지름 | 판정 | 그려지는 배율 |
> |---|---|---|---|
> | `SU_AcidPool` (`DamageZone.fxBaseRadius`) | 5.95m | 1.5m | 0.25 |
> | 폭격 마커 | 5.68m | 1.5m | 0.26 |

> | 폭격 폭발 | 5.38m | 1.5m | 0.28 |
> | 미사일 폭발 | 6.72m | 1.2m | 0.18 |
>

>
> **교훈**: 새 FX 를 붙일 때마다 기준 반지름 측정을 같이 해야 한다. 원본 효과는 대개 5~7m 규모라 그대로 두면 판정보다 훨씬 크게 보인다.

> **2026-09-16 플레이 테스트 후 조정 — 미사일 "하늘색 사각형"**: 원인은 두 가지였고 둘 다 설정 누락이었다.

4. 적의 원점은 발밑이므로 번개 끝점은 `위치 + 위쪽 × hitHeight`.

- `Compose`: `Range = jumpRange + rangeAdd`, `MaxTargets = chainCount + projectileCountAdd` (10번 2-E).
- 연쇄 대상은 플레이어 감지 범위(10m) 안의 적으로 한정된다. 한계로 둔다.
- 대상의 `IDamageable`은 `GetComponentInParent`로 찾는다 (보스는 감지기가 콜라이더 쪽 Transform을 넘겨준다).

**② Lightning Bolt 작업 — 에셋 스크립트를 코드에서 부르지 않는 방법**

`LightningBoltScript`는 `StartObject`·`EndObject`를 지정해 두면, `ManualMode`가 꺼져 있을 때 `Duration`마다 두 점 사이에 번개를 새로 그린다. 이 성질을 이용해 **우리 코드는 두 자식의 위치만 옮긴다.**

```
FX_Tesla_Bolt (Poolable, BoltFx*, LineRenderer, LightningBoltScript)
├─ Start   ← BoltFx 가 시작점으로 옮긴다
└─ End     ← BoltFx 가 끝점으로 옮긴다

* BoltFx: 우리 스크립트. SetEnds(a, b) 로 두 자식을 옮기고 lifetime(0.15초) 뒤 풀로 돌아간다.
  반납할 때 LineRenderer.positionCount = 0 으로 지워, 다음에 꺼낼 때 옛 번개가 한 프레임 보이지 않게 한다.
```

1. `SimpleLightningBoltPrefab` 복제 → `FX_Tesla_Bolt`.
2. `LightningBoltScript` 설정: **ManualMode 끔**, StartObject = `Start`, EndObject = `End`, StartPosition·EndPosition = (0, 0, 0), **Duration 0.05** (0.15초 동안 세 번 깜빡임), Generations 5~6, ChaosFactor 0.15~0.25.
3. **재질 교체**: `Materials/M_Lightning_URP` 생성 → 셰이더 **Universal Render Pipeline/Particles/Unlit**, Surface Type **Transparent**, Blending Mode **Additive**, Base Map = 에셋 `Textures` 폴더의 번개 텍스처, 색 = 하늘색 HDR (강도 2~3) → LineRenderer에 지정.
4. LineRenderer: Width 0.15 → 0.05, **Use World Space 켬** 확인.
5. 원본에 데모 스크립트·오디오가 있으면 지운다.
6. **스파크**: Particle Pack의 전기 스파크 계열 → `FX_Tesla_Spark`. 5-2의 `FX_EMP_Spark`를 하늘색으로 복제해도 된다.
7. **코일 모델**: GunPack 부품을 조립해 `W_TeslaCoil`에 넣고 **등 소켓(B7)** 에 붙인다. 코일 끝에 작은 plasma 구(하늘색)를 달면 발사 지점이 눈에 띈다.

**③ 데이터** `WD_TeslaCoil` (초안)

damage 3 · fireInterval 1.2 · firstRange 6 · jumpRange 3.5 · chainCount 3 · falloff 0.8 · maxLevel 5 · perLevelBonus `projectileCountAdd 1` (연쇄 +1), `damageAdd 0.3` · requiresTarget true · socket **Back**
→ 첫 대상 DPS 2.5, 세 명 합계 약 6.1.

**④ 확인**

- [ ] 번개가 분홍색이 아니다
- [ ] 번개가 적의 가슴 높이에 닿는다
- [ ] 가까운 순서로 튀고, 같은 적에게 두 번 튀지 않는다
- [ ] 0.15초 뒤 번개가 사라지고, 다음 발동 때 옛 번개가 번쩍이지 않는다

### 6-4. 유도 미사일 포드 — Particle Pack

**① 코드**

- **`Bullet`을 고치지 않고 `HomingMissile`을 새로 만든다.** `Bullet`은 소총·기관단총·스나이퍼·드론과 옛 `Gun`이 함께 쓴다. 미사일은 발사 궤적(위로 솟은 뒤 휘어짐)과 폭발(B1)이 더 필요해서, `Bullet`에 넣으면 분기가 늘고 기존 총이 깨질 위험만 커진다. 10번 3-3의 "`Bullet`에 유도 추가"를 이것으로 바꾼다.
- `HomingMissile : MonoBehaviour, IPoolable`
  - 발사 후 0.25초는 위로 → 이후 대상 쪽으로 초당 최대 `turnRate`(360도)만큼 돌며 전진.
  - 대상이 죽거나 풀로 돌아가면(`activeInHierarchy == false`) 가장 가까운 적으로 다시 조준하고, 없으면 직진한다.
  - `Enemy`·`Boss` 태그에 닿거나 수명이 끝나면 B1 폭발 + `FX_Missile_Explosion` 후 반납.
  - 충돌은 `Bullet`처럼 **kinematic Rigidbody + Trigger 콜라이더**.
  - 꺼낼 때(`OnSpawn`) `TrailRenderer.Clear()`를 부른다.
- `MissilePodWeaponData`(`missilePrefab`, `missileCount 2`, `speed 12`, `turnRate 360`, `blastRadius 1.2`, `explosionFxPrefab`), `MissilePodWeapon`: `OnFire`에서 가까운 적 N명(`GetTargets`)에게 한 발씩 쏜다. 적이 N명보다 적으면 돌아가며 배정한다. 발사구는 프리팹의 `Launch_L`·`Launch_R`.
- B7 등 소켓이 먼저 있어야 한다.

**② 프리팹·에셋 작업**

```
W_MissilePod (MissilePodWeapon)    ← 소켓 Back
├─ Model      GunPack 부품 조립
├─ Launch_L
└─ Launch_R

SU_Missile (Poolable, HomingMissile, Rigidbody kinematic, SphereCollider trigger)
├─ Body     GunPack Barrel_Single 또는 작은 캡슐 (길이 0.4)
├─ Trail    TrailRenderer (흰색 → 회색, 0.3초)
└─ Smoke    Particle Pack 연기 계열 (루프, Simulation Space = World)
```

1. **연기 꼬리**: Particle Pack 연기 계열 → 방출량을 낮추고 Simulation Space를 **World**로 둬서 연기가 미사일 뒤로 늘어지게 한다. 루프이므로 `EffectAutoReturn`을 붙이지 않는다 (3-3).
2. **폭발**: Particle Pack 작은 폭발 → `FX_Missile_Explosion` (주황). 광원·소리를 끈다. 기존 `BombSkillEffect`로 대신해도 된다.

**③ 데이터** `WD_MissilePod` (초안)

damage 3 (폭발) · fireInterval 2.0 · missileCount 2 · speed 12 · blastRadius 1.2 · maxLevel 5 · perLevelBonus `projectileCountAdd 1`, `rangeAdd 0.15` · requiresTarget true · socket **Back**
→ 대상 1명당 DPS 1.5 + 주변 폭발.

**④ 확인**

- [ ] 위로 솟았다가 휘어 들어간다
- [ ] 대상이 죽으면 다른 적으로 방향을 바꾼다
- [ ] 재사용할 때 꼬리가 이전 위치에서 길게 그어지지 않는다
- [ ] 폭발 반경이 효과 크기와 맞고, 보스에게도 맞는다
