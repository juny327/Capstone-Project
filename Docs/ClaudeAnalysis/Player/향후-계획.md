# 향후 계획 — 사운드와 확장 방향

보류한 것과 앞으로 할 수 있는 것을 모았다.
현재 구현 상태는 [플레이어-시스템-정리.md](플레이어-시스템-정리.md) 를 본다.

---

## 1. 사운드 (보류)

### 1-1. 지금 상태

프로젝트 전체에서 오디오를 쓰는 곳은 **두 군데뿐**이다.

| 위치 | 용도 |
|---|---|
| `Upgrade/UpgradeCard.cs` | 업그레이드 성공 · 실패음 |
| `Enemy/Attack/DashAttack.cs` | 돌진 공격 |

즉 **사격 · 장전 · 피격 · 사망 · 서브유닛 · UI 조작이 전부 무음**이다.
`AudioManager` 같은 중앙 관리자도, 볼륨 설정도 없다.

### 1-2. 붙일 지점 (이미 열려 있다)

나중에 다시 조사하지 않도록 호출 지점을 정리해 둔다.

**무기**

| 시점 | 지점 |
|---|---|
| 발사 | `WeaponBase.Fire()` — 모든 무기가 지나간다 |
| 장전 시작 | `WeaponBase.OnReloadStarted(duration)` |
| 장전 완료 | `WeaponBase.OnReloadFinished()` |
| 장전 취소 | `WeaponBase.OnReloadCanceled()` |
| 빈 총 | `CanFire` 가 false 로 바뀌는 지점 |
| 스왑 | `GameEvents.OnWeaponSwapped` |

탄창 작업 때 `OnReloadStarted` 같은 확장 지점을 이미 만들어 뒀다.
`WeaponData` 에 `AudioClip` 필드를 더하면 무기별로 다른 소리를 낼 수 있다.

**플레이어**

| 시점 | 지점 |
|---|---|
| 피격 | `PlayerStats.TakeDamage()` |
| 사망 | `GameEvents.OnPlayerDeadStart` |
| 회복 | `PlayerStats.AddHP()` |
| 레벨업 | `GameEvents.OnLevelUp` |
| 구르기 | `PlayerMove.StartRoll()` |

**UI · 진행**

`OnUpgradeSelected` · `OnUpgradeConfirmed` · `OnStageClear` · `OnBossSpawned`.
이벤트가 이미 다 있으므로 듣는 쪽만 만들면 된다.

### 1-3. 착수할 때 정할 것

| # | 항목 | 메모 |
|---|---|---|
| S1 | 중앙 관리자 | `AudioManager` 싱글턴 + 풀링 vs 각 객체에 `AudioSource` |
| S2 | **동시 발생 제한** | 기관단총은 초당 8발이다. 같은 클립이 겹치면 소리가 찢어진다 |
| S3 | 볼륨 설정 | `AudioMixer` 그룹(Master · SFX · BGM) + 설정 UI |
| S4 | `timeScale` 0 | 업그레이드 창은 정지 상태로 뜬다. UI 음은 `ignoreListenerPause` 가 필요할 수 있다 |
| S5 | 에셋 출처 | 무료 SFX 팩 라이선스 확인 |

> **S2 가 가장 실무적인 함정이다.** 발사음을 `Fire()` 에 그냥 붙이면 SMG 연사에서 클립이 수십 개 겹친다.
> 착수 시 제일 먼저 처리할 것.

### 1-4. 왜 보류인가

- 게임 로직이 아직 형태를 잡는 중이라, 지금 붙이면 바뀔 때마다 같이 손봐야 한다
- 사운드 에셋을 아직 고르지 않았다
- 무음이어도 플레이와 테스트에 지장이 없다

**우선순위가 올라가는 시점**: 게임 흐름이 고정되고 빌드를 내보내기 시작할 때.

## 2. 바로 이어서 할 만한 것

### 2-1. 주 무기 획득 경로

지금은 시작할 때 1개를 고르고 끝이라, **손 무기 슬롯 2칸 중 1칸이 늘 비어 있다.**
`Q` 스왑도 바꿀 대상이 없어 의미가 없다.

| 안 | 내용 |
|---|---|
| A | 업그레이드 카드에 주 무기도 넣는다 (`CanAcquire` 가 슬롯 만석을 이미 걸러 준다) |
| B | 스테이지 클리어 보상으로 무기 하나를 준다 |
| C | 슬롯을 1칸으로 줄이고 스왑을 제거한다 |

`WeaponController.Acquire` 는 손 무기 · 서브유닛을 모두 처리하므로, A 는 카드 에셋만 만들면 된다.

### 2-2. 남은 서브유닛 아이콘

파티클 전용 6종은 픽토 아이콘을 쓰고 있다.
`SU_Nanobot.prefab` 은 메시가 있어 `Tools/HUD Layout/무기 아이콘을 실제 모델로 굽기` 에
항목만 추가하면 실제 모델로 바꿀 수 있다.

### 2-3. 정리

- `Gun.cs` · `AutoAttack.cs` 파일 삭제 — `WeaponController` 의 경고 코드와 `WeaponAssetSetup` 참조,
  `Assets/_Recovery` 백업 씬을 먼저 정리해야 한다
- 우측 스탯 패널 `BG` 높이를 줄 간격(40)에 맞추기

## 3. 시스템 확장 후보

### 3-1. 서브유닛 추가

설계 단계에서 14종을 후보로 뽑았고 8종을 구현했다. 남은 유형:

| 유형 | 예 | 필요한 선행 작업 |
|---|---|---|
| 설치형 | 터렛 · 지뢰 | 수명 · 개수 제한 관리 |
| 제어형 | 중력장 · 빙결 | **적에게 상태이상 수용부가 필요**(`IStatusReceiver` 확장) |
| 지원형 | 보호막 · 이동속도 버프 | 플레이어 버프 스택 구조 |

제어형은 적 쪽 작업이 함께 필요해 비용이 가장 크다.

### 3-2. 이동 확장

대시 · 벽 타기 등을 넣는다면 `PlayerMove` 를 나누는 편이 낫다.
지금 한 클래스가 입력 · 조준 · 이동 · 구르기 · 스태미나 · 애니메이터를 모두 들고 있다.

분할안: `PlayerInputReader`(입력) / `PlayerAim`(조준) / `PlayerMove`(이동 · 상태).
다만 **지금 당장 필요하지 않다면 미루는 편이 낫다** — 동작하는 코드를 쪼개는 비용이 작지 않다.

### 3-3. 세이브 · 이어하기

현재 `PlayerPrefs` · `JsonUtility` · 파일 저장이 전혀 없다.
런 단위 로그라이크라면 런 중간 저장은 불필요할 수 있으니, **먼저 게임 구조를 정한 뒤** 판단한다.

저장한다면 대상: 보유 무기 · 레벨 · EXP · 스테이지 진행도.

### 3-4. 밸런스 작업

수치가 코드가 아니라 에셋에 있어 플레이하면서 조정할 수 있다.

| 대상 | 위치 |
|---|---|
| 무기 피해 · 간격 · 탄창 | `Data/Weapons/WD_*.asset` |
| 레벨 곡선 | `PlayerStats` 의 `baseExp` · `expGrowth` |
| 스태미나 | `PlayerMove` 의 소모 · 회복량 |
| 스테이지 처치 목표 | `StageData` 의 `killTarget` |

> 스태미나 필드는 프리팹에 아직 직렬화돼 있지 않다(새로 추가한 필드).
> C# 초기값으로 동작하며, 인스펙터에서 한 번 만지면 그때부터 프리팹에 기록된다.

## 4. 알려진 이슈

초기 분석에서 잡았던 항목 중 **아직 처리하지 않은 것**들이다.

| # | 내용 |
|---|---|
| H-4 | 플레이어 스폰 경로가 둘(`GameAppManager` · `RunManager`). 실제로는 `GameAppManager` 만 쓰이고 `RunManager` · `PlayerSpawnPoint` 는 **어느 씬에도 없는 죽은 코드**다 |
| H-1 | 상태이상 코루틴이 중단되면 슬로우 · 스턴이 영구화될 수 있다 |
| M-7 | 총알이 지형을 관통한다 |
| M-3 | 사망 대기 시간이 하드코딩 + 애니메이션 이벤트 의존 |

`RunManager` 를 지우려면 씬 배치부터 확인해야 한다 — 지금은 쓰이지 않지만 참조는 남아 있다.
