## 1. 지금 구조에서 손댈 지점

발사는 이 네 단계를 모두 통과해야 일어난다 (`WeaponController.Update`).

```
w.Tick(dt)                    쿨다운 감소
  ↓
w.CanFire                     쿨다운이 0 이하이고 활성 무기인가
  ↓
ShouldFire(w)                 requiresTarget 이면 감지 범위에 적이 있는가
  ↓
w.HasTargetInReach(ctx)       무기 자체 사거리 안에 적이 있는가
  ↓
w.Fire(ctx)                   OnFire 실행 후 cooldown = FireInterval
```

탄창은 **`CanFire` 에 조건을 하나 더 얹는 방식**이 가장 자연스럽다. 이미 "쏠 수 있는가"를 판단하는 자리이고, 여기서 막으면 쿨다운·연출·업그레이드 경로를 건드리지 않아도 된다.

| 현재 | 추가 후 |
|---|---|
| `CanFire => cooldown <= 0f && IsActive` | `CanFire => cooldown <= 0f && IsActive && !IsReloading && HasAmmo` |

## 2. 1단계 — 탄창 스탯 추가

### 2-1. `WeaponModifier` · `WeaponRuntimeStats` (`Assets/Scripts/Data/WeaponStats.cs`)

업그레이드로 탄창을 늘리거나 장전을 빠르게 할 수 있어야 하므로, 서브유닛의 `durationAdd` 를 넣었을 때와 같은 방식으로 필드를 추가한다.

| 추가할 곳 | 필드 | 의미 |
|---|---|---|
| `WeaponModifier` | `int magazineAdd` | 탄창 크기 증가 |
| `WeaponModifier` | `float reloadTimeMul` (곱셈, 항등원 1) | 장전 시간 배율 |
| `WeaponRuntimeStats` | `int MagazineSize` | 최종 탄창 크기 |
| `WeaponRuntimeStats` | `float ReloadTime` | 최종 장전 시간(초) |

⚠ `reloadTimeMul` 은 곱셈 필드다. `Identity`, `Sanitized()`, `Combine()`, `Scaled()` 네 곳에 모두 넣어야 한다. `damageMul`·`fireIntervalMul` 이 이미 같은 처리를 하고 있으니 그대로 따라 쓴다. 빠뜨리면 기본값 0이 되어 장전 시간이 0초가 된다.

### 2-2. `ProjectileWeaponData`

```
[Header("Ammo")]
magazineSize    기본 탄창. 0 이면 무제한 (탄창 기능을 쓰지 않는 무기)
reloadTime      장전에 걸리는 시간(초)
autoReload      탄이 떨어지면 자동으로 장전할지
```

`Compose()` 에서 스탯으로 합성한다.

```
s.MagazineSize = magazineSize <= 0 ? 0 : Mathf.Max(1, magazineSize + m.magazineAdd);
s.ReloadTime   = Mathf.Max(0.1f, reloadTime * m.reloadTimeMul);
```

`magazineSize = 0` 을 "무제한"으로 두면 드론 같은 다른 무기 데이터는 손대지 않아도 된다.

## 3. 2단계 — 탄약과 장전 상태 (`WeaponBase`)

무기 공통 기반에 넣는다. 근접·서브유닛은 `MagazineSize = 0` 이라 자동으로 무제한이 되어 영향을 받지 않는다.

### 3-1. 상태

| 항목 | 내용 |
|---|---|
| `int ammo` | 현재 탄약 |
| `float reloadRemaining` | 남은 장전 시간. 0보다 크면 장전 중 |
| `public bool IsReloading` | `reloadRemaining > 0f` |
| `public bool HasAmmo` | `MagazineSize <= 0` 이거나 `ammo > 0` |
| `public int Ammo` / `public int MagazineSize` | HUD 표시용 |

### 3-2. 동작

- **`Initialize`**: 탄창을 가득 채운다.
- **`Tick`**: 장전 중이면 `reloadRemaining` 을 줄이고, 0이 되면 탄창을 채운 뒤 `OnReloadFinished()` 를 부른다. 쿨다운 감소는 그대로 둔다.
- **`Fire`**: `OnFire` 뒤에 탄약을 1 줄인다. 산탄(`ProjectileCount`)이 여러 발이어도 **1회 발사는 탄약 1 소모**로 둔다. 탄 수만큼 소모하면 산탄 업그레이드가 곧 탄약 소모 증가가 되어 업그레이드가 벌칙이 된다.
- **`StartReload()`**: 장전 시작. 이미 장전 중이거나 탄창이 가득이면 무시한다.
- **`CancelReload()`**: 장전 취소. 스왑·사망·구르기에서 부른다.
- **`SetActive(false)`**: 손에서 빠질 때 장전을 취소한다. 취소하지 않으면 무기를 바꿨다가 돌아왔을 때 갑자기 장전이 끝난다.

### 3-3. 확장 지점

```
protected virtual void OnReloadStarted(float duration) { }
protected virtual void OnReloadFinished() { }
```

투사체 무기가 이것을 재정의해 애니메이션과 소리를 연결한다 (5단계).

## 4. 3단계 — 발사 차단과 자동 장전 (`WeaponController`)

`CanFire` 가 이미 탄약을 보게 되므로 발사 루프는 고칠 필요가 없다. 대신 **탄이 떨어졌을 때 장전을 시작하는 한 줄**을 넣는다.

```
if (!w.CanFire)
{
    // 활성 무기이고, 탄이 없고, 장전 중이 아니면 장전을 시작한다
    if (i == activeHeldIndex) w.TryAutoReload();
    continue;
}
```

- 자동 장전은 **활성 무기에만** 적용한다. 손에 없는 무기까지 장전하면 스왑으로 장전 시간을 회피할 수 있다.
- 수동 장전(R 키)을 넣으려면 `HandleSwapInput` 옆에 입력 처리를 추가하고 `ActiveWeapon.StartReload()` 를 부른다. 입력은 지금 `Keyboard.current` 를 직접 읽는 임시 방식이므로 같은 자리에 두면 된다.

## 5. 4단계 — 장전 애니메이션 연결 (에디터 작업)

구르기(`Roll`)·베기(`Slash`)를 붙였을 때와 같은 절차다. 09번 문서의 도구 메뉴 9번이 한 것과 같은 방식이라 도구로 자동화할 수 있다.

### 5-1. 클립 준비

| 항목 | 값 |
|---|---|
| 원본 | `Assets/SciFiWarriorPBRHPPolyart/Animations/Reload.fbx` (휴머노이드, 80프레임) |
| 추출본 | `Assets/Animations/Player/Reload.anim` (2.67초) — **이미 있다** |
| 반복 | 꺼야 한다. 원본 임포트 설정이 `loopTime: 1` 이므로 추출본에서 반복을 끈다 |

### 5-2. Animator 구성

현재 컨트롤러 구조다.

| 레이어 | 용도 | 마스크 |
|---|---|---|
| Base | 이동·점프·사망·구르기 | 없음 |
| ShootLayer | 사격 자세 (`Idle_gunMiddle_AR`, `Shoot_Autoshot_AR`, `Run_gunMiddle_AR`) | Upper |
| MeleeLayer | 검 (`MeleeIdle`, `Slash`) | Upper |

장전은 **상체 동작이므로 ShootLayer 에 넣는다.**

1. ShootLayer 에 `Reload` 상태를 만들고 `Reload.anim` 을 넣는다.
2. 파라미터에 트리거 `Reload` 를 추가한다. 기존 `Roll`·`Slash` 와 같은 방식이다.
3. `Any State → Reload` 전이를 만든다. 조건은 트리거 `Reload`, **Has Exit Time 끔**, 전이 시간 0.1초.
4. `Reload → Idle_gunMiddle_AR` 전이를 만든다. **Has Exit Time 켬**, Exit Time 0.9.
5. 상태의 Write Defaults 는 다른 상태와 맞춘다 (이 컨트롤러는 전부 On).

### 5-3. 속도 맞추기

클립은 2.67초인데 `reloadTime` 은 데이터 값이다. 둘이 어긋나면 모션이 끝나기 전에 쏘거나, 다 쏠 수 있는데 모션이 계속된다.

Animator 의 `Reload` 상태에 **Speed 파라미터**(`float ReloadSpeed`)를 물리고, 코드에서 이렇게 맞춘다.

```
anim.SetFloat("ReloadSpeed", clipLength / stats.ReloadTime);
anim.SetTrigger("Reload");
```

`reloadTime` 을 2.67초로 두면 배속이 1이 되어 가장 자연스럽다. 기관단총처럼 빠른 장전을 원하면 1.2초로 두고 배속 2.2로 재생한다.

## 6. 5단계 — 모션과 코드 맞물리기

### 6-1. 누가 애니메이터를 부르는가

무기가 직접 `Animator` 를 찾아 쓰는 방식은 `MeleeWeapon` 이 이미 쓰고 있다 (`Owner.GetComponent<Animator>()` 캐시 후 파라미터 존재 확인). 같은 방식을 `ProjectileWeapon` 에 둔다.

```
protected override void OnReloadStarted(float duration)
{
    // Animator 가 없거나 Reload 파라미터가 없으면 조용히 건너뛴다 (경고 스팸 방지)
}
```

파라미터 존재 확인을 반드시 넣는다. 4단계를 하기 전에 코드를 먼저 넣어도 오류 없이 돌아가야 한다.

### 6-2. 상체 레이어 처리

`WeaponController.ApplyUpperBodyLayers()` 가 활성 무기 종류에 따라 레이어 가중치를 정한다. 장전은 ShootLayer 안에서 일어나므로 **추가 처리가 필요 없다.**

다만 구르기는 상체 레이어를 끈다(`SuppressUpperBodyLayers`). 구르는 동안 장전 모션이 사라지므로, `PlayerMove.StartRoll` 에서 **장전을 취소**하거나 **구르기 중에는 장전을 시작하지 않도록** 막는 편이 자연스럽다. 둘 중 하나를 정한다 (7장 R2).

### 6-3. 사망 처리

`WeaponController.OnPlayerDead` 에서 모든 무기의 장전을 취소한다. 취소하지 않으면 사망 연출 중에 장전이 끝나고 HUD 숫자가 갱신된다.

## 7. 6단계 — HUD 표시

### 7-1. 이벤트

`GameEvents` 에 한 줄 추가한다.

```
public static Action<int, int> OnAmmoChanged;   // 현재 탄약, 탄창 크기
```

발행 시점은 세 곳이다 — 발사 후, 장전 완료, 무기 스왑. 스왑 때 빠뜨리면 다른 무기의 탄약이 그대로 남아 보인다.

### 7-2. 표시

`PlayerStatsUI` 에 `TextMeshProUGUI ammoText` 를 추가하고 `OnAmmoChanged` 를 구독한다. 기존 필드들(`bulletDamageText` 등)과 같은 방식이다.

| 상태 | 표시 |
|---|---|
| 일반 | `12 / 30` |
| 장전 중 | `장전 중...` 또는 남은 시간 게이지 |
| 무제한 (`MagazineSize = 0`) | 표시하지 않음 (검·드론을 들었을 때) |

⚠ HUD 배치 시 주의: 현재 HUD 요소들은 **화면 중앙 앵커에 고정 좌표**로 놓여 있어 해상도가 바뀌면 잘린다. 탄약 표시를 새로 놓을 때는 앵커를 화면 모서리 기준으로 잡는 편이 안전하다.

## 8. 7단계 — 수치

07번 문서의 총기 설계값을 기준으로 잡은 초안이다. 탄창은 "한 번에 얼마나 쏘고 얼마나 쉬는가"로 결정한다.

| 무기 | 발사 간격 | 탄창 | 장전 | 한 탄창 지속 | 비고 |
|---|---|---|---|---|---|
| 소총 | 0.50초 | 30발 | 2.0초 | 15초 | 기본. 장전이 드물게 걸린다 |
| 기관단총 | 0.12초 | 45발 | 1.6초 | 5.4초 | 자주 장전한다. 빠른 장전으로 보완 |
| 스나이퍼 | 1.60초 | 5발 | 2.6초 | 8초 | 클립 그대로(2.67초) 재생 |

- 장전 시간은 **DPS 에 직접 영향을 준다.** 소총은 15초 사격 + 2초 장전이라 실효 DPS 가 약 88% 가 된다. 기존 밸런스를 유지하려면 데미지를 12% 정도 올리거나, 탄창을 넉넉히 준다.
- 업그레이드 카드에 "탄창 +10", "장전 속도 20% 증가"를 넣을 수 있다. `magazineAdd`, `reloadTimeMul` 이 그대로 대응한다.

## 9. 테스트 체크리스트

- [ ] 탄을 다 쏘면 발사가 멈추고 장전 모션이 나온다
- [ ] 장전이 끝나면 탄창이 차고 다시 쏜다
- [ ] 장전 중 무기를 바꾸면 장전이 취소된다. 되돌아와도 탄약이 그대로다
- [ ] 장전 중 구르기를 해도 상체가 어색하게 끊기지 않는다 (7장 R2 결정에 따라)
- [ ] 사망 시 장전이 멈추고 HUD 가 갱신되지 않는다
- [ ] 검·드론을 들었을 때 탄약 표시가 사라진다
- [ ] 스왑할 때 HUD 숫자가 해당 무기 것으로 바뀐다
- [ ] 산탄(`projectileCount` 2 이상)이어도 한 번에 탄약 1만 준다
- [ ] 모션 길이와 `reloadTime` 이 맞는다 (모션이 끝나기 전에 쏘지 않는다)

## 11. 구현 순서 (권장)

1. **1~3단계를 먼저 코드로 끝낸다.** 애니메이션 없이도 탄창·장전이 동작한다. 이 상태에서 수치를 만져 보며 밸런스를 잡는다.
2. **4~5단계로 모션을 붙인다.** 클립이 이미 있으므로 Animator 상태와 트리거만 추가하면 된다.
3. **6단계 HUD.** 탄약이 보이면 체감이 크게 달라진다.
4. **7단계 수치 확정과 테스트.**

1단계만 끝나도 "탄이 떨어지면 잠시 못 쏜다"가 성립하므로, 중간에 멈춰도 게임은 정상 동작한다.

### 12-2. 발사 차단이 걸리는 지점

`WeaponBase.CanFire` 한 곳에서 막는다. 호출부를 고칠 필요가 없다는 것이 이 설계의 핵심이다.

```
CanFire => cooldown <= 0f && IsActive && !IsReloading && HasAmmo
HasAmmo => MagazineSize <= 0 || ammo > 0     // 0 은 무제한(근접·서브유닛)
```

`WeaponController.Update` 는 `!CanFire` 인 활성 무기에 대해 `TryAutoReload()` 를 부른다. **손에 든 무기만 장전**하므로 스왑으로 장전 시간을 회피할 수 없다.

### 12-3. R1~R6 이 실제로 어디에 구현됐는가

| # | 결정 | 구현 위치 |
|---|---|---|
| R1 | 자동 + 수동 | 자동은 `WeaponController.Update` 의 `TryAutoReload()`. 수동은 `HandleReloadInput()` → `ReloadActiveWeapon()`. `StartReload()` 는 탄이 남아 있어도 받아들이고, 탄창이 가득일 때만 무시한다 |
| R2 | 구르면 취소 | `PlayerMove.StartRoll()` → `CancelReload()` → `WeaponController.CancelActiveReload()`. 상체 레이어를 끄는 자리 바로 옆이다 |
| R3 | 산탄도 1발 | `WeaponBase.Fire()` 에서 `ProjectileCount` 와 무관하게 `ammo -= 1` |
| R4 | 빈 채 스왑하면 상태 유지 | `SetActive(false)` 가 `CancelReload()` 만 하고 `ammo` 는 건드리지 않는다. 취소하지 않으면 무기를 바꿔 둔 사이에 장전이 끝나 버린다 |
| R5 | 서브유닛 제외 | 서브유닛 데이터에는 `magazineSize` 자체가 없어 `MagazineSize` 가 0 이 된다. 추가로 `RaiseAmmoChanged()` 가 `IsAlwaysActive` 무기를 걸러내, HUD 숫자가 드론 것으로 덮이지 않는다 |
| R6 | 소리 나중에 | 미구현 |

### 12-4. 장전 모션

- 클립: `Assets/Animations/Player/Reload.anim`, 길이 **2.6666667초** (`ProjectileWeapon.ReloadClipLength = 2.67f` 와 일치).
- `PlayerAnimator` 의 **ShootLayer** 에 `Reload` 상태를 만들고 `Reload`(Trigger) · `ReloadSpeed`(Float, 기본 1) 파라미터를 추가했다.
- 전이: `AnyState → Reload` 는 exit time 없이 0.05초, `canTransitionToSelf = false`. `Reload → (레이어 기본 상태)` 는 exit time 0.95, 0.15초.
  클립이 루프 설정(`m_LoopTime: 1`)이라 **이 복귀 전이가 한 바퀴에서 끊어 주는 역할**을 한다.
- 무기마다 장전 시간이 다르므로 코드가 `ReloadSpeed = 2.67 / stats.ReloadTime` 을 넣어 배속을 맞춘다.
- 파라미터가 없는 애니메이터에서도 죽지 않도록, `ProjectileWeapon` 이 `Animator.parameters` 를 한 번 훑어 존재를 확인한 뒤에만 호출한다 (`MeleeWeapon` 의 `Slash` 처리와 같은 방식).

### 12-6. 검증

모두 **프로젝트 고정 버전인 6000.3.7f1** 로 확인했다.

- 배치 모드 컴파일: `error CS` **0건**, `Exiting batchmode successfully now!` (반환 코드 0).
- `MagazineSetup.RunAll` 배치 실행: 예외 없음, 반환 코드 0.
- 로그가 아니라 **파일에서 직접 확인**했다 — 세 `.asset` 에 `magazineSize`/`reloadTime`/`autoReload` 가 기입됐고, `PlayerAnimator.controller` 에 두 파라미터와 `m_SpeedParameterActive: 1` / `m_SpeedParameter: ReloadSpeed` 인 Reload 상태, `Reload` 조건 전이가 들어갔다.
- 같은 셋업을 두 번 돌려 **멱등성도 확인**했다. 두 번째 실행에서는 "파라미터 추가" 로그가 나오지 않았고(이미 존재), 전이도 중복되지 않았다.
- 6000.3.7f1 로 돌린 실행에서는 12-8 의 프로젝트 파일 덮어쓰기가 **재발하지 않았다.** 원인이 에디터 버전이었음이 확인된 셈이다.

아직 못 한 것: **인게임 플레이 검증.** 탄이 떨어질 때 장전 모션이 상체에 제대로 얹히는지, 배속이 어색하지 않은지는 직접 플레이로 확인해야 한다.

### 12-7. 남은 일

- **`PlayerStatsUI.ammoText` 가 아직 비어 있다.** 코드는 준비됐지만 씬에 표시용 TMP 오브젝트를 만들어 연결해야 실제로 보인다. 대상 씬은 `Stage1` · `Stage2` · `Stage3` · `StageBoss` 네 곳이다.
  현재 HUD 배치 문제(중앙 앵커 + 고정 좌표로 화면 밖에 나가는 건)가 미해결이라, **그 배치 방식을 정한 뒤에 같이 넣는 편이 안전하다.** 먼저 넣으면 새 텍스트도 같은 이유로 화면 밖에 놓인다.
- R6 장전 효과음.

### 12-8. 주의 — 배치 실행의 부수 효과

이 작업 중 배치 모드 실행이 프로젝트 파일을 건드렸고, 전부 되돌렸다. 다음에도 같은 일이 생길 수 있으니 배치 실행 후에는 `git status` 를 확인할 것.

- `ProjectSettings/ProjectVersion.txt` — 프로젝트 고정 버전(6000.3.7f1)이 덮였다.
- `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset` — URP `m_AssetVersion` 9 → 10 이관.
- `Packages/manifest.json` · `packages-lock.json` — `ai.navigation` 2.0.9 → 2.0.10, `burst` 1.8.27 → 1.8.28.

**원인은 에디터 버전 선택 실수였다.** Hub 에 6000.3.7f1 · 6000.3.9f1 · 6000.3.10f1 이 함께 설치돼 있는데, 실행 스크립트가 설치 목록을 이름 내림차순으로 정렬해 첫 번째를 골랐다. 문자열 정렬이라 `6000.3.9f1` 이 `6000.3.10f1` 보다 위로 올라와 9f1 로 열린 것이다.

**이 프로젝트는 6000.3.7f1 을 고정해서 쓴다.** 배치를 돌릴 때는 설치 목록을 정렬하지 말고 `ProjectSettings/ProjectVersion.txt` 의 버전으로 경로를 만들어야 한다.

```powershell
$ver = ((Select-String -Path "$proj\ProjectSettings\ProjectVersion.txt" -Pattern '^m_EditorVersion:\s*(.+)$').Matches[0].Groups[1].Value).Trim()
$exe = Join-Path $env:ProgramFiles "Unity\Hub\Editor\$ver\Editor\Unity.exe"
```
