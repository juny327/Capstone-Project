> **로그를 믿었다가 틀린 사례가 또 나왔다** (이 프로젝트에서 세 번째, 앞선 둘은 8장).
>
> 투사체 시절 `Bullet_Chain.prefab` 에 `ChainBullet` 이 아니라 원본 `Bullet` 이 붙었는데,
> 로그는 "전격 탄 생성" 으로 정상이었다.
> 원인은 인스펙터 값을 옮길 때 **`m_Script` 까지 복사**한 것이었다 —
> 새로 붙인 컴포넌트의 `m_Script` 가 원본으로 되돌아가 타입이 바뀌어 버린다.
>
> 그 프리팹은 지금 설계에서 사라졌지만, **교훈은 남는다.**
> `SerializedObject` 로 값을 옮길 때는 `m_Script` 를 건너뛰고,
> **저장한 결과를 다시 읽어 확인한 뒤** 성공 로그를 찍는다.

## 1. 만드는 것

| 무기 | 원형 | 성격 | 새 코드 |
|---|---|---|---|
| **샷건** | — | 근거리 산탄. 붙어야 아프다 | **없음** (데이터만) |
| **전격 소총** | 되돌린 서브유닛 *테슬라 코일* | 커서 방향으로 얇은 전기 레이저, 맞으면 주위로 퍼진다 | 무기 클래스 + 데이터 2개 |
| **충전 레이저** | 아이작 *혈사포* | 모았다가 굵은 관통 빔 한 방 | 무기 클래스 + 데이터 2개 |

**샷건을 먼저 만든 이유**는 코드 없이 "무기를 늘리면 어디가 깨지는지"(로비 · HUD · 풀)를
싸게 확인하기 위해서다. 나머지 둘은 새 판정 방식(히트스캔)을 여는 작업이다.

### 1-1. 끝났을 때의 상태

- 로비 선택지 **4종 → 7종**
- 인게임에서 슬롯 · 스왑 · 탄창 · 장전 · HUD · 업그레이드는 **기존 것이 그대로 동작**
  (새 무기가 `WeaponKind.Projectile` 이면 전부 공짜로 따라온다)

## 2. 공통 선행 작업

세 무기 모두 **무기 프리팹 · 아이콘 · 로비 버튼**이 필요하다. 먼저 해 둔다.

### 2-1. 무기 프리팹 — `WeaponAssetSetup` 에 항목 추가

`Assets/Editor/WeaponAssetSetup.cs` 의 `Guns` 배열에 줄을 더하면 프리팹이 자동 생성된다.

```csharp
static readonly GunSpec[] Guns =
{
    new GunSpec { Prefab = "W_Rifle",  Model = "AR_3",     ExpectedMuzzle = ... },
    new GunSpec { Prefab = "W_SMG",    Model = "SMG_1",    ExpectedMuzzle = ... },
    new GunSpec { Prefab = "W_Sniper", Model = "Sniper_1", ExpectedMuzzle = ... },
    // 추가. Component 를 비우면 ProjectileWeapon 이 붙는다.
    new GunSpec { Prefab = "W_Shotgun", Model = "Grenade_2",
                  ExpectedMuzzle = new Vector3(0f, 0.335f, 1.253f) },
    new GunSpec { Prefab = "W_TeslaRifle", Model = "AR_6",
                  ExpectedMuzzle = new Vector3(0f, 0.275f, 0.763f),
                  Component = typeof(ChainBeamWeapon) },
    new GunSpec { Prefab = "W_ChargeLaser", Model = "Sniper_3",
                  ExpectedMuzzle = new Vector3(0f, 0.181f, 1.513f),
                  Component = typeof(ChargeBeamWeapon) },
};
```

**`ExpectedMuzzle` 은 검증용이다.** 총구 위치는 `ComputeMuzzle()` 이 메시 정점에서 자동으로
계산한다. `Vector3.zero` 로 두면 경고가 뜨면서 **계산된 실제 값이 로그에 찍히므로**, 그 값을
다시 붙여넣으면 다음부터 검증이 된다.

`SkipIfExists()` 가 있어 **이미 있는 프리팹은 건너뛴다.** 여러 번 돌려도 안전하다.

**모델 선택** (`Assets/GunPack/Guns/`, 현재 쓰지 않는 것들 중)

| 무기 | 1순위 | 대안 | 이유 |
|---|---|---|---|
| 샷건 | `Grenade_2` | `AR_4` | 몸통이 두껍고 짧아 근거리 무기로 읽힌다 |
| 전격 소총 | `AR_6` | `AR_5` | 매끈하고 군더더기가 없어 에너지 무기에 맞는다 |
| 충전 레이저 | `Sniper_3` | `Sniper_2` | 총열이 길어 "모아서 쏜다"가 드러난다 |

> 모델 이름과 실제 생김새가 꼭 일치하지는 않는다(`Grenade_2` 가 유탄 발사기처럼 생기지 않았다).
> **에디터에서 한 번 보고 확정할 것.**

> **실행 결과**: 세 모델의 총구가 각각 z = 1.253 · 0.763 · 1.513 로 **전부 +Z(앞)** 였다.
> 기존 3종과 방향이 같아 뒤로 쏘는 문제는 없었다. 위 값은 그 실측치다.

> ⚠ **총구 방향을 확인해야 하는 이유.**
> `BuildGun` 은 `Guns` 배열 전체에 **같은 `barrelSign`** 을 적용한다.
> 새로 넣은 모델의 로컬 방향이 기존 3종과 반대면 **총이 뒤를 보고 쏜다.**
> 도구가 `"계산한 총구 ... 가 문서 값 ... 과 다릅니다"` 경고를 띄우고
> `"반대면 Model 의 Y 회전 부호를 바꾸세요"` 라고 알려 준다.
> 방향이 섞이면 **`barrelSign` 을 `GunSpec` 의 필드로 옮기는 편이 낫다.**

### 2-3. 로비 선택 UI — 4칸 → 7칸

`Assets/Editor/LobySelectSetup.cs` 의 배열에 3개를 더한다.

```csharp
static readonly string[] Weapons =
    { "WD_Rifle", "WD_SMG", "WD_Sniper", "WD_Sword",
      "WD_Shotgun", "WD_TeslaRifle", "WD_ChargeLaser" };
```

이 도구는 **버튼 생성 · `OnClick` 연결 · `LobyWeaponSelectUI.buttons` 배열 ·
`LobyManager.selectableWeapons` 를 전부 자동으로 채운다.** 손으로 연결할 것이 없다.

**⚠ 다만 레이아웃이 그대로는 안 된다.**

현재 값: 버튼 `220 × 110`, 간격 `step = 240`, 루트 `1000 × 260`, 캔버스 기준 `1920 × 1080`

| 버튼 수 | 가로 총폭 | 판정 |
|---|---|---|
| 4개 (현재) | 240×3 + 220 = **940** | 루트(1000) 안에 들어간다 |
| 7개 | 240×6 + 220 = **1660** | 화면(1920)에는 들어가지만 **루트(1000)를 크게 넘는다** |

루트에 `Mask` 가 없어 잘리지는 않지만, 설명 텍스트(960 폭)와 어긋나 보인다.

**선택 A — 한 줄 유지 (최소 수정)**

```
버튼 200 × 105 · step = 225 · 루트 1600 × 260
→ 225×6 + 200 = 1550
```

**선택 B — 2행 그리드 (권장)**

```
1행 4개 · 2행 3개 · step = 240 · 행 간격 125 · 루트 1000 × 380
```

무기를 더 늘릴 계획([주무기-확장-후보.md](주무기-확장-후보.md))이 있으므로 **B 를 권한다.**
한 줄은 8개째부터 다시 깨진다.

## 3. 무기 1 — 샷건 (코드 0줄)

`ProjectileWeaponData` 에 `projectileCount` · `spreadAngle` · `projectileLifeTime` 이
**이미 있다.** `.asset` 하나만 만들면 끝난다.

### 3-1. 수치

| 필드 | 값 | 이유 |
|---|---|---|
| `weaponName` | 샷건 | |
| `damage` | **1.4** | 탄 1발당. 8발 전탄 명중 = 11.2 |
| `fireInterval` | 0.9 | |
| `projectileCount` | 8 | |
| `spreadAngle` | 28 | 기관단총(5)보다 훨씬 넓게 |
| `projectileSpeed` | 18 | 느리게 — 멀면 퍼져서 빗나간다 |
| `projectileLifeTime` | **0.35** | **사거리를 여기서 만든다.** 18 × 0.35 ≈ 6 m |
| `pierceCount` | 0 | |
| `critChance` / `critMultiplier` | 0.05 / 2 | |
| `magazineSize` / `reloadTime` | 6 / 2.4 | |
| `aimMode` | `AimDirection` | 마우스 방향 |
| `perLevelBonus.projectileCountAdd` | 1 | 레벨업마다 탄 +1 — 성장이 눈에 보인다 |

> **`damage` 를 1.6 → 1.4 로 낮췄다.** 1.6이면 전탄 명중 기준 장전 포함 DPS 가 10.3으로
> 기준선 상단(9)을 넘는다. 1.4면 9.05다. 짝 문서의 1.6은 조사 단계 값이다.

### 3-2. 설계 의도

`projectileLifeTime` 이 **사거리이자 위력 곡선**이다. 붙으면 8발이 다 맞고 멀면
하나도 안 맞으므로, **구르기로 파고드는 플레이**와 맞물린다.
이건 지금 무기 중 어느 것도 요구하지 않는 움직임이다.

### 3-3. 작업

1. `Assets/Scripts/Data/Weapons/WD_Shotgun.asset` 생성 (`Create > Weapon > Projectile Weapon Data`)
2. 위 표대로 값 입력
3. `weaponPrefab` = `W_Shotgun`, `projectilePrefab` = `Bullet_new`,
   `muzzleFlashPrefab` = `Shoot`, `casingPrefab` = `BulletCase`
4. 2-2 아이콘 · 2-3 로비 도구 실행

## 4. 무기 2 — 전격 소총

> **설계가 한 번 바뀌었다.** 처음에는 연쇄하는 **투사체**로 만들었지만,
> 되돌린 서브유닛 *테슬라 코일*의 감각(전깃줄이 튀는 느낌)을 살리기로 하고
> **즉시 명중(히트스캔)** 으로 다시 만들었다. 아래는 최종 설계다.

### 4-1. 동작

1. 사거리(14m) 안에 적이 들어오면
2. **마우스 커서 방향으로 얇은 전기 레이저**를 쏜다
3. 처음 맞은 적에게 피해
4. 거기서 **주위 적으로 2번까지 퍼진다** — 퍼질 때마다 피해 50%

총알이 날아가지 않으므로 이동 중인 적을 놓치지 않는다. 대신 한 발의 값이 비싸다.

**적을 못 맞혀도 레이저는 그려진다.** 안 그러면 쏘는지 안 쏘는지 알 수 없다.

### 4-2. 구조

| 파일 | 내용 |
|---|---|
| `Data/ChainBeamWeaponData.cs` | 사거리 · 연쇄 · 연출 수치 |
| `Player/ChainBeamWeapon.cs` | `SphereCast` 로 첫 적 → `OverlapSphere` 로 퍼지기 |

- 첫 적 찾기: `SphereCastNonAlloc`(반지름 0.12). `RaycastNonAlloc` 은 가는 적을 자주 놓친다.
  **`SphereCast` 는 순서를 보장하지 않으므로** `distance` 로 가장 가까운 것을 직접 고른다
- 퍼지기: `OverlapSphereNonAlloc` + `HashSet` 중복 제거 —
  되돌린 `ChainWeapon`(테슬라 코일)과 같은 **적 → 적 경로** 방식이다.
  반경 공격과 성격이 다르기 때문에 영역 판정을 쓰지 않는다
- 차이는 **조준**이다. 코일은 가장 가까운 적을 자동으로 때렸지만, 이쪽은 조준해서 맞힌 적이 시작점이다

### 4-3. 연쇄 규칙

| 규칙 | 값 | 이유 |
|---|---|---|
| 연쇄 횟수 | 2 | 3번째부터는 화면에서 따라가기 어렵다 |
| 감쇠 | 50% | 3.2 → 1.6 → 0.8 |
| 연쇄 사거리 | 4.5 m | 직전 대상 기준 |
| 같은 적 재연쇄 | **금지** | 막지 않으면 두 적 사이를 왕복한다 |
| 치명타 | **첫 적에게만** | 퍼지는 전기까지 치명타가 뜨면 한 발에 숫자가 여러 번 터져 읽히지 않는다 |
| 태그 확인 | `Enemy` · `Boss` | `Bullet` 의 기존 규약과 맞춘다 |

연쇄 횟수는 `WeaponRuntimeStats.MaxTargets` 에 실어 **관통 업그레이드를 재사용**한다.
레이저 자체는 첫 적에서 멈추고, 그다음은 "퍼지기"로 이어지기 때문이다.

### 4-4. 수치

| 필드 | 값 | 비고 |
|---|---|---|
| `damage` / `fireInterval` | 3.2 / 0.5 | 히트스캔이라 안 빗나가는 만큼 간격을 늦췄다 |
| `range` | 14 m | 감지 범위(10)보다 조금 길게 |
| `beamRadius` | 0.12 | 얇은 레이저 |
| `critChance` / `critMultiplier` | 0.08 / 2 | |
| `magazineSize` / `reloadTime` | 20 / 1.8 | |

단일 대상 장전 포함 DPS **5.86**, 3명이 붙어 있으면 **약 10.3**.
뭉쳐 다니는 적에게 강하고 하나만 있을 때는 평범하다.

### 4-5. 연출 — 지그재그가 핵심

`LineRenderer` 로 그린다. 프리팹이 필요 없다.

**곧은 선은 전기로 보이지 않는다.** 8조각으로 나누고 축과 직각인 두 방향으로
0.12m 흔든다. 양 끝은 정확히 맞물려야 하므로 **가운데만** 흔든다.

본 줄기는 밝은 하늘색(두께 0.06), 퍼지는 전기는 더 옅고 가늘게(0.04) 해서 구분한다.
줄기 하나당 `LineRenderer` 하나를 만들어 돌려 쓴다.

### 4-6. 파일

| 파일 | 구분 |
|---|---|
| `Assets/Scripts/Data/ChainBeamWeaponData.cs` | 신규 |
| `Assets/Scripts/Player/ChainBeamWeapon.cs` | 신규 |
| `Assets/Scripts/Data/Weapons/WD_TeslaRifle.asset` | 신규 |
| `Assets/Scripts/Player/Bullet.cs` | 수정 — `OnHit` 훅 (이 무기는 안 쓰지만 **남겨 둔다**) |

> **투사체 시절의 잔재는 지웠다.** `ChainBullet.cs` · `Bullet_Chain.prefab` ·
> `BulletChain.asset` 과 4개 씬의 풀 등록을 모두 제거했다.
> 쓰지 않는데 풀에 남아 있으면 스테이지마다 12개를 미리 만든다.
>
> 다만 **`Bullet.OnHit` 훅은 남겼다.** 파열탄 · 폭발탄이 나중에 쓸 자리다.

## 5. 무기 3 — 충전 레이저

### 5-1. 충전을 자동 발사로 번역

아이작 혈사포는 **누르고 있다가 놓는다.** 우리 게임은 적이 범위에 들어오면 자동으로 쏘므로
그 조작이 없다.

**→ `fireInterval` 을 그대로 충전 시간으로 쓴다.**

`WeaponBase` 는 발사 후 `cooldown = stats.FireInterval` 을 걸고, 0이 될 때까지 기다린다.
**이 대기 시간이 곧 충전 시간이다.** 별도 상태 기계가 필요 없다.

남는 일은 **"모이는 중"을 보여 주는 것**뿐이다. 이게 없으면 플레이어는
2초 넘게 아무 일도 안 일어나는 것을 보고 "고장 났나" 한다.

```csharp
// WeaponBase.cs — 파생 클래스가 충전 진행도를 읽을 수 있게
protected float CooldownRemaining => cooldown;
```

`cooldown` 이 `private` 이라 이 한 줄이 필요하다.

### 5-2. 구조

| 파일 | 내용 |
|---|---|
| `ChargeBeamWeaponData : WeaponData` | `Kind => WeaponKind.Projectile`. 사거리 · 빔 굵기 · 빔 지속 · 탄창 |
| `ChargeBeamWeapon : WeaponBase` | `OnFire` 에서 `SphereCast`, `OnTick` 에서 충전 연출 |

**판정**

```csharp
Physics.SphereCastNonAlloc(origin, beamRadius, dir, hits, range, hitLayers)
```

- `RaycastNonAlloc` 은 가는 적을 자주 놓친다. **`SphereCast`(반지름 0.25 정도)를 쓸 것**
- 관통이므로 맞은 것을 **전부** 때린다. 중복 제거는 `HashSet<Transform>`
  (`MeleeWeapon.ApplyHits` 와 같은 방식)

**연출**

- 충전 중: 총구에 빛이 점점 커진다. `CooldownRemaining / FireInterval` 로 크기를 보간
- 발사: `LineRenderer` 를 **0.15초** 켠다. 굵게, 흰색 코어 + 색 외곽
- 발사 직전 0.2초에 소리와 빛이 최고조 — **언제 나갈지 예측 가능해야 한다**

### 5-3. 수치

| 필드 | 값 | 이유 |
|---|---|---|
| `weaponName` | 충전 레이저 | |
| `damage` | **18** | 관통이라 기준선 낮은 쪽에 맞췄다 |
| `fireInterval` | **2.2** | = 충전 시간 |
| `critChance` / `critMultiplier` | 0.15 / 2.5 | 한 방이 커야 체감된다 |
| 사거리 | 18 m | 감지 범위 10m 보다 길게 — "무한"처럼 느껴진다 |
| 빔 반지름 | 0.25 | |
| 빔 지속 | 0.15초 | 연출용. 판정은 발사 순간 1회 |
| 관통 | 무제한 | |
| `magazineSize` / `reloadTime` | **3 / 2.5** | |

단일 대상 장전 포함 DPS **7.27**. 관통이라 줄 서 있는 적에게는 훨씬 높다.

> **탄창 3발**이 리듬을 만든다. 충전 2.2초 × 3발 = 6.6초 쏘고 2.5초 장전이라,
> "모으고 → 쏘고 → 장전하며 피하고"가 반복된다. 스나이퍼와는 다른 박자다.

### 5-4. 주의

- 충전 중에 적이 사라져도 **충전을 유지할 것.** 초기화하면 적이 들락거릴 때마다 끊긴다.
  `fireInterval` 을 쿨다운으로 쓰는 구조라 이건 **자동으로 만족된다** (쿨다운은 적과 무관하게 흐른다)
- `HasTargetInReach` 를 재정의해 **사거리(18m) 밖이면 쏘지 않게** 한다.
  그렇지 않으면 허공에 쏘고 충전을 날린다
- 탄창을 쓰려면 `Compose()` 에서 `s.MagazineSize` · `s.ReloadTime` 을 채우기만 하면 된다.
  장전 · HUD · 스왑 취소는 `WeaponBase` 가 이미 처리한다

## 9. 밸런스 대조표

기대 피해 = `damage × (1 + 치명타확률 × (배율 − 1))`

| 무기 | 기대 피해/발 | 장전 포함 DPS (단일) | 비고 |
|---|---|---|---|
| 소총 | 2.10 | 5.73 | |
| 기관단총 | 1.37 | 8.81 | |
| 스나이퍼 | 16.50 | 7.78 | 관통 3 |
| 검 | 6.60 | 9.43 | **과함 — 아래 참고** |
| **샷건** | 1.47 ×8 | **9.05** | 전탄 명중 기준. 실전에서는 절반 이하 |
| **전격 소총** | 3.46 | **5.86** | 히트스캔. 3명 연쇄 시 약 10.3 |
| **충전 레이저** | 22.05 | **7.27** | 관통이라 다수전에서 훨씬 높다 |

> 기존 문서에서 지적한 대로 **검(9.43)이 단일 대상에서도 1위**이고 5명 기준으로는 47이다.
> 새 무기를 넣기 전에 검 수치를 먼저 보는 편이 좋다. 새 무기들을 검에 맞추면 전부 과해진다.

## 10. 함께 걸리는 문제

| 문제 | 내용 |
|---|---|
| **탄 풀 크기** | `Bullet.asset` 의 `initialSize` 가 **10**이다. 샷건은 **한 번에 8발**이라 두 번째 발사에서 바로 넘친다. `expandable: 1` 이라 터지지는 않지만 초반에 할당이 몰린다. **24 정도로 올릴 것** |
| **무기 획득 경로가 로비뿐** | 7종을 만들어도 **한 판에 1종만 쓴다.** 슬롯 4칸이 의미가 없다. `GrantWeaponUpgrade : UpgradeEffect` (20줄)를 만들어 레벨업 카드로 주는 것을 같이 고려할 것 |
| 슬롯 4칸 | `WeaponController.maxHeldSlots` = 4, `PlayerHudSetup.SlotCount` = 4. 지금은 문제없지만 늘리려면 둘 다 |
| `OpenScene(Single)` 함정 | 에디터 도구를 새로 쓸 일이 있으면 **씬을 먼저 열고 그다음 에셋을 로드**할 것. 순서를 어기면 참조가 조용히 `{fileID: 0}` 이 된다 |
| 에셋 폴더 규칙 | 가져온 위치 그대로 둔다. 재배치하면 병합 충돌 |
