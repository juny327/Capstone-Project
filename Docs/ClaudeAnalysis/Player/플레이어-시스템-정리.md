## 1. 이동 (`PlayerMove`)

### 1-1. 속도

`CurrentSpeed` = `baseSpeed`(3) × `speedModifiers` 누적.
슬로우 · 스턴이 리스트로 쌓이므로 **중첩이 자연스럽게 처리**된다.

스프린트는 `CurrentSpeed` 에 `sprintMultiplier`(1.6)를 곱한다.

> `AddSpeedModifier` 를 쓰지 않는 이유: 슬로우와 뒤섞여 해제 순서에 따라 값이 어긋난다.

### 1-2. 스태미나

| 상황 | 초당 |
|---|---|
| 달리기 | -25 (최대 100 → 약 4초) |
| 걷기 | +8 |
| 정지 | +18 |
| 달리기 중단 직후 | 0.5초 대기 후 회복 시작 |

`IsSprinting` 조건에 스태미나가 들어가 있어 바닥나면 자동으로 달리기가 풀린다.

> **바닥난 뒤에는 25% 가 찰 때까지 다시 달릴 수 없다**(`exhausted`).
> 이 장치가 없으면 0 근처에서 한 프레임씩 달렸다 멈췄다를 반복해 조작감이 망가진다.

프리팹에 이 필드들이 아직 직렬화돼 있지 않다(새 필드). C# 초기값으로 동작하며,
인스펙터에서 한 번 만지면 그때부터 프리팹에 기록된다.

### 1-3. 구르기

| 값 | 의미 |
|---|---|
| `rollDistance` 4 | 커브 모양과 무관하게 실제로 이 거리만큼 이동한다 |
| `rollDuration` 1.5 | 클립 길이와 맞춘 값 |
| `rollCooldown` 2.5 | 구르기가 **끝난 뒤부터** 시작 |
| `rollIFrame` 1.5 | 무적 시간 |
| `rollBufferTime` 0.15 | 쿨다운 끝나기 직전 입력을 살린다 |

**실제 재사용 대기는 4초**다 — `rollCdTimer = rollDuration + rollCooldown`.
HUD 는 `RollCooldownRemaining / RollCooldownTotal` 로 이 값을 그대로 보여준다.

## 2. 무기 시스템

### 2-1. 스탯 3층 구조

```
WeaponData (SO, 기본값)              ← 절대 수정하지 않는다
      +
WeaponModifier (누적 업그레이드 + perLevelBonus.Scaled(level-1))
      ↓  Compose()
WeaponRuntimeStats (실제 사용값)
```

> **`WeaponData` 를 직접 고치면 에디터에서 에셋에 영구 기록되어 플레이마다 수치가 누적된다.**
> 업그레이드는 반드시 `WeaponModifier` 로만 쌓는다.

### 2-2. 발사 게이트

```
WeaponController.Update()
  → w.Tick(dt)
  → w.CanFire            // cooldown <= 0 && IsActive
  → ShouldFire(w)        // requiresTarget 이면 감지된 적이 있어야
  → w.HasTargetInReach() // 사거리 밖이면 쿨다운을 쓰지 않고 기다린다
  → w.Fire(ctx)
```

### 2-3. 슬롯

| 항목 | 값 |
|---|---|
| 손 무기 | 4칸 (`maxHeldSlots`) |
| 서브유닛 | 2칸 (`maxSubUnitSlots`) |
| 스왑 | `Q` · 마우스 휠 |
| 시작 무기 | `starterWeapon` = `WD_Rifle` |

서브유닛(`IsAlwaysActive` = `Kind == SubUnit`)은 스왑과 무관하게 항상 동작한다.

### 2-4. 무기 5종

| 무기 | 데이터 | 유형 | 특징 |
|---|---|---|---|
| 소총 | `WD_Rifle` | 투사체 | 기준값. 피해 2 / 간격 0.30 |
| 기관단총 | `WD_SMG` | 투사체 | 피해 1.33 / 간격 0.12 / 퍼짐 5도 |
| 스나이퍼 | `WD_Sniper` | 투사체 | 피해 12 / 간격 1.60 / 관통 3 |
| 검 | `WD_Sword` | 근접 | 전방 부채꼴 광역 |
| 드론 | `WD_Drone` | 서브유닛 | 주위를 돌며 자동 사격. 레벨 = 드론 수 |

### 2-5. ⚠ 옛 발사 체계가 남아 있다

`Player.prefab` 에 아직 붙어 있다.

| 컴포넌트 | 상태 | 문제 |
|---|---|---|
| `AutoAttack` | **꺼짐**(`m_Enabled: 0`) | 켜면 `WeaponController` 와 **이중 발사**가 된다 |
| `Gun` | **켜짐**(`m_Enabled: 1`) | 발사에는 관여하지 않지만 `OnBulletDamageChanged` 를 쏜다 |

`Gun` 이 켜져 있어서 생기는 실제 문제:

- `Gun.Start()` 가 프리팹 값(`bulletDamage: 2`)으로 HUD 이벤트를 쏘고,
  `WeaponController.RaiseLegacyStats()` 도 같은 이벤트를 쏜다 → **서로 덮어쓴다**
- `DamageUpgrade` · `GunSpeedUp` 이 `Gun` 의 필드를 올리는데 **실제 발사는 `WeaponController`** 가 한다
  → 데미지 업그레이드를 먹어도 **HUD 숫자만 오르고 피해량은 그대로**다

고치려면 업그레이드 효과를 `WeaponController.ApplyGlobalModifier` 로 옮기고
`Gun` 컴포넌트를 프리팹에서 제거해야 한다.

## 3. 성장 — 레벨업과 업그레이드 (다른 작업자 구현)

### 3-1. 레벨업

```
적 처치 → ExpOrb → PlayerStats.AddExp()
  → currentExp >= expToNextLevel 이면 레벨업
  → GameEvents.OnPlayerLevelUp(level)
```

| 값 | 의미 |
|---|---|
| `expToNextLevel` 10 | 다음 레벨까지 필요한 EXP (레벨업마다 갱신) |
| `expGrowthRate` 1.3 | **배수** 증가 — 10 → 13 → 17 → 23 → 30 … |

`AddExp` 의 `while` 루프로 다중 레벨업을 처리한다. 차감을 먼저 하고 `level++` 한다.

### 3-2. 업그레이드 카드

- 후보 풀이 **`UpgradePoolData` 에셋**에 있다 (`Upgrade/Pool/MainUpgradePool.asset`)
- `UpgradeManager.GetRandomUpgrades` 가 중복 없이 뽑고, 후보가 모자라면 `Mathf.Min` 으로 줄인다
- `UpgradeUI` 는 `OnOpenUpgradeUI` 로 열고 `OnUpgradeSuccess` 로 닫는다

효과 구성:

```
Upgrade/Effects/Stats/   DamageUpgrade · GunSpeedUp · Heal · ExpandHP · SpeedUpgrade
Upgrade/Effects/Skill/   FireBallEffect
```

### 3-3. 파이어볼 스킬

`Skill/FireBall/FireBallSkill.cs` · `FireBallProjectile.cs`.
업그레이드 카드(`FireBallEffect`)로 획득한다.

## 4. UI · HUD

### 4-1. 기존 HUD

`PlayerStateUI` 아래에 체력 바 · 킬 수 · EXP · 공격력 · 탄속 · 이동속도가 있다.

> ⚠ `PlayerStateUI` 는 **100×100 중앙 고정 박스**이고 자식들이 큰 픽셀 오프셋을 쓴다.
> 화면비가 16:9 보다 넓어지면 위쪽 요소부터 화면 밖으로 밀린다.
> 고치려면 이 루트를 캔버스 전체로 늘리고 자식을 가장자리에 앵커해야 한다.

### 4-2. 새로 붙인 HUD (Canvas 직속)

기존 HUD 를 건드리지 않기 위해 **`PlayerStateUI` 가 아니라 `Canvas` 바로 아래**에 붙였다.
좌측 하단에 모여 있다.

| 요소 | 위치 | 내용 |
|---|---|---|
| `HeldSlots` | (24, 24) | 주무기 슬롯 4칸 |
| `RollIcon` | (24, 120) | 구르기 쿨타임 |
| `StaminaBG` | (86, 134) | 스태미나 바 |

**슬롯 칸 구성**: 노란 테두리(활성) → 반투명 배경(알파 28%, 맵이 비침) → 흰 테두리 → 아이콘 · 이름 · 레벨.
테두리는 9-슬라이스(`Sprites/UI/SlotFrame.png`)라 칸 크기가 달라도 두께가 일정하다.
`WeaponData.icon` 이 비어 있으면 이름만 나오므로, 아이콘을 나중에 채워도 코드 수정이 필요 없다.

**구르기 아이콘**: 원형 아이콘 위로 시계 반대 방향으로 줄어드는 검은 덮개 + 남은 초.
준비되면 덮개와 숫자가 사라지고 아이콘이 밝아진다.

**스태미나 바**: 평소 하늘색, 바닥나면 붉은색.

글꼴과 바 스프라이트는 **기존 HUD(`hpText` · `hpBar`)에서 물려받는다.**
한글이 깨지지 않으면서 다른 작업자의 폰트 설정을 건드리지 않기 위해서다.

| 이벤트 | 시그니처 | 발행 | 구독 |

## 7. ⚠ 반복해서 걸린 함정

실제로 한 번씩 당한 것들이다.

### 7-1. 배치 모드

| 함정 | 대처 |
|---|---|
| 에디터 버전이 여러 개 설치돼 있다 | `ProjectVersion.txt` 의 버전으로 경로를 만든다. 이름 정렬로 고르면 `6000.3.9f1` 이 `6000.3.10f1` 보다 위로 온다 |
| 다른 버전으로 열면 프로젝트 파일이 덮인다 | `ProjectVersion.txt` · URP 설정 · 패키지 잠금 파일. **실행 후 `git status` 확인** |
| `& $exe` 가 Unity 종료 전에 반환한다 | 로그에 `Exiting batchmode successfully now!` 가 있어야 검증으로 친다 |

### 7-2. 에디터 스크립트

- **`EditorSceneManager.OpenScene(Single)` 은 참조되지 않은 에셋을 언로드한다.**
  씬을 열기 전에 로드해 둔 참조는 죽는다. 죽은 참조를 대입하면 **배열 크기만 늘고 값은 `{fileID: 0}`** 이 되는데,
  로그는 "N개 추가"로 찍혀 성공처럼 보인다. **씬을 먼저 열고 그다음 에셋을 로드할 것.**
- `PreviewRenderUtility` 는 배경색의 알파를 무시한다.
  투명 배경이 필요하면 **검은 배경과 흰 배경으로 두 번 찍어 알파를 역산**한다.
- `AssetDatabase.CreateFolder` 가 옆 파일 때문에 다른 이름으로 만들 수 있다. 생성 후 실제 경로를 확인한다.

### 7-3. 런타임

- **이 프로젝트는 신 Input System 전용**(`activeInputHandler: 1`)이다.
  `UnityEngine.Input` 을 쓰면 런타임에 예외가 난다. `Keyboard.current` · `Mouse.current` 를 쓸 것.
- **`Image.Type.Filled` 는 스프라이트가 있어야 동작한다.**
  없으면 단색 사각형으로 그려지고 `fillAmount` 가 무시된다 — 값은 바뀌는데 바 길이가 변하지 않는다.
- `Instantiate` 는 `Awake` 만 즉시 실행하고 `Start` 는 프레임 끝에 돈다.
  생성 직후 무기를 갈아 끼워도 뒤늦게 돈 `Start` 가 덮어쓴다.

### 7-4. 씬 검색

버튼 배선은 **프리팹 오버라이드** 형태로 저장될 수 있다.

```
propertyPath: m_OnClick.m_PersistentCalls.m_Calls.Array.data[0].m_MethodName
value: OnNextButton
```

`m_MethodName:` 으로만 검색하면 0건이 나와 "배선이 없다"고 오판한다.
