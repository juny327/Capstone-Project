## 1. 이동 (`PlayerMove`)

### 1-1. 속도

`CurrentSpeed` = `baseSpeed`(3) × `speedModifiers` 누적.
슬로우 · 스턴이 리스트로 쌓이므로 **중첩이 자연스럽게 처리**된다.

스프린트는 `CurrentSpeed` 에 `sprintMultiplier`(1.6)를 곱한다.
`AddSpeedModifier` 를 쓰지 않는 이유는, 그러면 슬로우와 뒤섞여 해제 순서에 따라 값이 어긋나기 때문이다.

### 1-2. 스태미나

| 상황 | 초당 |
|---|---|
| 달리기 | -25 (최대 100 → 약 4초) |
| 걷기 | +8 |
| 정지 | +18 |
| 달리기 중단 직후 | 0.5초 대기 후 회복 시작 |

`IsSprinting` 조건에 스태미나가 들어가 있어, 바닥나면 자동으로 달리기가 풀린다.

> **바닥난 뒤에는 25% 가 찰 때까지 다시 달릴 수 없다**(`exhausted`).
> 이 장치가 없으면 0 근처에서 한 프레임씩 달렸다 멈췄다를 반복해 조작감이 망가진다.

### 1-3. 구르기

| 값 | 의미 |
|---|---|
| `rollDistance` 4 | 커브 모양과 무관하게 실제로 이 거리만큼 이동한다 |
| `rollDuration` 1.5 | 클립 길이와 맞춘 값 |
| `rollCooldown` 2.5 | 구르기가 **끝난 뒤부터** 시작 |
| `rollIFrame` 1.5 | 무적 시간 |
| `rollBufferTime` 0.15 | 쿨다운 끝나기 직전 입력을 살린다 |

**실제 재사용 대기는 4초**다 — `rollCdTimer = rollDuration + rollCooldown`.
HUD 는 이 값을 그대로 보여준다(플레이어에게 의미 있는 건 "언제 다시 구를 수 있나"이므로).

구르기 시작 시 상체 레이어를 끄고 **장전을 취소**한다(12번 R2). 모션 없이 장전이 끝나는 눈속임을 막기 위함이다.

## 2. 무기 시스템

### 2-1. 스탯 3층 구조

```
WeaponData (SO, 기본값)              ← 절대 수정하지 않는다
      +
WeaponModifier (누적 업그레이드 + perLevelBonus.Scaled(level-1))
      ↓  Compose()
WeaponRuntimeStats (실제 사용값)
```

> **`WeaponData` 를 직접 고치면 에디터에서 에셋에 영구 기록되어 플레이마다 수치가 누적된다.**
> 업그레이드는 반드시 `WeaponModifier` 로만 쌓는다.

### 2-2. 발사 게이트

```
WeaponController.Update()
  → w.Tick(dt)
  → w.CanFire            // cooldown <= 0 && IsActive && !IsReloading && HasAmmo
  → ShouldFire(w)        // requiresTarget 이면 감지된 적이 있어야
  → w.HasTargetInReach() // 사거리 밖이면 쿨다운을 쓰지 않고 기다린다
  → w.Fire(ctx)
```

### 2-3. 슬롯

| 항목 | 값 |
|---|---|
| 손 무기 | **2칸** (`maxHeldSlots`) |
| 서브유닛 | **3칸** (`maxSubUnitSlots`) |
| 스왑 | `Q` · 마우스 휠 |
| 수동 장전 | `R` |
| 시작 무기 | 로비 선택값 → 없으면 프리팹 `starterWeapon`(소총) |

서브유닛은 `IsAlwaysActive`(= `Kind == SubUnit`)라 스왑과 무관하게 항상 동작한다.

### 2-4. 범용 업그레이드 누적

`ApplyGlobalModifier` 는 누적분을 `globalModifier` 에 보관하고, `Acquire` 로 새 무기가 들어올 때 그대로 얹어 준다.
**보관하지 않으면** "공격력 강화를 먼저 먹고 나중에 얻은 서브유닛"만 약해진다.

## 4. 탄창 · 장전

### 4-1. 규칙 (R1~R6)

| # | 결정 | 구현 위치 |
|---|---|---|
| R1 | 자동 + 수동(`R`) | `TryAutoReload()` · `HandleReloadInput()` |
| R2 | 구르면 장전 취소 | `PlayerMove.StartRoll()` |
| R3 | 산탄도 탄약 1 소모 | `WeaponBase.Fire()` |
| R4 | 빈 채 스왑해도 상태 유지 | `SetActive(false)` 가 취소만 하고 탄약은 둔다 |
| R5 | 서브유닛은 탄창 없음 | `MagazineSize == 0` |
| R6 | 소리 | 미구현 |

`magazineSize == 0` 은 **무제한**이라는 뜻이고, 업그레이드가 붙어도 0 을 유지한다.

### 4-2. 장전 모션

- 클립 `Animations/Player/Reload.anim`, 길이 **2.6667초**
- `PlayerAnimator` 의 **ShootLayer** 에 `Reload` 상태 + `Reload`(Trigger) · `ReloadSpeed`(Float)
- 무기마다 장전 시간이 다르므로 코드가 `ReloadSpeed = 2.67 / ReloadTime` 로 배속을 맞춘다
- 클립이 루프 설정이라, `Reload → 기본 상태` 복귀 전이(exit time 0.95)가 한 바퀴에서 끊어 준다
- 파라미터가 없는 애니메이터에서도 죽지 않도록 `Animator.parameters` 를 훑어 존재를 확인한 뒤 호출한다

## 5. 성장 — 레벨업과 업그레이드 카드

### 5-1. 흐름

```
적 처치 → ExpOrb → PlayerStats.AddExp()
  → 필요량 도달 → 레벨업 → GameEvents.OnLevelUp
  → UpgradeUI 가 카드 3장 (timeScale = 0)
  → 카드 선택 → 확인창 → 확인 버튼 → 창 닫힘 + timeScale = 1
```

`ExpToNext = baseExp(5) + expGrowth(3) × (level - 1)` → 5 · 8 · 11 · 14 · 17 …

> `AddExp` 는 `while` 로 여러 레벨 상승을 처리한다.
> **차감을 먼저 하고 `level++`** 해야 한다 — `ExpToNext` 가 `level` 에 의존하므로 순서를 바꾸면 필요량이 한 레벨씩 밀린다.

### 5-2. 카드

- 후보: **스탯 증가** 또는 **서브유닛 획득** (주 무기는 나오지 않는다)
- 서브유닛 카드는 `CanAcquire` 로 거른다 — 슬롯 만석이거나 최대 레벨이면 후보에서 빠진다
- **비용 없음**. EXP 를 레벨 진행도로 쓰면서 화폐로도 빼면 레벨이 뒤로 밀린다
- 표시 문구는 `UpgradeEffect.GetTitle/GetDescription/GetIcon` 이 답한다.
  서브유닛 카드는 `WeaponData` 의 이름 · 설명을 읽어, 같은 문구를 두 군데 적지 않는다
- 보유 중이면 `Lv.2 -> Lv.3`, 아니면 `[ NEW ]`

### 5-3. 스테이지 클리어

클리어는 **다음 스테이지로 넘기는 역할만** 한다(업그레이드는 레벨업에서 받으므로).

> `BossStage.asset` 은 `killTarget: 0` 이다. `StageManager` 에 **`killTarget <= 0` 이면 처치 수로 끝나지 않는다**는
> 가드와 1회 발행 가드가 들어 있다. 없으면 적을 잡을 때마다 클리어가 발행된다.

### 5-4. ⚠ 창이 멈춘 채 남지 않게 하는 지점

카드는 **전투 중에** 뜨므로 `timeScale = 0` 이 필수다. 복구 지점이 빠지면 게임이 멈춘 채로 남는다.

- 확인 버튼(`UpgradeSuccessUI.OnClose`) → `OnUpgradeConfirmed` → 카드 창 닫기 + `timeScale = 1`
- 확인창이 꺼져 있으면 버튼이 뜨지 않으므로, 그때는 자동 닫힘으로 떨어진다
- 레벨이 한 번에 여러 번 오르면 **큐**에 쌓아 하나씩 띄운다

## 6. UI · HUD

### 6-1. 배치

`PlayerStateUI` 를 캔버스 전체로 늘리고 자식을 화면 가장자리에 앵커한다.

> **이것이 핵심이다.** 예전에는 부모가 100×100 중앙 박스여서 자식 앵커가 의미를 갖지 못했고,
> 화면비가 16:9 보다 넓어지면 위쪽 HUD 부터 화면 밖으로 밀렸다.

| 위치 | 요소 |
|---|---|
| 상단 중앙 | 체력 바 · 수치(-24), 킬 수(-64), EXP 바 · 레벨(-104) |
| 우측 상단 | 경험치 · 공격력 · 탄속 · 이동속도 |
| 하단 중앙 | 탄약 숫자(44), 총알 칸 10개(84) |
| 좌측 하단 | 서브유닛 슬롯 3칸(24), 주무기 슬롯 2칸(118), 구르기 아이콘(214) · 스태미나 바(228) |

### 6-2. 총알 표시

칸 수를 **10으로 고정하고 비율로 채운다**.
탄창이 10 이하인 스나이퍼(5)는 한 칸 = 한 발이 되고, 소총(30) · 기관단총(45)은 한 칸이 여러 발을 대표한다.
45개를 그리면 읽히지 않기 때문이다.

총알 모양 스프라이트는 프로젝트에 없어 **코드로 그려 생성**했다 — `Assets/Sprites/UI/BulletPip.png`.

### 6-3. 무기 슬롯

- 칸 구성: 노란 테두리(활성) → 반투명 배경(알파 28%, 맵이 비침) → 흰 테두리 → 아이콘 · 이름 · 레벨
- 테두리는 **9-슬라이스**라 칸 크기가 달라도(주무기 88 · 서브유닛 72) 두께가 일정하다
- 노란 표시는 손 무기에만 붙는다 — 서브유닛은 전부 항상 동작해 하나를 가리킬 대상이 없다
- 아이콘이 없으면 이름만 나오므로, 아이콘을 나중에 채워도 코드 수정이 필요 없다

### 6-4. 무기 아이콘

| 대상 | 방식 |
|---|---|
| 소총 · SMG · 스나이퍼 · 검 · 드론 · 플라즈마 오브 | 실제 프리팹을 렌더링해 구운 스프라이트 |
| 나머지 서브유닛 6종 | GUI 킷 픽토 아이콘 (파티클 전용이라 렌더링해도 빈 그림) |

### 6-5. 폰트

폰트는 `Assets/Font/RiaSans-Bold SDF` (한글 포함).

> ⚠ 기본 머티리얼의 **`_FaceColor` 가 2.67(HDR 과노출)** 이었다.
> URP Bloom 이 켜져 있어 글자마다 흰 빛이 번져 "뒷배경"처럼 보였다.
> 1.0 으로 정상화하고, HUD 용으로 검은 외곽선 0.12 를 넣은 `RiaSans-Bold SDF Outline.mat` 를 쓴다.

크기 체계: 체력 28 / 킬 34 / 스탯 24.

## 7. 이벤트 계약 (`GameEvents`)

| 이벤트 | 시그니처 | 발행 | 구독 |
|---|---|---|---|
| `OnPlayerSpawned` | `(Transform)` | `GameAppManager.SetupPlayer` | HUD · 업그레이드 · 슬롯 |
| `OnAmmoChanged` | `(int 현재, int 탄창)` | `WeaponBase` | `PlayerStatsUI` |
| `OnWeaponSwapped` | `(IWeapon)` | `WeaponController.SwapTo` | `WeaponSlotUI` |
| `OnWeaponStatsChanged` | `(IWeapon)` | 레벨업 · 모디파이어 | `WeaponSlotUI` |
| `OnWeaponsChanged` | `()` | `Acquire` · `ResetWeapons` | `WeaponSlotUI` |
| `OnLevelUp` | `(int)` | `PlayerStats.AddExp` | `UpgradeUI` |
| `OnUpgradeSelected` / `Success` / `Failed` | `(UpgradeData)` | 카드 · 매니저 | 확인창 |
| `OnUpgradeConfirmed` | `()` | `UpgradeSuccessUI.OnClose` | `UpgradeUI` |
| `OnStageClear` / `OnNextStage` | `()` | `StageManager` / `UpgradeUI` | `GameManager` |
| `OnBossSpawned` | `(BossHealth)` | `BossHealth.Awake` | `BossHPUI` |

> 서브유닛을 얻으면 활성 무기가 바뀌지 않아 `OnWeaponSwapped` 가 나가지 않는다.
> 그래서 목록 변경 전용 이벤트 `OnWeaponsChanged` 가 따로 있다.

## 9. ⚠ 반복해서 걸린 함정

같은 실수를 되풀이하지 않기 위해 남긴다. **전부 실제로 한 번씩 당한 것들이다.**

### 9-1. 배치 모드

| 함정 | 대처 |
|---|---|
| 에디터 버전이 여러 개 설치돼 있다 | `ProjectVersion.txt` 의 버전으로 경로를 만든다. 이름 정렬로 고르면 `6000.3.9f1` 이 `6000.3.10f1` 보다 위로 온다 |
| 다른 버전으로 열면 프로젝트 파일이 덮인다 | `ProjectVersion.txt` · URP 설정 · 패키지 잠금 파일. **실행 후 `git status` 확인** |
| `& $exe` 가 Unity 종료 전에 반환한다 | 로그에 `Exiting batchmode successfully now!` 가 있어야 검증으로 친다 |

### 9-2. 에디터 스크립트

- **`EditorSceneManager.OpenScene(Single)` 은 참조되지 않은 에셋을 언로드한다.**
  씬을 열기 전에 로드해 둔 참조는 죽는다. 죽은 참조를 대입하면 **배열 크기만 늘고 값은 `{fileID: 0}`** 이 되는데,
  로그는 "N개 추가"로 찍혀 성공처럼 보인다. **씬을 먼저 열고 그다음 에셋을 로드할 것.**
- `PreviewRenderUtility` 는 배경색의 알파를 무시한다.
  투명 배경이 필요하면 **검은 배경과 흰 배경으로 두 번 찍어 알파를 역산**한다.
- `AssetDatabase.CreateFolder` 가 옆 파일 때문에 다른 이름으로 만들 수 있다. 생성 후 실제 경로를 확인한다.

### 9-3. 런타임

- **이 프로젝트는 신 Input System 전용**(`activeInputHandler: 1`)이다.
  `UnityEngine.Input` 을 쓰면 런타임에 예외가 난다. `Keyboard.current` · `Mouse.current` 를 쓸 것.
- **`Image.Type.Filled` 는 스프라이트가 있어야 동작한다.**
  없으면 단색 사각형으로 그려지고 `fillAmount` 가 무시된다 — 값은 바뀌는데 바 길이가 변하지 않는다.
- `Instantiate` 는 `Awake` 만 즉시 실행하고 `Start` 는 프레임 끝에 돈다.
  생성 직후 무기를 갈아 끼워도 뒤늦게 돈 `Start` 가 덮어쓴다.

### 9-4. 씬 검색

버튼 배선은 **프리팹 오버라이드** 형태로 저장될 수 있다.

```
propertyPath: m_OnClick.m_PersistentCalls.m_Calls.Array.data[0].m_MethodName
value: OnNextButton
```

`m_MethodName:` 으로만 검색하면 0건이 나와 "배선이 없다"고 오판한다.
