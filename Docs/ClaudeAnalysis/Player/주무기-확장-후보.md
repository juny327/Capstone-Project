# 주무기 확장 후보

> 작성 2026-09-22 · 대상 브랜치 `main`
> 짝 문서: [플레이어-시스템-정리.md](플레이어-시스템-정리.md)

현재 주무기 4종(소총 · 기관단총 · 스나이퍼 · 검)에 새 무기를 더하기 위한 조사 문서다.
**지금 구조에서 코드 없이 되는 것과 새 코드가 필요한 것을 먼저 갈라** 비용을 알고 고를 수 있게 했다.

축은 둘이다.

- **3 ~ 4장 — 총을 더 놓는 쪽.** 수치와 사거리가 다른 무기. 레이저 계열이 여기 들어간다
- **5장 — 쏘는 방식 자체를 바꾸는 쪽.** 궤적 · 착탄 후 파생 · 조작이 달라지는 무기

두 축 모두 아이작을 레퍼런스로 삼되, **자동 발사라는 우리 게임의 전제 때문에
그대로 옮길 수 없는 부분**을 2-1과 5-2에 따로 정리했다.

---

## 1. 지금 구조에서 되는 것 / 안 되는 것

무기는 `WeaponBase` 파생 3종뿐이고, 판정 방식은 **두 가지 선례**밖에 없다.

| 방식 | 구현 | 쓰는 무기 |
|---|---|---|
| 투사체를 만들어 날린다 | `Bullet` (Rigidbody 직선 이동 + `OnTriggerEnter`, 관통 카운터 있음) | 소총 · 기관단총 · 스나이퍼 · 드론 |
| 범위를 훑어 한 번에 때린다 | `OverlapSphereNonAlloc` + 각도 필터 | 검 |

**즉시 명중(히트스캔) 방식이 아직 없다.** 레이저는 여기에 해당하므로 세 번째 방식이 필요하다.

### 1-1. 비용 구분

| 만들고 싶은 것 | 필요한 작업 | 비용 |
|---|---|---|
| 연사 · 피해 · 탄창 · 퍼짐 · 탄 수 · 관통을 바꾼 총 | `.asset` 하나 만들고 숫자만 | **코드 0줄** |
| 사거리 · 각도 · 타격 수를 바꾼 근접 무기 | 같음 | **코드 0줄** |
| 즉시 명중 관통 레이저 | `BeamWeapon` + `BeamWeaponData` 새로 | 파일 2개 |
| 지속 빔 (계속 붙어 있는 광선) | 위 + 틱 피해 · 라인 렌더러 | 파일 2개 + 연출 |
| 고리 모양으로 퍼지는 레이저 | 새 투사체 컴포넌트 (`RingProjectile`) | 파일 2개 |
| 착탄 후 폭발 | `Bullet` 확장 또는 `ExplosiveBullet` | 파일 1개 |

### 1-2. 이미 깔려 있어 그대로 쓸 수 있는 것

새 무기를 만들 때 **다시 만들 필요가 없는** 부분이다.

- **탄창 · 장전** — `WeaponBase` 가 전부 처리한다. 새 데이터 클래스의 `Compose()` 에서
  `s.MagazineSize` 와 `s.ReloadTime` 만 채우면 장전 · HUD · 스왑 취소가 자동으로 따라온다.
- **업그레이드 합성** — `WeaponModifier` 에 피해 · 연사 · 관통 · 탄 수 · 사거리 · 탄창이 이미 있다.
- **치명타** — `RollCritical` / `ApplyCritical` 가 `WeaponBase` 에 있다.
- **조준 방향** — `WeaponFireContext.AimDirection` 이 마우스 방향을 준다.
  가장 가까운 적 자동 조준은 `WeaponAimMode.NearestTarget` 으로 데이터에서 켠다.
- **슬롯 · 스왑 · 아이콘 · HUD** — `WeaponKind.Projectile` 또는 `Melee` 면 그대로 동작한다.

## 2. 레퍼런스 조사 — 아이작의 레이저 계열

언급하신 "테크 레이저" 계열을 실제 동작 기준으로 정리했다.

| 아이템 | 동작 | 우리 게임으로 옮기면 |
|---|---|---|
| **Technology** | 눈물 대신 **즉시 명중 관통 레이저**. 발사 속도는 연사 스탯을 따른다 | 히트스캔 + 무한 관통. 가장 옮기기 쉽다 |
| **Technology 2** | 한쪽 눈이 **끊기지 않는 빔**을 계속 쏜다. 무한 사거리 관통, **초당 15회** 피해 | 지속 빔. 피해 틱을 초당 15회로 두면 숫자가 화면을 덮는다 |
| **Tech.5** | 일반 눈물에 **더해** 레이저가 1/6 확률로 ~0.07초마다 나간다 | 서브유닛에 가깝다. 주무기보다 드론 쪽 확장에 맞다 |
| **Tech X** | 눈물이 **고리 모양 레이저**로 바뀐다. 충전하면 고리가 커진다. **고리의 바깥 둘레만** 피해를 준다. 적 · 장애물을 통과하고 사거리가 무한이며, 벽에 닿으면 잠시 머문다. 충전은 **크기만** 키우고 피해는 25% → 100% 로 오른다 | 가장 개성이 강하다. 충전 입력이 없는 게 문제 |
| **Brimstone** | 충전 후 굵은 관통 빔을 한 번 크게 쏜다 | 스나이퍼와 역할이 겹친다 |

### 2-1. 그대로 옮기면 안 되는 세 가지

**(1) 충전이 성립하지 않는다.**
아이작은 플레이어가 발사를 누르고 있다가 놓는다. 우리 게임은 **적이 범위에 들어오면 자동으로 쏜다.**
충전을 넣으려면 발사 입력을 새로 만들어야 하는데, 이건 게임의 조작 전제를 바꾸는 일이다.
→ **충전 대신 "발사 간격을 길게 + 한 방을 강하게"** 로 번역하는 편이 맞다. 스나이퍼가 이미 그 방식이다.

**(2) 초당 15회 피해는 우리 연출과 충돌한다.**
`DamageText` 가 피격마다 숫자를 띄우므로, 초당 15회 × 관통 5명이면 초당 75개의 숫자가 뜬다.
→ 지속 빔을 넣는다면 **틱 간격을 0.2초(초당 5회) 이상**으로 잡고, 피해량을 그만큼 키워야 한다.

**(3) 무한 사거리가 의미가 없다.**
아이작은 방 하나가 화면에 다 들어오지만, 우리는 탑다운 카메라에 맵이 이어져 있다.
적 감지 범위가 10m이므로, 사거리는 **12~18m 정도**면 "무한처럼" 느껴진다.

## 3. 추가 후보

**차별화 ÷ 구현 비용** 순으로 정렬했다. 위 세 개만 해도 무기 구성이 충분히 달라진다.

> **샷건 · 전격 소총 · 충전 레이저** 3종은 실제 작업 계획을
> [무기-3종-구현계획.md](무기-3종-구현계획.md) 에 따로 정리했다.

| # | 무기 | 한 줄 | 새 코드 | 모델 |
|---|---|---|---|---|
| 1 | **레이저 라이플** | 즉시 명중 · 일직선 관통 | 파일 2개 | 대체 필요 |
| 2 | **샷건** | 근거리 산탄, 붙어야 아프다 | **없음** | `AR_4` 등 |
| 3 | **석궁** | 느리지만 한 발이 꿰뚫는다 | **없음** | `Crossbow_1` |
| 4 | **테크 링** | 고리가 퍼지며 지나간 적을 벤다 | 파일 2개 | 대체 필요 |

## 4. 후보별 상세

### 4-1. 레이저 라이플 — 첫 번째로 권함

> Technology 계열. **총알이 날아가지 않고 즉시 맞는다**는 점 하나로 기존 총 3종과 완전히 갈린다.

지금 총 3종은 탄속(20 / 25 / 60)만 다를 뿐 전부 "투사체를 피할 수 있다". 빠르게 움직이는 적에게
빗나가는 감각이 공통으로 있다. 레이저는 그 감각을 없애는 대신 **한 발의 값이 비싸다.**

| 항목 | 값 | 근거 |
|---|---|---|
| `damage` | 5 | 소총(2)과 스나이퍼(12) 사이 |
| `fireInterval` | 0.5 | 소총보다 느리게 — 즉시 명중의 대가 |
| `critChance` / `critMultiplier` | 0.08 / 2 | |
| 관통 | 무제한 (또는 5) | 일직선 위 적을 전부 |
| 사거리 | 15 m | 감지 범위 10m보다 길게 |
| `magazineSize` / `reloadTime` | 20 / 2.2 | |

**구현 메모**
- `BeamWeaponData : WeaponData` (`Kind => Projectile`) + `BeamWeapon : WeaponBase`
- 판정: `Physics.SphereCastNonAlloc`(반지름 0.2 정도) 로 한 번에 훑는다.
  `RaycastNonAlloc` 은 가는 적을 자주 놓친다.
- 중복 제거는 `MeleeWeapon.ApplyHits` 의 `HashSet<Transform> struck` 방식을 그대로 쓴다.
- 연출은 `LineRenderer` 를 0.05초 켰다 끄는 것으로 충분하다.
- 탄창은 `Compose()` 에서 `s.MagazineSize` · `s.ReloadTime` 만 채우면 끝이다.

**에셋**: 레이저 총 모델이 프로젝트에 없다. 쓰지 않는 `GunPack/Guns/AR_4` 나 `Pistol_3` 을
가져다 쓰고 빔 색(청록)으로 구분하거나, 별도 에셋을 받아야 한다.

### 4-2. 샷건 — 코드 없이 오늘 추가 가능

> `projectileCount` 와 `spreadAngle` 이 이미 데이터에 있다. **`.asset` 하나로 끝난다.**

| 항목 | 값 | 비고 |
|---|---|---|
| `damage` | 1.6 | 탄 1발당. 8발 전부 맞으면 12.8 |
| `fireInterval` | 0.9 | |
| `projectileCount` | 8 | |
| `spreadAngle` | 28 | 기관단총(5)보다 훨씬 넓게 |
| `projectileSpeed` | 18 | 느리게 — 멀면 퍼져서 안 맞는다 |
| `projectileLifeTime` | 0.35 | **사거리를 여기서 만든다.** 18 × 0.35 ≈ 6m |
| `magazineSize` / `reloadTime` | 6 / 2.4 | |

**핵심**: `projectileLifeTime` 을 짧게 잡아 **거리로 위력이 갈리게** 한다.
붙으면 8발이 다 맞고 멀면 하나도 안 맞으므로, 구르기로 파고드는 플레이와 맞물린다.

`perLevelBonus.projectileCountAdd = 1` 로 두면 레벨업마다 탄이 늘어 성장이 눈에 보인다.

---

### 4-3. 석궁 — 코드 없이 오늘 추가 가능

> 모델이 이미 있다 (`GunPack/Guns/Crossbow_1.fbx`).

| 항목 | 값 |
|---|---|
| `damage` | 9 |
| `fireInterval` | 1.1 |
| `pierceCount` | 6 |
| `projectileSpeed` | 35 |
| `critChance` / `critMultiplier` | 0.15 / 2.2 |
| `magazineSize` / `reloadTime` | 1 / 1.3 |

**탄창 1발**이 이 무기의 성격이다. 한 발 쏠 때마다 장전하므로 "쏘고 → 장전하며 피하고 → 쏘고"
리듬이 생긴다. 스나이퍼(단발 고피해)와 달리 **줄 서 있는 적을 뚫는 것**이 목적이라 관통이 훨씬 높다.

### 4-4. 테크 링 — Tech X 오마주

> 가장 개성이 강하지만 **충전을 뺀 번역**이 필요하다.

고리가 플레이어에게서 퍼져 나가며, 고리의 **둘레에 닿은 적**이 피해를 입는다.
적과 벽을 통과하고 계속 커지다 사라진다.

| 항목 | 값 |
|---|---|
| `damage` | 3 (고리에 닿을 때마다) |
| `fireInterval` | 1.3 |
| 시작 반지름 → 최대 반지름 | 1 m → 7 m |
| 확장 속도 | 9 m/초 |
| 같은 적 재피격 | 없음 (한 고리당 1회) |

**구현 메모**
- `RingProjectile` 컴포넌트를 새로 만든다. 매 프레임 반지름을 키우고
  `Physics.OverlapSphere(현재 반지름)` 과 `OverlapSphere(직전 반지름)` 의 **차집합**을 때린다.
  이러면 "둘레만 피해"가 자연스럽게 나온다.
- 한 고리가 같은 적을 여러 번 때리지 않도록 `HashSet<Transform>` 으로 막는다.
- 충전 대신 **레벨이 오르면 최대 반지름이 커지게** 하면 Tech X 의 "커질수록 좋다"를 살릴 수 있다.

**주의**: 사방 360도로 나가므로 조준이 의미 없어진다. 마우스 조준을 쓰는 다른 무기와
플레이 감각이 크게 달라지는데, 이게 장점일 수도 단점일 수도 있다. **프로토타입을 먼저 보고 판단할 것.**

### 4-5. 유탄 발사기

| 항목 | 값 |
|---|---|
| `damage` | 4 (직격) + 7 (폭발) |
| `fireInterval` | 1.4 |
| 폭발 반경 | 3.5 m |
| `projectileSpeed` | 14 |
| `magazineSize` / `reloadTime` | 4 / 2.4 |

`Bullet` 을 상속한 `ExplosiveBullet` 에서 `OnTriggerEnter` 때 `OverlapSphere` 로 범위 피해를 준다.
폭발 이펙트는 `GabrielAguiarProductions/FreeQuickEffectsVol1/vfx_Explosion_01` 을 쓸 수 있다.

### 4-6. 지속 빔 — 나중에

Technology 2 계열. 레이저 라이플(4-1)이 먼저 들어가야 한다. 같은 판정 코드를 재사용하되
매 프레임이 아니라 **0.2초 간격으로 틱**을 돌린다.

`fireInterval` 을 틱 간격으로 쓰고, "적이 사라지면 빔이 꺼진다"만 추가하면 된다.
`requiresTarget = true` 이므로 기존 발사 게이트가 그 판단을 이미 해 준다.

## 5. 공격 방식 자체를 바꾸는 무기

3~4장이 "총을 몇 자루 더 놓을까"였다면, 이 장은 **쏘는 방식 자체를 바꾸는** 쪽이다.
아이작이 눈물을 건드리는 방법을 뜯어 보면 축이 다섯 개다.

> **용어 확인**: 말씀하신 "박사학위"는 눈물 대신 **폭탄**을 쏘는 `Dr. Fetus` 로 보고 정리했다.
> `PhD` 라는 아이템은 따로 있지만 알약을 바꾸는 것이라 공격 방식과 무관하다.

### 5-1. 눈물을 바꾸는 다섯 가지 축

| 축 | 무엇이 바뀌나 | 아이작 아이템 |
|---|---|---|
| **① 발사체 교체** | 날아가는 물건 자체가 다른 것이 된다 | 혈사포(빔) · Dr. Fetus(폭탄) · 엄마의 칼(칼) · Trisagion(빛줄기) |
| **② 궤적 변경** | 직선으로 안 간다 | 구토제(포물선) · 타이니 플래닛(공전) · 안티 그래비티(멈췄다 발사) · 러버 시멘트(튕김) · 내 거울(부메랑) |
| **③ 착탄 후 파생** | 맞은 다음에 일이 더 생긴다 | 야곱의 사다리(전기 분기) · 헤모라크리아(작은 탄 파열) · 구토제(폭발 + 독) |
| **④ 조작 방식 변경** | 쏘는 행위의 조작이 달라진다 | 루도비코(탄을 직접 조종) · 에픽 피투스(조준점 폭격) · 엄마의 칼(붙으면 근접) |
| **⑤ 발사 리듬 변경** | 언제 얼마나 나가는지가 달라진다 | 몬스트로의 폐(충전 산탄) · 소이 밀크(초고연사 저피해) · 저주받은 눈(4연발) |

**우리 게임에 가장 값싸게 들어오는 축은 ③이다.** 투사체는 그대로 두고 착탄 시점에만
코드를 얹으면 되므로 `Bullet` 한 곳만 건드린다. ①과 ②는 새 컴포넌트가 필요하고,
④는 조작 전제를 건드린다.

### 5-2. 옮길 때 공통으로 걸리는 세 가지

**(1) 자동 발사라 "안 쏘는 선택"이 없다.**
구토제와 Dr. Fetus는 **자기도 피해를 입는 것**이 장치의 핵심인데, 아이작은 쏠지 말지를
플레이어가 정한다. 우리는 적이 범위에 들어오면 무조건 쏘므로 자기 피해를 넣으면
**플레이어가 통제할 수 없는 피해**가 된다.
→ 자기 피해는 빼고, 대신 **최소 사거리**로 위험을 표현하는 편이 맞다.

**(2) 최소 사거리 개념이 없다.**
`EnemyDetector` 는 10m 안의 적을 전부 알려 주므로 1m 앞의 적에게도 발사가 나간다.
포물선 · 폭발 무기는 발밑에서 터진다.
→ `HasTargetInReach()` 를 재정의해 **너무 가까우면 쏘지 않게** 막을 수 있다.
검이 최대 사거리를 거르는 데 쓰는 훅을 그대로, 부등호만 뒤집어 쓰면 된다.

**(3) 총알이 벽을 그냥 통과한다.**
`Bullet.OnTriggerEnter` 는 `Enemy` · `Boss` 태그만 보고 나머지는 전부 무시한다.
벽에 맞는 개념이 아예 없고, 수명이 다해야 사라진다.
→ **러버 시멘트(도탄) · 벽에 머무는 Tech X 같은 것은 벽 충돌 처리가 선행 작업이다.**

### 5-4. 전격 소총 — 이 목록에서 가장 권함

> 야곱의 사다리. **우리 구조에 이미 필요한 부품이 다 있다.**

맞은 적에게서 전기가 튀어 근처의 다른 적으로 옮겨 간다. 절반 피해로 2단계까지.

`ITargetProvider.GetTargets(위치, 개수, 버퍼)` 가 **가까운 순으로 정렬된 적 목록**을
이미 주고 있다. 연쇄 대상을 찾는 코드를 새로 쓸 필요가 없다는 뜻이다.
`MeleeWeapon.HasTargetInReach` 가 같은 함수를 이미 그렇게 쓰고 있다.

| 항목 | 값 |
|---|---|
| `damage` | 3 |
| `fireInterval` | 0.45 |
| 연쇄 횟수 | 2 |
| 연쇄 피해 비율 | 50% (3 → 1.5 → 0.75) |
| 연쇄 사거리 | 4 m |
| `magazineSize` / `reloadTime` | 24 / 2.0 |

**구현 메모**: `Bullet` 에 `OnHit` 가상 메서드를 하나 열고 `ChainBullet` 이 이를 재정의한다.
`WeaponData` 가 아니라 **탄 프리팹 쪽에 얹는 방식**이라, 나중에 다른 무기도
탄만 바꿔 끼우면 전격이 된다.

**왜 잘 맞나**: 뱀서라이크는 적이 뭉쳐 다니므로 연쇄가 자주 터진다. 동시에
한 마리만 있을 때는 평범한 총이라, 쓰는 상황에 따라 체감이 달라진다.

### 5-5. 파열탄

### 5-6. 회수형 검

> 엄마의 칼. 아이작에서는 **붙어 있으면 초당 20회 찌르고, 던지면 관통하며 날아갔다 돌아온다.**

지금 무기 구성에는 **근접(검 3m)과 원거리(총 10m+) 사이가 비어 있다.**
이 무기가 그 자리를 메운다.

- 던진 검은 최대 거리까지 갔다가 **플레이어에게 돌아온다.** 갈 때와 올 때 모두 맞는다
- 돌아오는 중에는 플레이어가 움직여도 따라온다
- 검이 나가 있는 동안에는 다음 발사가 안 된다 → 연사 대신 **위치 잡기**가 중요해진다

충전은 넣지 않는다(5-2). 대신 **레벨이 오르면 사거리가 늘어나게** 해 아이작의
"충전할수록 멀리"를 성장으로 옮긴다.

| 항목 | 값 |
|---|---|
| `damage` | 7 (왕복 각 1회, 같은 적 재피격 없음) |
| `fireInterval` | 0.9 |
| 사거리 | 7 m (레벨당 +1) |
| 관통 | 무제한 |

### 5-7. 부유 코어

> 루도비코 테크닉. 눈물을 쏘지 않고 **직접 조종한다.**

아이작에서는 조작 방식을 통째로 바꾸는 아이템이지만, **우리 게임에는 오히려 쉽게 들어온다.**
이미 마우스 커서 방향으로 캐릭터가 회전하고 있으므로, 그 커서 위치를 그대로 쓰면 된다.

- 구체 하나가 플레이어 앞 일정 거리에 떠 있고, **커서 방향으로 천천히 따라 움직인다**
- 닿아 있는 적에게 **0.2초마다** 피해 (초당 5회 — 5-2의 숫자 폭탄 문제 회피)
- 탄창도 장전도 없다. 대신 피해가 낮다

| 항목 | 값 |
|---|---|
| 틱 피해 | 1.2 |
| 틱 간격 | 0.2초 |
| 반경 | 1.2 m |
| 추적 거리 | 최대 6 m |

**주의**: `requiresTarget = false` 로 두어야 적이 없어도 구체가 떠 있는다.
`WeaponController.ShouldFire` 가 이미 이 분기를 갖고 있다.

## 6. 구현 순서 제안

3장(총을 더 놓는 쪽)과 5장(방식을 바꾸는 쪽)을 섞어, **싼 것부터 · 뒤를 받쳐 주는 것부터** 놓았다.

| 단계 | 내용 | 결과 |
|---|---|---|
| 1 | 샷건 · 석궁 · 단검 `.asset` 3개 (4-2 · 4-3 · 4-7) | 코드 변경 없이 주무기 **4종 → 7종** |
| 2 | `Bullet` 에 착탄 훅(`OnHit`) 하나 열기 | 3단계 두 무기의 공통 토대 |
| 3 | 전격 소총(5-4) · 파열탄(5-5) | **탄 프리팹만 바꿔 끼우는 확장** 확보 |
| 4 | `BeamWeapon` + `BeamWeaponData` → 레이저 라이플(4-1) | 히트스캔 구조 확보 |
| 5 | 차지 캐논(5-4 표) · 지속 빔(4-6) | 4단계 코드 재사용 |
| 6 | `RingProjectile` → 테크 링(4-4) | |
| 7 | 회수형 검(5-6) · 부유 코어(5-7) | 근접 ↔ 원거리 사이를 메움 |
| 8 | `ExplosiveBullet` → 유탄 · 폭탄 · 산성탄 (4-5 · 5-3) | 폭발 계열을 한 번에 |

1단계를 먼저 하는 이유는 **무기가 늘어났을 때 UI · 밸런스가 어떻게 무너지는지 싸게 확인**하기
위해서다. 아래 7장의 문제들이 바로 드러난다.

2단계가 따로 있는 이유는, 착탄 훅 하나를 열어 두면 **전격 · 파열 · 폭발 · 독이 전부 같은
자리에 얹히기** 때문이다. 무기마다 `Bullet` 을 복사하는 것을 막는 투자다.

## 7. 무기를 늘리면 함께 손봐야 하는 것

무기 하나를 추가할 때 `.asset` 만으로는 끝나지 않는다. **네 곳이 4종 기준으로 고정돼 있다.**

| 위치 | 현재 | 손봐야 하는 이유 |
|---|---|---|
| `LobyManager.selectableWeapons` | 4개 배정됨 | 인스펙터 배열이라 늘리는 것 자체는 쉽다 |
| `Editor/LobySelectSetup.cs` 의 `Weapons` 배열 | 4개 하드코딩 | 로비 버튼을 만드는 도구. 5개 이상이면 **가로 배치가 넘친다** |
| `Editor/WeaponIconRender.cs` 의 `Weapons` 배열 | 5개 하드코딩 | 아이콘을 프리팹에서 렌더링. 여기 없으면 아이콘이 안 생긴다 |
| `WeaponController.maxHeldSlots` | 4 | 손에 드는 슬롯 수. HUD 슬롯 칸(`PlayerHudSetup.SlotCount`)도 4다 |

### 7-1. 더 큰 문제 — 무기를 얻을 방법이 하나뿐이다

지금 무기가 손에 들어오는 경로는 **로비에서 시작 무기를 고르는 것**뿐이다.
`WeaponController.Acquire()` 는 있지만 이걸 호출하는 업그레이드 효과가 없다.

무기를 7종으로 늘려도 **한 판에 1종만 쓰게 된다.** 슬롯이 4칸인 의미도 없다.

→ **해결 방향이 정해졌다. 스테이지를 깰 때마다 무기를 하나 고른다.**
자세한 내용은 아래 **8장**에 있다.

## 8. 무기 획득 — 스테이지 사이에서

### 8-1. 정해진 흐름

스테이지를 깨고 다음 스테이지로 넘어가기 전에 무기를 고른다. **기회는 세 번이다.**

| 전환 | 획득 |
|---|---|
| Stage1 클리어 → Stage2 | 1회 |
| Stage2 클리어 → Stage3 | 1회 |
| Stage3 클리어 → (보스 연출) → StageBoss | 1회 |

시작 무기 1 + 획득 3 = **최대 4종**.
손에 드는 슬롯이 정확히 4칸(`WeaponController.maxHeldSlots`)이라 **딱 맞아떨어진다.**

### 8-2. 지금의 클리어 흐름

실제 코드(`GameManager.StageClearFlow()`) 기준이다.

```
StageManager: killCount >= killTarget
  → GameEvents.OnStageClear
  → GameManager.StageClearFlow()
      1. 남은 레벨업 카드를 먼저 처리 (isUpgradeOpen || pendingLevelUps > 0 동안 대기)
      2. OnShowStageClearUI      → StageClearUI 패널 ON
      3. WaitForSecondsRealtime(3)
      4. OnHideStageClearUI      → 패널 OFF
      5. OnNextStage             → LoadScene(buildIndex + 1)
```

**끼워 넣을 자리는 4번과 5번 사이다.** 레벨업 카드가 이미 1번에서 처리되므로
창이 겹칠 걱정도 없다.

### 8-3. 좋은 소식 — 얻은 무기는 저절로 유지된다

가장 걱정되는 부분은 "씬을 넘어가면 얻은 무기가 사라지지 않나"인데, **사라지지 않는다.**

`GameAppManager.SetupPlayer()` 는 `Player == null` 일 때만 플레이어를 만들고
`DontDestroyOnLoad` 를 건다. 즉 플레이어 오브젝트는 **한 번만 생성되어 씬을 넘어 계속 살아 있고,
위치만 초기화된다.**

따라서

- `WeaponController` 의 **보유 무기 · 레벨 · 누적 업그레이드가 그대로 유지된다**
- `WeaponController.Start()` 는 **첫 스테이지에서 한 번만** 돈다 (시작 무기 장착)
- 획득은 `Acquire(data)` **한 줄이면 끝**이고, `GameAppManager` 에 따로 저장할 필요가 없다

> 로비 선택 무기만 `GameAppManager.SelectedWeapon` 에 담아 넘기는 이유는
> **그 시점에 플레이어가 아직 없기 때문**이다. 스테이지 사이에서는 이미 살아 있으므로
> 그 우회가 필요 없다.

### 8-4. 필요한 것

| 대상 | 구분 | 내용 |
|---|---|---|
| `WeaponRewardUI` | 신규 | 무기 카드 3장 표시 · 선택 대기 |
| `WeaponRewardPool` (ScriptableObject) | 신규 | 후보 무기 목록 |
| `GameEvents` | 수정 | `OnWeaponRewardOpen` · `OnWeaponRewardPicked(WeaponData)` |
| `GameManager.StageClearFlow()` | 수정 | 4번과 5번 사이에서 선택을 기다린다 |
| Stage 씬 4개 | 수정 | UI 배치 — 에디터 도구로 일괄 (`PlayerHudSetup` 방식) |

**구조는 업그레이드 카드를 그대로 베낄 수 있다.**
`UpgradeUI` 가 이미 "패널 ON → 후보 뽑기 → 카드 `Setup` → 클릭 → 이벤트 → 패널 OFF" 로 되어 있고,
`Time.timeScale = 0` + `WaitForSecondsRealtime` 규약도 `GameManager` 에 이미 있다.

### 8-5. 후보를 뽑는 규칙

| 상황 | 처리 | 근거 |
|---|---|---|
| 이미 가진 무기가 뽑혔다 | **레벨업으로 처리** | `Acquire()` 가 `LeveledUp` 을 반환한다 |
| 슬롯 4칸이 다 찼다 | 새 무기를 후보에서 빼고 **가진 무기 레벨업만** 띄운다 | 안 그러면 `NoFreeSlot` 이라 아무 일도 안 일어난다 |
| 최대 레벨(5)에 도달 | 후보에서 뺀다 | `MaxLevel` 반환 |
| 후보가 3개보다 적다 | 카드 수를 줄인다 | `UpgradeUI.Open()` 이 이미 그렇게 한다 |
| 드론(서브유닛) | 같이 섞어도 된다 | 손에 드는 슬롯과 별개로 2칸이 있다 |

> **"건너뛰기" 버튼은 넣지 않는 편이 좋다.**
> 기회 3번 × 슬롯 4칸이 정확히 맞물려 있어서, 건너뛰면 슬롯이 빈 채로 게임이 끝난다.
> 원치 않는 무기를 피하게 하려면 후보에 **"지금 든 무기 강화"** 카드를 섞는 편이 낫다.

### 8-6. 보스 직전 주의

빌드 순서상 Stage3 다음은 StageBoss 가 아니라 **IntroScene(보스 연출)** 이고,
거기서 `SequenceController` 가 StageBoss 를 부른다.

세 번째 획득은 **Stage3 클리어 직후**에 일어나므로 순서상 문제가 없다.
다만 `LoadNextStage()` 가 `buildIndex + 1` 로 씬을 고르므로,
**씬을 빌드 설정에서 옮기면 흐름이 통째로 어긋난다.** 무기 UI와는 무관하지만 같이 알아 둘 것.

### 8-7. 아직 정해지지 않은 것

- 보상을 무기만 줄 것인가, **무기 / 강화 중 선택**으로 할 것인가
- 보스 클리어 보상은 어떻게 할 것인가 (지금은 바로 `EndingScene` 으로 간다)
- 획득 화면에서 **무기 모델을 보여 줄 것인가** (아이콘은 이미 렌더링해 둔 것이 있다)

## 9. 밸런스 기준선

새 무기 수치를 정할 때 맞춰야 할 현재값이다. 치명타 기대값을 포함했다.

`기대 피해 = damage × (1 + 치명타확률 × (배율 − 1))`

| 무기 | 기대 피해/발 | 연사 DPS | 장전 포함 DPS | 비고 |
|---|---|---|---|---|
| 소총 | 2.10 | 7.00 | **5.73** | 30발 → 9초 사격 + 2초 장전 |
| 기관단총 | 1.37 | 11.41 | **8.81** | 45발 → 5.4초 + 1.6초 |
| 스나이퍼 | 16.50 | 10.31 | **7.78** | 5발 → 8초 + 2.6초 |
| 검 | 6.60 | 9.43 | **9.43** | 장전 없음 |
| 드론 | 2.10 | 2.63 | 2.63 | 항상 동작 |

**관통 · 광역을 넣으면 실제 DPS는 크게 올라간다.**
스나이퍼는 관통 3이므로 적 4명이 겹치면 31.1, 검은 5명이면 47.1 이다.

> **발견한 문제**: 검이 단일 대상 기준으로도 장전 포함 DPS 1위(9.43)이고,
> 5명 기준으로는 2위의 5배다. 사거리 3m라는 대가가 있긴 하지만 수치가 과하다.
> 새 무기를 넣기 전에 검을 먼저 보는 편이 좋다.

새 무기는 **장전 포함 DPS 5.5 ~ 9** 사이에 들어오도록 잡고, 관통 · 광역이 있으면 낮은 쪽에 둔다.
