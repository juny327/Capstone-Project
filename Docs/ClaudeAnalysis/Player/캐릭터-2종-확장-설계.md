게임을 시작할 때 **원거리 캐릭터(지금)** 와 **근거리 캐릭터(신규)** 중 하나를 고르고,

## 0. 요약

| 항목 | 결론 |
|---|---|
| 구조 | **플레이어 프리팹은 하나로 두고**, 캐릭터 차이는 `CharacterData`(데이터)로 표현한다 |
| 무기 제한 | `WeaponController.CanAcquire` **한 곳**에 캐릭터 규칙을 넣는다 → 스테이지 보상이 코드 수정 없이 따라온다 |
| 로비 | 사수 · 검사 영역을 **좌우로 크게 떨어뜨려** 한 화면에 둔다 — 무기를 고르면 그 무기의 캐릭터가 정해진다 (5-2) |
| 무기 배분 | 사수 = 지금의 총 6종 · 검사 = **검 · 대검 · 창 3종** · 드론은 공용 |
| 회피 | 사수 = **구르기**(지금 그대로) · 검사 = **패링** — 주변 · 커서 방향의 적을 밀쳐내고 적 투사체를 쳐낸 뒤 무적. 쿨타임 **5초** (헛쳐도 5초) |
| 제일 큰 공백 | 근접 무기가 **검 1종**뿐이다 → **대검 · 창 2종**을 먼저 만든다 |
| 대검 · 창 모델 | 이미 받아 둔 **Futura 원본 팩**으로 해결된다 — 창 = 할버드, 대검 = 검 A 를 크게 · 다른 색 (10-1) |
| 근접 사거리 · 크기 | 검 3m · 대검 4m · 창 5m. 무기 길이 2.3 · 3.5 · 5.0m 로 칼끝이 사거리 끝 근처까지 닿는다 (15 · 16장) |
| 근접 모션 | 휘두를 때마다 **기본 공격 · 양손 내려찍기** 중 무작위. 기본 공격 = 검 한손 가로베기 · 대검 양손 가로베기 · 창 양손 찌르기 (16장) |
| 협업 제약 | 기존 스크립트는 `Assets/Scripts/Player` 안에서만 고친다 — 패링까지 포함해 이 설계는 그 안에서 끝난다 |

## 1. 두 캐릭터 컨셉

| | **사수** (현재) | **검사** (신규) |
|---|---|---|
| 주력 | 총 · 빔 (원거리) | 검 · 대검 · 창 (근거리 광역) |
| 플레이 | 거리를 벌리고 조준한다 | **파고들어** 한 번에 여러 마리를 벤다 |
| 강점 | 안전하다. 멀리서 처리 | 광역 · 고화력. 뭉친 적에게 강하다 |
| 약점 | 둘러싸이면 약하다 | **맞으면서 싸워야 한다** |
| 회피 | **구르기** — 자리를 벗어난다 | **패링** — 자리를 지키며 밀어낸다 |
| 조작 핵심 | 마우스 조준 · 장전 관리 | 파고들 타이밍 · 패링 타이밍 |
| 탄창 · 장전 | 있음 | **없음** — 장전 HUD 가 저절로 숨는다 |

두 캐릭터가 같은 게임 안에서 **다른 판단을 요구**해야 한다.
사수는 "어디서 쏠까", 검사는 "언제 들어가고, 언제 밀어낼까"가 핵심 질문이 되도록 수치를 잡는다.

회피 수단이 다르면 이 차이가 몸으로 느껴진다. 사수는 위험하면 **빠져나가고**,
검사는 위험하면 **그 자리에서 밀어낸 뒤 다시 벤다.**

### 1-1. 스탯 방향 (초안)

검사는 적에게 붙어야 하므로 **맞는 것을 전제로** 버틸 수단이 필요하다.

| 스탯 | 사수 | 검사 | 이유 |
|---|---|---|---|
| 최대 체력 | 100 | **140** | 근접은 피격이 잦다 |
| 받는 피해 | ×1.0 | **×0.85** | 체력만 올리면 회복 카드 가치가 달라진다. 감소율로 나눠 준다 |
| 이동 속도 | ×1.0 | **×1.1** | 적에게 다가가는 시간이 곧 손해다 |
| 회피 | 구르기 (전체 **4.0초** 주기) | **패링** (**5.0초** — 성공 · 헛침 같음) | 7장. 패링은 무적 + 밀쳐내기 + 반격이라 구르기보다 길게 |
| 최대 스태미나 | 100 | 120 | 달려서 붙는 시간이 길다 (스태미나는 달리기에만 쓴다) |

> 구르기의 "4.0초"는 `PlayerMove.RollCooldownTotal` = 구르는 시간 1.5초 + 쿨타임 2.5초다.
> HUD 가 보여 주는 값도 이것이므로, 패링 쿨타임은 **이 값과 비교해 길게** 잡는다.
>
> 수치는 **테스트 룸에서 실측하며 조정할 초안**이다. 방향만 확정하고 숫자는 나중에 바꾼다.

## 2. 지금 구조에서 "캐릭터가 하나로 묶인" 지점

조사해 보니 캐릭터를 둘로 나누려면 다음이 걸린다. 추정이 아니라 코드와 에셋을 확인한 결과다.

| 지점 | 현재 | 문제 |
|---|---|---|
| 플레이어 생성 | `GameAppManager.playerPrefab` **하나** | 프리팹을 둘로 나누면 여기를 고쳐야 한다 (Core — 제약 밖) |
| 로비 무기 목록 | `LobyManager.selectableWeapons` **7종 평면 목록** | 캐릭터별로 나뉘어 있지 않다 |
| 스테이지 보상 | `StageRewardPool` 에 **무기 7종 공용** | 검사에게 소총이 나오면 안 된다 |
| 근접 무기 | **검 1종** | 검사를 고르면 시작 무기 선택지가 하나뿐이다 |
| 근접 모션 | `MeleeWeapon` 이 `Slash` 트리거 **하나**만 쓴다 | 검 · 대검 · 창이 모두 같은 동작으로 휘두른다 |
| 회피 | `PlayerMove` 의 **구르기 하나** | 캐릭터마다 다른 회피를 줄 수 없다 |
| 업그레이드 카드 | `MainUpgradePool` 공용 | 지금 카드는 전부 공용이라 **괜찮다** (아래 8장) |
| 테스트 룸 | 자체 `playerPrefab` 으로 생성 | 캐릭터를 고를 방법이 없다 |

### 2-1. 다행인 점 — 애니메이션 기반은 이미 있다

- 애니메이터에 **`ShootLayer` 와 `MeleeLayer` 가 따로 있고**, `MeleeLayer` 는 **상체 마스크**(`Upper.mask`)를 쓴다.
  근접 무기를 들면 `WeaponController.ApplyUpperBodyLayers()` 가 상체를 검 자세로 바꾼다.
  → 다리는 기존 달리기를 그대로 쓰므로, **검사가 총 든 자세로 뛰는 문제는 이미 해결되어 있다.**
- Kevin Iglesias 애니메이션 팩에 **근접 동작이 더 들어 있다** (프로젝트에 이미 있음).

| 파일 | 쓸 곳 |
|---|---|
| `HumanM@Attack1H01_R` · `CombatIdle1H01` | 검 (**지금 검이 쓰는 것**) |
| `HumanM@Attack2H01` · `CombatIdle2H01` · `WeaponHold2H01` | **대검** |
| `HumanM@AttackPolearm01` · `CombatIdlePolearm01` · `WeaponHoldPolearm01` | **창** |
| `HumanM@AttackShield01` | **패링** (7-8) — 방패로 밀쳐내는 동작이라 그대로 맞는다 |
| `HumanM@CombatDamage01` | 피격 모션 (검사 전용으로 쓸 만하다) |

**모션은 새로 구할 필요가 없다.** 연결만 하면 된다.

## 4. 구조 — 프리팹 하나 + 캐릭터 데이터

### 4-1. 왜 프리팹을 둘로 나누지 않는가

| | 프리팹 2개 (사수 · 검사) | **프리팹 1개 + `CharacterData`** |
|---|---|---|
| `GameAppManager` 수정 | **필요** (생성할 프리팹 선택) — 제약 위반 | 불필요 |
| 테스트 룸 | 프리팹을 따로 연결해야 한다 | **같은 프리팹이라 저절로 따라온다** |
| 공통 수정 | 두 프리팹을 **각각** 고쳐야 한다 | 한 번만 고친다 |
| 외형 차이 | 자유롭다 | 머티리얼 · 무기로 구분 (아래 4-5) |
| 3번째 캐릭터 | 프리팹 또 추가 | **`.asset` 하나** |

두 캐릭터는 **같은 몸에 다른 설정**이다. 모델 · 리그 · 이동 · 피격이 전부 같고,
달라지는 것은 스탯 · 무기 · 회피 종류뿐이다. 이걸 프리팹 두 벌로 관리하면 한쪽만 고치는 실수가 반드시 생긴다.

패링용 컴포넌트(`ParryController`)도 **프리팹에 늘 붙여 두고**, 사수일 때는 쓰지 않을 뿐이다.

### 4-2. 구성 요소

```
[로비]
  CharacterSelectUI ── 고른 캐릭터를 ──▶ CharacterSelection (씬을 넘어 유지)
                                                │
[Stage · TestRoom]                              ▼
  Player.prefab                           CharacterData (SO)
    └ CharacterLoadout ◀── 읽어서 적용 ────┤ 스탯 · 회피 종류 · 시작 무기 · 허용 무기 · 외형
         ├ PlayerStats  (체력 · 피해 감소)
         ├ PlayerMove   (속도 · 스태미나 · 회피 입력 분기)
         │    ├ 구르기 (사수)
         │    └▶ ParryController (검사)
         └ WeaponController (허용 무기 · 시작 무기)
```

| 파일 | 구분 | 하는 일 |
|---|---|---|
| `Player/Character/CharacterData.cs` | 신규 | 캐릭터 한 명의 설정 (SO) |
| `Player/Character/CharacterSelection.cs` | 신규 | 로비에서 고른 캐릭터를 씬 너머로 들고 간다 |
| `Player/Character/CharacterLoadout.cs` | 신규 | `Player.prefab` 에 붙어, 생성될 때 설정을 적용한다 |
| `Player/Character/CharacterSelectUI.cs` | 신규 | 로비의 캐릭터 선택 버튼 |
| `Player/Character/ParryController.cs` | 신규 | 패링 판정 · 밀쳐내기 · 쳐내기 · 무적 (7장) |
| `Player/WeaponController.cs` | 수정 | 허용 무기 규칙 · 캐릭터 시작 무기 |
| `Player/PlayerStats.cs` | 수정 | 받는 피해 배율 |
| `Player/PlayerMove.cs` | 수정 | 속도 · 스태미나 배율 · **회피 키를 구르기 / 패링으로 분기** |
| `Player/PlayerStatsUI.cs` | 수정 | 회피 아이콘 교체 (구르기 ↔ 방패) |
| `Player/MeleeWeapon.cs` | 수정 | 무기별 휘두르기 모션 (6-3) · 패링 중 휘두르기 멈춤 |

**전부 `Assets/Scripts/Player` 안이다.** 제약 밖 파일은 하나도 고치지 않는다.

### 4-3. `CharacterData` 필드 (초안)

```csharp
public enum DodgeType { Roll, Parry }

[CreateAssetMenu(menuName = "Character/Character Data")]
public class CharacterData : ScriptableObject
{
    [Header("Identity")]
    public string displayName;          // 사수 · 검사
    [TextArea] public string description;
    public Sprite portrait;

    [Header("Stats")]
    public int maxHp = 100;
    [Range(0.1f, 2f)] public float damageTakenMultiplier = 1f;
    public float moveSpeedMultiplier = 1f;
    public float maxStamina = 100f;

    [Header("Dodge")]
    public DodgeType dodge = DodgeType.Roll;   // 사수 = Roll, 검사 = Parry
    [Tooltip("HUD 회피 아이콘. 비우면 지금의 구르기 아이콘")]
    public Sprite dodgeIcon;                   // 검사 = shield-128

    [Header("Weapons")]
    [Tooltip("이 캐릭터가 로비에서 고를 수 있는 시작 무기")]
    public WeaponData[] startWeapons;

    [Tooltip("스테이지 보상 · 획득으로 얻을 수 있는 손 무기 종류")]
    public WeaponKind[] allowedHeldKinds;   // 사수 = Projectile, 검사 = Melee

    [Header("Look")]
    [Tooltip("몸 머티리얼. 비우면 프리팹 기본값")]
    public Material bodyMaterial;
}
```

패링의 세부 수치(범위 · 무적 · 쿨타임)는 `CharacterData` 가 아니라 **`ParryController` 의 직렬화 필드**에 둔다.
패링을 쓰는 캐릭터가 하나뿐이고, 테스트 룸에서 Play 중에 인스펙터로 바로 조정하기 편하다.

### 4-4. 무기 제한은 한 곳에서 — 보상이 저절로 따라온다

스테이지 보상의 `WeaponReward.CanOffer()` 는 이미 `WeaponController.CanAcquire()` 를 묻는다.

```
StageRewardPool.GetRandom
  └ WeaponReward.CanOffer(player)
       └ WeaponController.CanAcquire(weapon)   ← 여기에 캐릭터 규칙을 넣는다
```

**`CanAcquire` 한 곳에 "이 캐릭터가 쓸 수 있는 종류인가"를 추가하면**, 스테이지 보상 풀은
무기 7종 + 신규 근접 2종을 **전부 섞어 둔 채로** 캐릭터에 맞는 것만 카드로 나온다.

- 보상 코드(`Stage/Reward/*`) **수정 0줄** — 제약 밖이라 원래 못 고치는 곳이다
- 캐릭터를 하나 더 만들어도 **보상 쪽은 그대로다**
- 서브유닛(드론)은 `allowedHeldKinds` 와 별개로 두 캐릭터 모두 허용 — 손 무기 규칙만 거른다

> ⚠ **규칙은 `CanAcquire` 에만 넣고, `Acquire` 에는 넣지 말 것.**
>
> 테스트 룸 픽업은 `TestWeaponPickup` → `TestRoomManager.QueueSelection` →
> **`WeaponController.SelectHeldWeapon`** 경로를 쓰는데, 이 함수는 빈 슬롯이 있으면
> 내부에서 **`Acquire` 를 직접 부른다** (`CanAcquire` 는 거치지 않는다).
>
> | 규칙을 넣은 곳 | 스테이지 보상 | 테스트 룸 |
> |---|---|---|
> | `CanAcquire` (권장) | 캐릭터 무기만 나온다 ✅ | **모든 무기 시험 가능** ✅ |
> | `Acquire` | 캐릭터 무기만 나온다 | **검사로 총을 못 집는다** ❌ |
>
> 테스트 룸은 캐릭터와 무관하게 모든 무기를 시험하는 곳이므로, `Acquire` 에 넣으면 그 목적이 깨진다.

### 4-5. 외형 구분 — 추가 에셋 없이

`SciFiWarriorPBRHPPolyart` 팩에 **같은 모델의 머티리얼이 3종** 있다.

| 머티리얼 | 쓸 곳 |
|---|---|
| `HP.mat` | 사수 — **지금 쓰는 것** |
| `PBR.mat` | 검사 후보 |
| `Polyart.mat` | 검사 후보 (색이 더 선명하다) |

`CharacterData.bodyMaterial` 로 바꿔 끼우면 **새 모델 없이** 한눈에 구분된다.
손에 든 무기(총 vs 검)가 이미 실루엣을 가르므로, 머티리얼만으로도 충분하다고 본다.

> **개정 2026-09-26** — 검사도 사수와 **같은 모습**(`HP.mat`)으로 바꿨다 (`CH_Swordsman.bodyMaterial` 비움).
> 몸 머티리얼을 바꾸는 기능(`CharacterLoadout`)은 그대로 남아 있어, 나중에 다시 구분하고 싶으면 칸만 채우면 된다.

### 4-6. 선택 저장 — `GameAppManager` 를 고치지 않고

로비에서 고른 캐릭터는 스테이지 씬까지 살아 있어야 한다.
`GameAppManager` 가 무기 선택(`SelectedWeapon`)을 그렇게 들고 가지만, Core 라 고칠 수 없다.

→ **`CharacterSelection` 이라는 작은 정적 보관소**를 새로 둔다.

```csharp
public static class CharacterSelection
{
    public static CharacterData Current { get; private set; }
    public static void Select(CharacterData data) => Current = data;
}
```

- 정적 필드라 씬을 넘어 유지된다
- `Current` 가 비어 있으면(스테이지 씬을 에디터에서 바로 Play) **사수로 떨어진다** —
  지금 `WeaponController` 가 시작 무기를 `starterWeapon` 으로 떨어뜨리는 것과 같은 규칙이다

> ⚠ 이 프로젝트는 `Enter Play Mode Options` 가 켜져 있다. 지금은 도메인 리로드가 살아 있어
> 정적 필드가 Play 마다 초기화되지만, 나중에 끄면 **이전 Play 의 선택이 남는다.**
> `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]` 로
> 초기화해 두면 설정과 무관하게 안전하다.

### 4-7. 적용 순서 주의

`CharacterLoadout` 은 **다른 컴포넌트보다 먼저** 적용돼야 한다.

- `PlayerStats.Awake` 가 `currentHp = maxHp` 를 한다 → 그 전에 `maxHp` 가 바뀌어 있어야 한다
- `WeaponController.Start` 가 시작 무기를 장착한다 → 그 전에 허용 규칙 · 시작 무기가 정해져 있어야 한다
- `PlayerMove` 가 회피 입력을 받기 전에 회피 종류가 정해져 있어야 한다

같은 오브젝트의 `Awake` 순서는 보장되지 않으므로 `[DefaultExecutionOrder(-100)]` 을 붙이거나,
`CharacterLoadout` 이 `maxHp` 와 `currentHp` 를 **둘 다** 설정하게 한다.

**시작 무기를 정하는 입구는 이미 있다.** 테스트 룸 작업 때 `WeaponController` 에
`ConfigureStartingWeapon(WeaponData)` 가 추가되었다 — `Start` 전에 부르면 시작 무기를 바꾼다.

- 로비를 거친 경우: 로비가 이미 **그 캐릭터의 무기 중에서** 고르므로 `SelectedWeapon` 이 맞다. 할 일 없음
- 스테이지를 에디터에서 바로 Play 한 경우: `CharacterLoadout.Awake` 가
  `ConfigureStartingWeapon(캐릭터의 첫 시작 무기)` 를 부른다 → 검사인데 소총을 드는 일이 없다

### 5-3. `LobyManager` 를 고치지 않는 방법

`LobyManager.selectableWeapons` 는 **직렬화 배열**이다. 코드를 고치지 않고:

1. 에디터 도구(`CharacterSetup` 10번)가 `selectableWeapons` 에 **9종**(사수 6 → 검사 3 순서)을 넣는다 — 씬 데이터 수정
2. 버튼은 예전처럼 `LobyManager.SelectWeapon(i)` 를 부른다. 강조 표시도 기존 `LobyWeaponSelectUI` 를 그대로 쓴다
3. 새 `CharacterSelectUI` 가 `OnSelectionChanged` 를 듣고, 고른 무기가 속한 캐릭터를 `CharacterSelection` 에 맡긴다

`LobyManager.Start` 는 0번(소총)을 기본 선택하므로, **기본 캐릭터는 사수**다.
캐릭터를 안 골라도 지금과 똑같이 시작된다. 스테이지에서 로비로 돌아오면 직전에 고른 무기(= 캐릭터)를 다시 골라 둔다.

## 6. 검사 — 근접 캐릭터의 무기

### 6-1. 무기 3종 — 검 · 대검 · 창

지금 근접 무기는 **검 1종**이다. **대검 · 창 2종**을 더해 3종으로 만든다.

| 무기 | 성격 | 모션 | 새 코드 | 모델 |
|---|---|---|---|---|
| **검** | 균형 (현재) | 1H | 없음 | Futura `Sword_A_Orange` 2.3m ✅ |
| **대검** | 느리고 넓게 · 한 방이 크다 | **2H** | 모션 연결만 | Futura `Sword_A_Red` 3.5m ✅ |
| **창** | 가장 멀리 · 판정은 좁다 | **Polearm** | 모션 연결만 | Futura `Halberd_Blue` 5.0m ✅ |

> 길이는 15 · 16장에서 사거리에 맞춰 늘렸다 (처음: 검 1.2 · 대검 1.8 · 창 2.2m).

세 무기는 **판정 모양부터 다르다** — 검은 중간, 대검은 넓은 부채꼴, 창은 가늘고 긴 부채꼴.
개수는 사수(6종)보다 적지만 고르는 의미는 분명하다.

- 로비: 3종 중 하나로 시작
- 스테이지 보상: 나머지 2종이 무기 카드로 나올 수 있다
- 선택 폭이 부족하게 느껴지면 **단검**을 나중에 붙인다 — 1H 모션 · `Knife_01` 모델이 이미 있어 **데이터만으로** 추가된다

`MeleeWeaponData` 에 `range` · `arcAngle` · `maxTargets` · `hitDelay` 가 이미 있어서,
**성격 차이는 전부 숫자로 만든다.** 새 판정 코드가 필요 없다.

### 6-2. 수치 초안

| 무기 | damage | 간격 | 사거리 | 각도 (가로 / 세로) | 최대 타격 | 치명 | 단일 DPS |
|---|---|---|---|---|---|---|---|
| 검 (현재) | 6 | 0.70 | 3.0 | 120° / 60° | 5 | 0.10 / 2.0 | **9.43** |
| 대검 | 16 | 1.40 | **4.0** | 160° / 70° | 8 | 0.10 / 2.0 | **12.6** |
| 창 | 9 | 0.90 | 5.0 | 40° (찌르기) / 50° | 4 | 0.10 / 2.0 | **11.0** |

> 15 · 16장에서 바뀐 값: 대검 사거리 3.6 → 4.0. 창은 15장에서 가로 90° 로 넓혔다가 16장에서 두 손 찌르기로 바꾸며 40° 로 돌렸다.
> 내려찍기 각도는 모든 무기에 새로 생겼다 (15-3 · 16-2).

`단일 DPS = damage × (1 + 치명확률 × (배율 − 1)) ÷ 간격`

> **근접 기준선은 원거리보다 높게 잡는다 (9 ~ 13).**
> 원거리 기준선은 5.5 ~ 9 였다 ([주무기-확장-후보.md](주무기-확장-후보.md) 9장).
> 근접은 **맞으면서 싸우는 위험**을 지므로 그만큼 화력으로 보상해야 한다.

### 6-3. 모션을 무기별로 — `Slash` 하나로는 부족하다

지금 `MeleeWeapon` 은 `Slash` 트리거 하나로 모든 근접 무기를 휘두른다.
대검과 창이 한손검처럼 휘둘러지면 무기 차이가 눈에 안 보인다.

**구현: `MeleeLayer` 안에 모션을 나란히 두고 `MeleeStyle`(Int) 파라미터로 고른다.**

| MeleeStyle | 무기 | 대기 | 휘두르기 (속도) | Hit Delay |
|---|---|---|---|---|
| 0 | 검 | `MeleeIdle` (`CombatIdle1H01`) | `Slash` (`Attack1H01_R`) — 기존 | 0.16초 — 기존 |
| 1 | 대검 | `MeleeIdle2H` (`CombatIdle2H01`) | `Slash2H` (`Attack2H01` ×1.27) | **0.43초** |
| 2 | 창 | `MeleeIdlePolearm` (`CombatIdlePolearm01`) | `SlashPolearm` (`AttackPolearm01` ×1.69) | **0.23초** |

- 휘두르기: Any State → `Slash_스타일` (Slash 트리거 + MeleeStyle 같음). 대기끼리는 MeleeStyle 이 바뀌면 서로 넘어간다
- 휘두르기 속도는 **공격 간격의 90% 안에 끝나게**, Hit Delay 는 **오른손이 가장 빠른 순간**으로 도구가 계산해 넣었다
- **스타일은 무기 프리팹의 `MeleeWeapon.swingStyle` 에 둔다.** 손에 들 때 · 휘두를 때 애니메이터에 넣는다

> **설계와 달라진 점** — 처음에는 무기마다 `AnimatorOverrideController` + 새 SO `MeleeStyleTable` 을 두려 했다.
> 그런데 컨트롤러를 교체하면 **애니메이터 파라미터가 초기화**된다. `isMove` 는 이동 입력이 바뀔 때만 다시 쓰므로,
> 무기를 바꾼 순간 캐릭터가 달리면서 멈춘 자세로 미끄러진다.
> 한 컨트롤러 안에서 파라미터로 고르면 이 문제가 없고, 표(SO)도 필요 없다 —
> 무기마다 프리팹이 따로 있으니 **프리팹에 한 칸**이면 충분하다. 무기 데이터(Data 폴더)는 건드리지 않았다.

> **개정 2026-09-26** — 위 표의 휘두르기(검 · 창은 찌르기)는 **가로베기 · 세로베기 두 모션**으로 바뀌었다. **15-3** 참고.

### 6-4. 생존 — 맞는 것을 전제로

| 수단 | 구현 위치 | 비고 |
|---|---|---|
| 체력 140 | `PlayerStats.maxHp` | `CharacterLoadout` 이 설정 |
| 받는 피해 ×0.85 | `PlayerStats.TakeDamage` | 한 줄 곱셈. Player 폴더라 수정 가능 |
| **패링** | `ParryController` (신규) | 구르기 대신. **7장** |
| 이동 ×1.1 | `PlayerMove.AddSpeedModifier` | **이미 배율 목록 구조가 있다** — 곱하기 하나 추가 |

**지금 구조가 거의 다 받아 준다.** 특히 이동 속도는 `speedModifiers` 목록이 이미 있어
캐릭터 배율을 하나 넣기만 하면 슬로우 · 업그레이드와 자연스럽게 겹친다.

### 6-5. 공격이 나가는 조건

검은 `HasTargetInReach` 로 **사거리 + 부채꼴 안에 적이 있을 때만** 휘두른다.
감지 범위(10m)보다 사거리(3m)가 훨씬 짧으므로, 검사는 **스스로 다가가야** 공격이 나간다.

이게 곧 검사의 플레이다. 따로 손댈 것은 없지만, **창(5m)** 처럼 사거리가 긴 무기는
부채꼴이 좁아 조준이 중요해진다 — 마우스 방향이 곧 창끝 방향이다.

> 인식 범위(휘두르기 시작하는 거리)는 **사거리 + 0.5m**(적 몸통 반지름)다. 부채꼴은 가로 · 세로 중 넓은 쪽을 쓴다 (15-2).

## 7. 검사의 회피 — 패링

검사는 구르기 대신 **패링**을 쓴다. 같은 키(지금의 구르기 키)를 누른다.

> 회피 키를 누르면 **주변 또는 커서 방향 일정 범위** 안의 **적을 밀쳐내고**, **적 투사체를 쳐낸 뒤**
> 잠깐 **무적**이 된다. 쿨타임은 **구르기보다 길다.**

### 7-1. 구르기와 비교

| | 구르기 (사수) | **패링 (검사)** |
|---|---|---|
| 성격 | 자리를 **벗어난다** (이탈) | 자리를 **지킨다** (밀어내고 다시 벤다) |
| 이동 | 4m 굴러간다 | 제자리 — 걷기는 그대로 |
| 무적 | 1.5초 | **0.6초** (성공했을 때만) |
| 적에게 | 영향 없음 | **밀쳐내기 3m + 경직 1초** |
| 적 투사체 | 피한다 | **쳐낸다** — 그 투사체가 날아오던 방향의 정반대로 튕겨 나가 적을 맞힌다 (17-2) |
| 조건 | 언제나 발동 | 범위 안에 적 · 투사체가 **있어야** 성공 |
| 쿨타임 | 전체 **4.0초** | **5.0초** — 성공해도 헛쳐도 같다 |

패링은 무적이 짧은 대신 **주변을 정리해 준다.** 구르기보다 한 번의 가치가 크므로 쿨타임이 더 길다.
헛쳐도 5초가 묶이므로 **아무 때나 누를 수 없고, 언제 쓸지 판단해야 한다.**

### 7-2. 흐름

```
[회피 키] ─▶ 방어 자세 (판정 창 0.2초)
               │  창 안에서 매 프레임 검사: 주변 원 ∪ 커서 부채꼴
               │
               ├─ 적 또는 적 투사체가 걸림 ─▶ ✅ 성공 (그 순간 범위 안의 것 전부 처리)
               │     · 적       → 밀쳐내기 + 경직 (7-5)
               │     · 투사체   → 쳐내기 (7-6)
               │     · 플레이어 → 무적 0.6초 (7-7)
               │     · 쿨타임 5.0초
               │
               └─ 0.2초 동안 아무것도 없음 ─▶ ❌ 헛침
                     · 무적 없음
                     · 쿨타임 5.0초 (성공과 같다)
```

**누른 순간만 검사하지 않고 0.2초 창을 두는 이유** — 투사체가 한 프레임 늦게 범위에 들어와도
놓치지 않게 하기 위해서다. 조금 일찍 눌러도 성공하므로 손맛이 덜 까다롭다.
헛침의 대가가 5초로 크기 때문에, 이 여유가 없으면 억울한 헛침이 생긴다.

**헛침은 분명히 알려 줘야 한다.** 5초가 묶였는데 왜 그런지 모르면 버그로 느낀다.
헛침 전용 소리 + HUD 아이콘을 잠깐 붉게 깜빡이는 정도로 "헛쳤다"를 보여 준다 (7-8).

### 7-3. 수치 초안

| 항목 | 값 | 비고 |
|---|---|---|
| 판정 창 | 0.2초 | 위 7-2 |
| 주변 원 | 반경 **2.0m**, 360° | 등 뒤 · 옆 포함. 둘러싸였을 때 빠져나오는 용도 |
| 커서 부채꼴 | 반경 **5.0m**, **70°** | 날아오는 투사체를 미리 쳐낸다. 창 사거리(5m)와 맞춤 |
| 밀쳐내기 거리 | 3.0m (0.15초에 나눠 민다) | 한 번에 옮기면 순간이동처럼 보인다 |
| 경직 | 1.0초 | 기존 적 `Hit` 상태 길이 그대로 (`EnemyBrain.hitDelay`) |
| 무적 | 0.6초 | 구르기(1.5초)보다 짧다 — 대신 적을 밀어낸다 |
| 쿨타임 | **5.0초** (성공 · 헛침 모두) | 구르기 전체 4.0초보다 길게. 헛쳐도 같아서 연타가 통하지 않는다 |
| 반사탄 피해 | 들고 있는 근접 무기 `Damage` × 1.5 | 적 투사체의 피해 값은 private 라 읽을 수 없다 (7-6) |

### 7-4. 판정 범위 — 주변 원 ∪ 커서 부채꼴

```
                커서 방향
                   ▲
          \        │        /
           \       │       /     ← 커서 부채꼴 5.0m · 70°
            \      │      /
             \   ╭───╮   /
              \ │ 나  │ /      ← 주변 원 2.0m · 360°
                 ╰───╯
```

**둘 중 하나에만 들어도** 대상이다.

```
대상 = (거리 ≤ 2.0m) 또는 (거리 ≤ 5.0m 그리고 커서 방향과의 각도 ≤ 35°)
```

- **커서 방향** = 플레이어 정면(`transform.forward`). 근접 무기 판정(`MeleeWeapon`)과 같은 기준이다
- **적 찾기** — `Physics.OverlapSphere(5.0m)` 뒤 위 조건으로 거른다. `MeleeWeapon` 의 판정 방식 · 레이어를 그대로 쓴다
- **적 투사체 찾기** — 적 투사체(`RangedProjectile`)는 **콜라이더가 없다** (SphereCast 로 스스로 움직인다).
  그래서 `OverlapSphere` 에 잡히지 않는다.
  → `FindObjectsByType<RangedProjectile>(FindObjectsSortMode.None)` 으로 **활성 투사체만** 모아 같은 조건으로 거른다.
  풀에 들어간 비활성 투사체는 기본값으로 빠진다. 판정 창 0.2초 동안만 부르므로 비용은 문제없다.

> 투사체 목록을 따로 관리하면 더 싸지만, 그러려면 `RangedProjectile`(Enemy 폴더)을 고쳐야 한다 — 제약 밖.

### 7-5. 적 밀쳐내기

**어떻게 미는가** — 적은 `NavMeshAgent` 로 움직인다(`NavMeshMovement`).
Rigidbody 에 힘을 주면 에이전트가 위치를 다시 덮어쓰므로 **`NavMeshAgent.Move(offset)`** 로 민다.
내비메시 위에서만 움직이므로 **벽 너머로 밀려나지 않는다.**

**경직을 같이 건다** — `enemy.ChangeState(EnemyState.Hit)` (public).
치명타를 맞았을 때 적이 이미 쓰는 경로와 같다: 이동 정지 → `Hit` 모션 → 1초 뒤 추격 복귀.

```
① enemy.ChangeState(EnemyState.Hit)   ← 이동이 멈춘다 (movement.Stop)
② 0.15초 동안 agent.Move(바깥 방향 × 거리 / 프레임)
③ 1초 뒤 적이 알아서 Chase 로 돌아간다
```

순서가 중요하다. 먼저 멈추지 않으면 추격 경로가 밀린 만큼 다시 끌어당긴다.

**경직이 꼭 필요한 이유 — 근접 적의 공격이 끊겨야 한다**

| 적 공격 | 피해가 들어가는 방식 | `ChangeState(Hit)` 효과 |
|---|---|---|
| 원거리 (`RangedAttack`) | 조준 후 발사 | `CancelAttack` 이 조준을 취소하고 쿨타임을 다시 잰다 ✅ |
| 돌진 (`DashAttack`) | 돌진 중 접촉 | `CancelAttack` 이 돌진을 멈춘다 ✅ |
| 근접 (`MeleeAttack`) | 애니메이션 이벤트 `PerformAttack` — **거리 검사 없음** | `CancelAttack` 재정의가 **없다.** 대신 `Hit` 모션이 공격 모션을 끊어 이벤트가 안 나온다 |

근접 적은 **밀어내기만 하면 3m 밖에서도** 휘두르던 모션이 끝나며 피해가 들어온다.
그래서 밀쳐내기와 경직은 **한 묶음**이다.

**밀지 않거나 경직을 걸지 않는 대상**

| 대상 | 처리 | 이유 |
|---|---|---|
| 죽은 적 (`state == Dead`) | 건너뛴다 | |
| 자폭 적 (`SuicideAttack`) | **밀기만**, 경직 없음 | `Enemy.TakeDamage` 도 이 적에게는 `Hit` 을 걸지 않는다 — 같은 규칙을 따른다. 폭발은 무적 0.6초가 받는다 |
| 보스 | 밀지 않는다 | `Enemy` 가 아니라 `BossHealth` 계열이라 `ChangeState` 가 없다. 보스 앞에서는 **무적만** 적용 |

밀기 코루틴은 **플레이어 쪽(`ParryController`)** 에서 돌린다. 밀리는 도중 적이 죽어 풀로 돌아가면
`activeInHierarchy` 로 확인하고 멈춘다.

### 7-6. 적 투사체 쳐내기

> ⚠ **17-2 에서 바뀌었다** — 반사탄(플레이어 탄)으로 바꾸지 않고, 몬스터가 쏜 투사체가 모양 그대로 반대 방향으로 날아간다.

`RangedProjectile` 에는 **방향을 바꾸는 public 함수가 없다** (방향 · 피해 · `ReturnToPool` 모두 private).
그래서 "방향을 바꾼다" 대신 **"적 투사체를 지우고, 그 자리에서 플레이어 탄을 쏜다"** 로 만든다.

```
① PoolManager.Instance.Return(투사체)   ← 풀이 OnDespawn 을 불러 비행 · 트레일을 정리한다
                                           투사체가 스스로 돌아갈 때와 같은 경로라 안전하다
② 같은 위치에서 반사탄(Bullet_Deflect) 발사   ← 플레이어 Bullet 이라 적에게 피해를 준다
```

| 항목 | 결정 |
|---|---|
| 방향 | **쏜 방향 그대로 되돌린다** (`-transform.forward` — 투사체는 진행 방향을 바라보게 회전되어 있다). 조준 없이 쏜 적에게 돌아간다 |
| 피해 | 근접 무기 `Damage` × 1.5 — 원래 투사체의 피해 값은 읽을 수 없다 |
| 모양 | 신규 프리팹 `Bullet_Deflect` — 적 투사체와 같은 모양, 플레이어 탄 색 |
| **보스 투사체** | **쳐내지 않는다** — 아래 |

> ⚠ **보스 투사체(`BossProjectile`)는 제외한다.**
> 포물선으로 떨어지고, 바닥의 경고 표시는 폭발할 때 **static 이벤트 `OnExplosion`** 으로 지워진다.
> 이 이벤트는 밖에서 부를 수 없으므로, 중간에 지우면 **경고 표시가 바닥에 계속 남는다.**
> 보스 투사체는 무적으로만 버틴다.

### 7-7. 무적

- `PlayerStats.SetInvulnerable(0.6f)` — **구르기가 쓰는 것과 같은 함수**다. 새 코드가 없다
- 이미 더 긴 무적이 걸려 있으면 그쪽을 유지한다(`Max`) → 겹쳐도 안전
- **성공했을 때만** 준다. 헛치면 무적도 없다 → "아무 때나 눌러 무적"을 막는다
- 무적 중 적 투사체에 맞으면 피해 없이 투사체만 사라진다 (지금 구르기 무적과 같은 동작)
- 사망 시 `PlayerMove.StopPlayer` 가 `ClearInvulnerable` 로 정리한다 — 그대로 둔다

## 9. 밸런스 — 캐릭터 분리가 오래된 문제를 풀어 준다

[주무기-확장-후보.md](주무기-확장-후보.md) 9장에서 **"검이 과하다"** 고 적었다.
단일 대상 DPS 9.43 으로 총 6종보다 높고, 5명 기준으로는 47 이었다.

이건 **사수가 검을 고를 수 있어서** 생긴 문제였다. 캐릭터를 나누면:

- 검은 **검사만** 쓴다 → 근접 기준선(9 ~ 13) 안이라 **적정**이다
- 사수는 총 6종 안에서만 고른다 → 원거리 기준선(5.5 ~ 9) 안에서 비교된다

**수치를 하나도 바꾸지 않고 문제가 사라진다.** 기준선이 캐릭터별로 나뉘기 때문이다.

패링의 반사탄 피해(무기 `Damage` × 1.5)는 무기 DPS 에 더해지는 **덤**이다.
5초에 한 번이라 기준선을 흔들 정도는 아니지만, 원거리 적이 많은 스테이지에서 실측해 본다.

### 10-2. 가져오는 법 — 지금 검과 같은 절차

Futura 모델을 가져올 때의 주의점은 검을 넣을 때 이미 확인했다.

| 항목 | 방법 |
|---|---|
| 파일 위치 · 이름 | `Assets/FuturaWeapons/Models/` 에 `Halberd_Blue.fbx` · `Sword_A_Red.fbx` — 지금 `Sword_A_Orange.fbx` 와 같은 규칙 |
| 재질 | 파일마다 재질 이름이 제각각(`Solid` · `Transparent` · `phong2` 등)이다 → 이름과 상관없이 **전부 `FuturaPalette.mat` 으로 remap**. 안 하면 하얗게 보인다 (FBX 의 텍스처 경로가 제작자 PC 경로다) |
| 텍스처 | 이미 들어와 있다 (`FuturaPalette.png` — Point 필터 · 무압축 · 밉맵 끔). 할 일 없음 |

|---|---|---|---|---|
| 검 A → 검 (지금) | 29.7cm · 칼날 +X | 1.2m | ×4.05 | Y 90° · 위로 +0.258 (`WeaponAssetSetup` 메뉴 8 에서 적용됨) |
| 검 A → **대검** | 29.7cm · 칼날 +X | 1.8m | ×6.1 | 검과 같은 회전. 오프셋도 ×1.5 |
| 할버드 → **창** | 20.3cm · Y축으로 섬 | 2.2m | ×10.8 | **원점이 자루 한가운데**다 → 손이 잡는 위치(자루 아래 ⅓)로 옮긴다. 창끝이 앞을 보도록 눕힌다 |

- 창 길이 2.2m 는 판정 사거리(5m)보다 짧다. 판정은 숫자로 따로 가므로 괜찮다 — 검도 1.2m 모델에 사거리 3m 다

  모션을 연결한 뒤(6-3) 테스트 룸에서 보면서 손 소켓 위치를 맞춘다

## 14. 구현 결과

### 14-1. 실행 방법

에셋 · 씬 구성은 전부 **`Tools / Character Setup / 전체 실행`** 한 번으로 된다 (여러 번 실행해도 결과가 같다).
배치 모드: `-executeMethod CharacterSetup.RunAllBatch`

| 번호 | 하는 일 |
|---|---|
| 1~5 | 근접 무기 3종 모델 임포트 → 프리팹(길이 · 칼끝) → 무기 데이터 → 애니메이터(가로 · 세로) → 대검 · 창 아이콘 |
| 6~7 | 캐릭터 데이터 → `Player.prefab` 에 `CharacterLoadout` · `ParryController` |
| 8 | 스테이지 보상 풀에 대검 · 창 |
| 9 | 테스트 룸 — 픽업 9개를 **원거리(위 6) · 근거리(아래 3)** 로 묶어 배치 |
| 10 | 로비 — 5-2 배치 |

### 14-2. 검증

| 검증 | 결과 |
|---|---|
| 테스트 룸 통합 검증 (`TestRoomValidation`) | **전부 통과** — 대검 · 창 픽업 장착, 실제 공격이 표적에 맞음, 로비 왕복, 일반 게임 시작 |
| 검사 스모크 테스트 (임시, 실행 후 삭제) | **38개 전부 통과** — 아래 |

- 로비: 대검을 누르면 검사, 소총을 누르면 사수, 검사 제목을 누르면 검
- 테스트 룸 검사: 체력 140 · 받는 피해 ×0.85 · 스태미나 120 · 이동 ×1.1 · 몸 `Polyart` · HUD 방패 아이콘
- 테스트 룸이 소총을 쥐여 줘도 검사는 **검으로 시작**, 소총은 보상 후보에서 빠지고 창은 들어온다
- 창 = `MeleeStyle` 2, 대검 = 1
- 정면 3.5m 적 투사체 → 패링 **성공**, 투사체 제거, 반사탄 발사, 무적(피해 무시), HUD 쿨타임 5초, 연타 불가
- 5초 뒤 빈 곳에서 패링 → **헛침**, 무적 없음, 쿨타임 다시 5초
- 무적이 끝난 뒤 피해 10 → 8 (×0.85)

### 14-3. 제약 밖 파일 — 검증 도구 두 줄

대검 · 창을 테스트 룸에 넣으면 기존 검증 도구가 **예전 가정 때문에** 실패해서, 가정만 일반화했다.

| 파일 | 예전 | 바꾼 것 |
|---|---|---|
| `TestRoomSetup.ValidateSavedScene` | 픽업이 **7개**여야 통과 | 픽업 수 = `TestRoomManager` 무기 수 |
| `TestRoomValidation` 공격 확인 | **3번(검)만** 표적 가까이(11.6) | **근접 무기 전부** 가까이 — 대검 사거리 3.6 이라 10 에서는 닿지 않는다 |

### 14-4. 남은 확인 — 실제 스테이지에서

테스트 룸에는 적 AI 가 없어 아래는 **자동으로 확인하지 못했다.** 스테이지에서 검사로 한 판 해 볼 것.

## 15. 근접 무기 사거리 · 크기 · 가로/세로 베기

> ⚠ **이 장의 모션(15-3 세로베기 · 대검 가로베기 · 창 가로베기)과 무기 길이는 16장에서 바뀌었다.**
> 사거리 · 인식 범위 · 바닥 보정 · 무작위 선택 규칙은 그대로다.

> 2026-09-26 요청: "근접 캐릭터도 원거리 캐릭터와 같은 모델로, 사거리는 검 3 · 대검 4 · 창 5m,
> 사거리에 맞게 적 인식 범위와 무기 크기도, 단순 찌르기 대신 가로베기 · 세로베기가 무작위로."

### 15-1. 한눈에

| 항목 | 전 | 후 |
|---|---|---|
| 검사 외형 | `Polyart.mat` | **사수와 같은 `HP.mat`** (`CH_Swordsman.bodyMaterial` 비움) |
| 사거리 | 검 3 · 대검 3.6 · 창 5 | **검 3 · 대검 4 · 창 5** |
| 무기 길이 | 검 1.2 · 대검 1.8 · 창 2.2m | **검 2.1 · 대검 3.1 · 창 4.8m** |
| 모션 | 검 · 창 = 찌르기, 대검 = 사선 내려베기 | **휘두를 때마다 가로베기 · 세로베기 무작위** |
| 판정 각도 | 무기당 하나 | 가로(무기 데이터 `arcAngle`) · 세로(프리팹 `verticalArcAngle`) 따로 |

### 15-2. 사거리 · 인식 범위 · 무기 크기

- **인식 범위** = 휘두르기 시작하는 거리. `MeleeWeapon.HasTargetInReach` 가 **사거리 + 0.5m**(적 몸통 반지름) 안,
  정면 부채꼴(가로 · 세로 중 넓은 쪽) 안에 적이 있을 때만 휘두른다. 사거리 값 하나로 인식 · 판정이 같이 움직인다.
- `EnemyDetector`(10m)는 건드리지 않았다. 드론(공용)과 사수 총이 같이 쓰고, 근접은 위 확인이 거른다.
- **무기 길이** = 휘둘렀을 때 칼끝이 사거리 끝 근처에 닿도록.
  `길이 = (사거리 − 0.3 − 손이 몸에서 떨어진 거리 약 0.8m) ÷ 쥔 점부터 끝까지 비율(검 0.9 · 창 0.8)`.
  창은 자루 끝에서 20% 지점을 쥔다(예전 30%).

**모션을 플레이어에 직접 샘플링해 잰 칼끝 거리** (몸 중심에서 수평 거리):

| 무기 | 사거리 | 가로베기 최대 | 세로베기 최대 |
|---|---|---|---|
| 검 2.1m | 3 | 2.72m | 2.71m |
| 대검 3.1m | 4 | 3.94m | 3.55m |
| 창 4.8m | 5 | 4.84m | 4.84m |

판정은 적 콜라이더 표면까지 재므로(`OverlapSphere`), 칼끝보다 적 몸통 반지름(0.4 ~ 0.5m)만큼 더 나간다 — 눈에 보이는 칼끝과 거의 맞는다.

### 15-3. 가로베기 · 세로베기

`MeleeWeapon` 이 휘두를 때마다 방향을 고르고 애니메이터 `SlashVariant`(Int) 에 넣는다.

- 확률 50 : 50 (`verticalChance`). **같은 방향이 3번 연속 나오지 않게** 2번 이어지면 반대로 바꾼다
- 세로베기는 폭이 좁다 — 좁은 부채꼴 안에 적이 없으면 허공을 치지 않게 **가로베기로 바꾼다**
- 판정: 가로 = 무기 데이터 `arcAngle` · `hitDelay`, 세로 = 프리팹 `verticalArcAngle` · `verticalHitDelay`
  (무기 데이터 스크립트는 Data 폴더라 고치지 않았다 — 협업 제약)
- 애니메이터에 `SlashVariant` 가 없으면 예전처럼 항상 가로베기다

| MeleeStyle | 가로베기 상태 · 클립 | 세로베기 상태 · 클립 |
|---|---|---|
| 0 검 | `Slash` — Kevin `AttackShield01` ×1.43, 타격 0.24초 | `SlashV` — UAL 내려찍기 ×1.0, 0.39초 |
| 1 대검 | `Slash2H` — Kevin `Attack2H01` ×1.27, 0.44초 (양손 사선) | `SlashV2H` — UAL 내려찍기 ×1.0, 0.39초 |
| 2 창 | `SlashPolearm` — Kevin `AttackShield01` ×1.11, 0.31초 | `SlashVPolearm` — UAL 내려찍기 ×1.0, 0.39초 |

**클립 고르는 법** — 원본 FBX 를 직접 읽어 칼 방향 뼈(Kevin `B-handProp.R`, Quaternius 검지 − 새끼 뿌리)로 칼끝 궤적을 쟀다.

| 클립 | 칼끝 궤적 | 판정 |
|---|---|---|
| Kevin `Attack1H01_R` · `AttackPolearm01` (예전 검 · 창) | 뒤로 뺐다가 정면으로 곧게 뻗음 | **찌르기** — 뺐다 |
| Kevin `AttackShield01` (패링에도 씀) | 오른쪽 뒤 → 정면, 높이 변화 40cm 이내 | **가로베기** |
| Kevin `Attack2H01` | 양손으로 오른쪽 위 → 왼쪽 아래 | 사선 — 대검 가로베기 |
| Quaternius UAL2 `Sword_Heavy_Combo` 마지막 타 | 머리 위 → 몸 중심선 → 바닥, 좌우 흔들림 10cm 이내 | **세로베기** |
| UAL2 `Sword_Regular_C` · Heavy 앞의 두 타 | 몸이 한 바퀴 돈다 | 다리는 달리기 레이어라 어색해 뺐다 |

Kevin 무료 팩은 이미 들어 있는 것이 전부라(itch 의 무료판도 같은 5개), 세로베기는
**Quaternius Universal Animation Library 2 — Standard (CC0, 무료)** 에서 가져왔다.

- 43개 모션이 든 FBX 하나(24MB)다. 도구가 **내려찍기 한 구간(30fps 67~82프레임)만** Humanoid 클립으로 잘라 가져온다
- 원본은 바닥을 찍은 뒤 0.6초 멈춰 있어서, 긴 무기가 그동안 바닥에 묻혔다 → 바닥에 닿은 직후에서 잘랐다
- 플레이어에 옮기면 몸이 비틀려 정면보다 20 ~ 25° 왼쪽으로 내려찍힌다 → 세로 판정 폭을 50° 이상으로 잡았다

### 15-4. 칼끝 바닥 보정

무기가 길어져서 낮게 쓸거나 내려찍을 때 칼끝이 바닥 아래로 들어간다(창은 최대 2.5m).
`MeleeWeapon.LateUpdate` 가 애니메이션 뒤에 **쥔 점을 축으로 칼을 들어 올려 칼끝을 발 높이 + 5cm 위에 둔다** — 바닥을 긁는 모양이 된다.
칼끝 위치(`bladeTip`)는 도구가 모델에서 재서 프리팹에 넣는다. 판정과는 상관없다(보이는 것만).

## 16. 근접 모션 개정 — 하체 고정 · 두 손

> 2026-09-26 요청: "위에서 아래로 내려칠 때 몸이 뒤틀려 공중에 뜨는 게 어색하다 — 하체와 코어는 지면에 붙인 채
> 두 팔을 들어 내리치게. 창은 한 손으로 단검처럼 찌르지 말고 두 손으로 잡고 푹 찌르게."

### 16-1. 원인 — 상체 레이어가 골반까지 덮어쓴다

테스트 룸에서 실제로 휘두르게 하고 시간대별로 찍어 쟀다 (플레이 모드, 레이어가 섞인 결과).

| 세로베기 (서 있을 때) | 15장 (Quaternius 내려찍기) | 16장 (KayKit 양손 내려찍기) |
|---|---|---|
| 골반 높이 | 0.75 ~ 1.05m (30cm 오르내림) | 0.96 ~ 1.02m |
| 골반 회전 | 약 120° | 약 15° |
| 발(발목 뼈) 높이 | **최대 0.67m — 공중에 뜸** | 0.08 ~ 0.15m (서 있는 높이) |

- 근접 레이어의 마스크(`Upper.mask`)는 **Body(골반 · 척추)를 포함**한다. 다리는 달리기 레이어가 맡지만 골반에 붙어 있어서,
  골반이 돌고 오르내리면 **다리째 따라 돌고 들린다** → 몸이 비틀리며 떠 보인다
- 15장 내려찍기(Quaternius `Sword_Heavy_Combo`)는 골반을 크게 돌리고 낮췄다 올리는 한손 콤보 모션이었다.
  대검 가로베기(Kevin `Attack2H01`)도 머리 위에서 내리치며 골반이 18cm 내려가고 115° 돌았다
- 마스크에서 Body 를 빼면 척추도 같이 빠져 휘두르는 힘이 사라진다 (Humanoid 마스크는 골반 · 척추를 따로 못 나눈다)
  → **골반이 거의 안 움직이는 모션으로 바꾸는 것**이 맞다

### 16-2. 해결 — KayKit 양손 모션 (CC0, 무료)

[KayKit Character Animations](https://kaylousberg.itch.io/kaykit-character-animations) 무료판의 양손 근접 모션 셋은
**골반 높이가 ±1cm 로 그대로**이고 두 손이 자루를 함께 쥔다. 원본 FBX 를 직접 읽어 확인했다.

| MeleeStyle | 기본 공격 (SlashVariant 0) | 내려찍기 (SlashVariant 1) |
|---|---|---|
| 0 검 | `Slash` — Kevin 한손 가로베기 (그대로), 타격 0.24초 | `SlashV` — **KayKit 양손 내려찍기**, 0.49초 |
| 1 대검 | `Slash2H` — **KayKit 양손 가로베기**, 0.41초 | `SlashV2H` — KayKit 양손 내려찍기, 0.58초 |
| 2 창 | `SlashPolearm` — **KayKit 양손 찌르기**, 0.42초 | `SlashVPolearm` — KayKit 양손 내려찍기, 0.58초 |

| 클립 | 원본 테이크 · 구간(30fps) | 모양 |
|---|---|---|
| `KK_2H_Chop` | `Melee_2H_Attack_Chop` 8 ~ 30 | 두 손으로 머리 위까지 들었다가 정면 아래로 내리친다. 천천히 들기 시작하는 앞부분과 바닥에서 멈춘 뒷부분은 잘랐다 (원본대로면 대검이 0.8초 뒤에야 맞는다) |
| `KK_2H_Slice` | `Melee_2H_Attack_Slice` 0 ~ 24 | 왼쪽 뒤로 감았다가 수평으로 오른쪽까지 쓸어 벤다 |
| `KK_2H_Stab` | `Melee_2H_Attack_Stab` 0 ~ 24 | 두 손으로 자루를 쥐고(간격 30cm) 뒤로 뺐다가 앞으로 1m 찌른다 |

- 타격 시점: 내려찍기는 **이 캐릭터에 샘플링했을 때 칼끝이 가장 멀리 나가며 가슴 높이(1.1 ~ 1.3m)를 지나는 순간**,
  가로베기는 칼끝이 정면을 지나는 순간, 찌르기는 다 뻗은 순간
- 창 판정: 찌르기 40° · 내려찍기 50°. 고른 모션의 부채꼴 안에 적이 없으면 다른 모션으로 바꾼다 (`MeleeWeapon.PickVariant`)
- 15장의 Quaternius 파일(24MB)은 뺐다. KayKit 파일은 3.3MB 이고, 22개 모션 중 3구간만 가져온다

### 16-3. Humanoid 연결 두 곳을 손으로 고정

KayKit 뼈대는 자동 연결이 어긋날 수 있는 곳이 두 군데라 도구(`CharacterSetup.BoneOverrides`)가 못박는다.

| 뼈 | 자동 연결 | 고정한 것 | 이유 |
|---|---|---|---|
| 손 | `hand` (맞음) | `hand.l` · `hand.r` | `wrist` 아래에 `hand` 가 한 번 더 있고, 무기는 `hand` 기준으로 손목 대비 최대 70° 돈다. `wrist` 로 잡히면 무기 각도가 사라진다 |
| 가슴 | **비어 있었다** | `chest` | 비면 상체 비틀림(최대 70°)이 팔 회전에 섞여 들어간다 |

### 16-4. 왼손을 자루에 — `MeleeTwoHandGrip` (신규)

KayKit 원본은 2~3등신이라 팔이 짧다. 이 캐릭터로 옮기면 **왼손이 자루에서 50 ~ 90cm 떨어진 채** 휘둘렀다.

- `Scripts/Player/MeleeTwoHandGrip.cs` — Player 루트, Animator IK (근접 레이어의 IK Pass)
- 애니메이터 상태 태그 **`TwoHand`** 인 상태에서만 켠다: 내려찍기 3개 · 대검 가로베기 · 창 찌르기 · 대검 / 창 대기. 전이 중에는 비율대로 섞는다
- 무기 프리팹 `MeleeWeapon.leftGripNear/Far` = 왼손이 쥘 수 있는 구간 (도구가 모델에서 잰다)
  - 검 · 대검: 오른손 아래 손잡이 (0.11m ~ 손잡이 끝 4cm 앞)
  - 창: 오른손 앞 자루 0.3 ~ 1.0m
- 애니메이션의 왼손에서 **가장 가까운 자루 위 점**을 쥔다 → 모션이 두 손을 벌리는 만큼 자루를 따라 미끄러진다
- 결과: 자루까지 거리 50 ~ 90cm → 5 ~ 37cm (손목 기준 — 손바닥은 자루 위)

### 16-5. 무기 길이 다시 맞춤

양손 모션은 손을 몸 가까이(약 0.75m) 두고 휘둘러 칼끝이 덜 나간다. 캐릭터에 샘플링해 다시 쟀다.

| 무기 | 사거리 | 길이 (15장 → 16장) | 기본 공격 칼끝 최대 | 내려찍기 칼끝 최대 |
|---|---|---|---|---|
| 검 | 3 | 2.1 → **2.3m** | 2.88m | 2.60m |
| 대검 | 4 | 3.1 → **3.5m** | 3.20m ⚠ | 3.60m |
| 창 | 5 | 4.8 → **5.0m** | 4.95m | 4.75m |

⚠ 대검 가로베기는 칼을 머리 높이로 비스듬히 들고 쓸어서 가장 짧다. 판정은 적 몸통(0.4 ~ 0.5m)까지 재므로 실제 차이는 약 0.3m 다.

## 17. 패링 연출 · 튕겨내기 · 무기별 자세

> 2026-09-26 요청: "패링하면 '팅' 하는 사운드 · 연출이 있으면 좋겠다. 투사체는 총알로 바꾸지 말고 몬스터가 쏜 투사체가
> 반대 방향으로 튕겨지게. 패링 모션은 검은 맞받아치는 느낌, 대검 · 창은 두 손으로 칼등 · 창대로 막는 느낌."

### 17-1. "팅" — 소리 · 섬광 · 멈칫

패링이 성공한 순간 한꺼번에 나온다.

| 연출 | 내용 | 설정 |
|---|---|---|
| 금속 타격 | Kenney `impactMetal_light` — 2.3 ~ 3kHz 의 밝은 "틱" (0.06초) | `ParryController.successSound` |
| **"팅~" 여운** | 금속 막대 배음(1 : 2.756 : 5.404)을 **직접 합성**한 소리. 1.5 ~ 1.9kHz, 0.5초 울림, 3가지 | `ringSound` · `Assets/AUDIO/Parry/ParryRing_01~03.wav` |
| 투사체를 쳐냈을 때 | 같은 여운을 높게(×1.3 ~ 1.45) 한 번 더 | `deflectSound` |
| 섬광 · 고리 · 불꽃 | 몸 앞 0.9m · 높이 1.25m 에서 섬광(0.12초) + 퍼지는 고리(0.22초) + 불꽃 26개. 쳐낸 투사체 자리에도 불꽃 10개 | `Prefabs/Effect/Parry/ParryFlash.prefab` (`ParryFlash`) |
| 멈칫 (히트 스톱) | 시간 ×0.05 로 0.06초 | `hitStopScale` · `hitStopDuration` |
| 화면 흔들림 | 0.25 (예전 그대로) | `successShake` |

- Kenney 소리만으로는 "팅~" 이 안 된다 — 밝은 금속음은 0.06초 만에 끊기고, 종소리(`impactBell`)는 240 ~ 380Hz 로 "댕" 에 가깝다.
  그래서 타격음(시작) 위에 합성한 여운을 겹쳤다 ([AUDIO_LICENSES.md](../../../Assets/AUDIO_LICENSES.md) — 자체 제작)
- 섬광 재질은 URP Particles/Unlit 가산 혼합이고, 색을 1 넘게 줘서 스테이지 블룸(threshold 1)에 번진다. 텍스처 두 장(점 · 고리)도 도구가 그린다
- 멈칫은 게임이 멈춰 있으면(레벨업 창 등, timeScale 0) 걸지 않고, 그사이 다른 코드가 timeScale 을 바꾸면 되돌리지 않는다

### 17-2. 몬스터 투사체를 그대로 튕겨낸다 — `DeflectedProjectile` (신규)

| | 전 (7-6) | 후 |
|---|---|---|
| 모양 | 적 투사체를 없애고 **소총 탄**(`Bullet_new`)을 쐈다 | **몬스터가 쏜 그 투사체**가 트레일째 그대로 날아간다 |
| 방향 | 반대 방향 | 날아오던 방향의 **정반대** (쏜 몬스터를 쫓아가지 않는다) |
| 속도 | 16 고정 | 날아오던 속도 × 1.4 (최소 12) |
| 피해 | 무기 공격력 × 1.5 | 같음 |

- `RangedProjectile`(Enemy 폴더)은 협업 제약상 고칠 수 없고, 방향을 바꾸는 public 함수도 없다.
  그래서 쳐내는 순간 그 컴포넌트를 잠시 끄고 `DeflectedProjectile` 이 비행을 넘겨받는다 (속도는 private 값을 **읽기만** 한다)
- 원래 투사체처럼 구체 캐스트로 움직인다. Enemy · Boss 태그에 맞으면 피해를 주고 사라지고, 벽에 맞으면 사라지고, 플레이어는 통과한다
- 끝나면 `RangedProjectile` 을 다시 켜고 풀로 돌려보낸다 — 다음에 몬스터가 쏠 때는 원래대로 난다 (검증함)

### 17-3. 무기별 패링 자세

패링 상태가 무기마다 따로 생겼다: Any State → `Parry_스타일` (Parry 트리거 + MeleeStyle).

| 무기 | 상태 | 모션 | 느낌 |
|---|---|---|---|
| 검 | `Parry` | KayKit `Melee_1H_Attack_Slice_Diagonal` 3 ~ 24프레임 ×1.4 | **맞받아치기** — 칼을 왼쪽 위로 들었다가 정면을 가로질러 오른쪽 아래로 짧게 쳐낸다. 가로베기와 모양이 달라 "막았다"가 보인다 |
| 대검 | `Parry2H` (태그 `Guard`) | KayKit `Melee_Block_Hit` 0 ~ 18프레임 ×1.2 + **두 손 방어 IK** | 오른손을 허리 앞에 두고 칼을 왼쪽 위로 비스듬히 세운 뒤, **왼손으로 칼등을 받친다** (쥔 점에서 0.8m) |
| 창 | `ParryPolearm` (태그 `Guard`) | 같은 몸통 모션 + 두 손 방어 IK | 창대를 몸 앞에 비스듬히 세우고 **두 손을 벌려 창대를 쥔다** (0.85m) |

- 몸통 `Block_Hit` 은 골반이 그대로이고, 상체가 0.2초 동안 8° 뒤로 젖혀졌다 돌아온다 — 막고 밀리는 반동
- 두 손 방어는 `MeleeTwoHandGrip` 이 한다. 무기 프리팹의 `guardGrip`(오른손 자리) · `guardAxis`(무기 방향) · `guardLeftAlong`(왼손 자리)대로
  오른손 IK 로 무기를 세우고, 왼손을 칼등 · 창대에 붙인다. 무기는 지금 모션 자세에서 가장 적게 돌려 세워서 손목 비틀림이 자연스럽게 남는다
- 방어 자세 값은 `CharacterSetup` 사양 표의 `GuardGrip` · `GuardAxis` · `GuardLeftAlong` 에 있다 (검은 비어 있다 — 방어 자세 없음)
