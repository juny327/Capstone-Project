# 01. 구조 분석

## 1. 파일별 역할

### 핵심 (게임 루프에 직접 관여)

| 파일 | 역할 | 주요 의존 |
|---|---|---|
| `PlayerStats.cs` | HP/EXP 보유, `IDamageable` 구현, 사망 시퀀스 시작 | `GameEvents`, `CameraShakeManager`, `Animator` |
| `PlayerMove.cs` | Input System 입력, Rigidbody 이동, 마우스 방향 회전, 점프, 속도 배율 스택 | `PlayerInput`, `EnemyDetector`, `GameEvents` |
| `AutoAttack.cs` | 감지 범위에 적이 있으면 `attackRate` 주기로 발사 | `EnemyDetector`, `Gun` |
| `Gun.cs` | 총알·머즐플래시·탄피 생성, 무기 스탯(damage/speed) 보유 | `PoolManager`, `Bullet`, `GameEvents` |
| `Bullet.cs` | 직선 이동, 크리티컬 판정, 피격 이펙트, `IDamageable`에 데미지 전달 | `PoolManager`, `Poolable`, `IDamageable` |
| `EnemyDetector.cs` | 트리거 콜라이더 기반 주변 적 카운트, 적 유무 이벤트 발행 | `Enemy.OnDeath` |

### 동작하지만 보조적

| 파일 | 역할 |
|---|---|
| `PlayerStatus.cs` | `IStatusReceiver` 구현. 받은 `StatusEffect`를 자기 `gameObject`에 위임하는 3줄짜리 얇은 어댑터 |
| `StatusEffect.cs` | `duration` + `Apply(GameObject)` 추상 클래스 |
| `SlowEffect.cs` | `StatusEffect` 구현. 코루틴으로 `AddSpeedModifier` → 대기 → `RemoveSpeedModifier` |
| `PlayerStatsUI.cs` | HP바/HP텍스트/EXP/킬수/탄속/공격력/이동속도 HUD 갱신 |
| `CameraShakeManager.cs` | Cinemachine `ImpulseSource` 래핑 싱글턴 |

### 정리 대상

| 파일 | 상태 |
|---|---|
| `WeaponController.cs` | Unity 기본 템플릿 그대로. 빈 `Start`/`Update`만 존재 |
| `WeaponBase.cs` | 동일하게 빈 템플릿 |
| `IWeapon.cs` | **이름은 인터페이스인데 실제로는 빈 `MonoBehaviour` 클래스**. `Gun`은 이를 구현하지 않음 |
| `MarkerFollow.cs` | `BossProjectile.OnExplosion`을 구독하는 보스 투사체 마커. Player 폴더에 있을 이유가 없음 |

## 2. 데이터 흐름

### 2-1. 이동

```
Mouse/Keyboard
  └→ PlayerInput.Player.Move (performed/canceled)
       └→ PlayerMove.OnMove → move(Vector2), Animator "isMove"

PlayerMove.Update()
  └→ cam.ScreenPointToRay(마우스) → groundLayer Raycast → targetLookPos

PlayerMove.FixedUpdate()
  ├→ rb.linearVelocity.xz = move * CurrentSpeed      (y는 보존 → 중력 유지)
  ├→ Physics.Raycast(down) → currentGround
  ├→ Quaternion.RotateTowards → rb.MoveRotation      (targetLookPos 바라보기)
  └→ 착지 감지(!wasGround && currentGround) → Animator "isJump" = false
```

`CurrentSpeed`는 `baseSpeed`에 `speedModifiers` 리스트의 모든 값을 곱한 결과다. 슬로우(0.5f)와 스턴(0f)이 동시에 걸려도 자연스럽게 합성된다.

### 2-2. 전투

```
EnemyDetector (트리거)
  ├→ Count++/Count--
  ├→ OnEnemyEnter(bool) ──→ PlayerMove.OnEnemyEntered → Animator "isAttack"
  └→ HasEnemy() ─────────→ AutoAttack.Update

AutoAttack.Update (timer >= attackRate)
  └→ Gun.Shoot()
       ├→ PoolManager.Get(muzzleFlashPrefab)  → muzzle 위치
       ├→ PoolManager.Get(bulletCasePrefab)   → bulletCase 위치
       └→ PoolManager.Get(bulletPrefab)
            └→ Bullet.Init(speed, damage)
                 ├→ 크리티컬 판정 (Random.value < 0.05f → damage × 2)
                 ├→ rb.linearVelocity = forward * speed
                 ├→ ApplyDamageVisual()  (MaterialPropertyBlock "_PowerColor")
                 └→ Invoke(ReturnToPool, lifeTime=3f)

Bullet.OnTriggerEnter (tag: Enemy / Boss)
  ├→ SpawnHitEffect  (Boss는 중심에서 바깥 방향으로 오프셋)
  ├→ IDamageable.TakeDamage(DamageInfo{damage, isCritical, hitPoint, hitDirection})
  └→ ReturnToPool()
```

### 2-3. 성장 (EXP → 업그레이드)

```
Enemy 사망 → ExpOrb 스폰 → 플레이어 근접(SphereCollider trigger)
  └→ ExpOrb.Update: 가속 추적 → pickupDistance 이내
       └→ PlayerStats.AddExp → OnExpChanged → PlayerStatsUI.UpdateExp

StageManager: OnEnemyKilled 누적 → killTarget 도달 → OnStageClear
  └→ GameManager → OnShowStageClearUI → OnOpenUpgradeUI → UpgradeUI

UpgradeCard 클릭 → OnUpgradeSelected(data)
  └→ UpgradeManager.TryUpgrade
       ├→ currentExp < costExp → OnUpgradeFailed
       └→ SpendExp → UpgradeEffect.Apply(player) → OnUpgradeSuccess
            ├→ DamageUpgrade  → Gun.AddDamage       (GetComponentInChildren)
            ├→ GunSpeedUp     → Gun.AddSpeed        (GetComponentInChildren)
            ├→ SpeedUpgrade   → PlayerMove.AddSpeed (GetComponent)
            ├→ ExpandHP       → PlayerStats.ExpandHP
            └→ Heal           → PlayerStats.AddHP
```

### 2-4. 상태이상 (보스 → 플레이어)

```
BossSlowSkill / StunZone
  └→ hit.GetComponent<IStatusReceiver>()
       └→ PlayerStatus.ApplyStatus(effect)
            └→ effect.Apply(gameObject)
                 └→ target.GetComponent<MonoBehaviour>().StartCoroutine(...)
                      ├→ SlowEffect : PlayerMove.AddSpeedModifier(multiplier)
                      └→ StunEffect : PlayerMove.AddSpeedModifier(0f)
                         ... WaitForSeconds(duration) ...
                      └→ RemoveSpeedModifier + 이펙트 파괴
```

### 2-5. 사망 시퀀스

```
PlayerStats.TakeDamage → currentHp == 0
  └→ Die()
       ├→ GameEvents.OnPlayerDeadStart
       │    ├→ PlayerMove.StopPlayer     (isDead=true, 입력 차단, 속도 0)
       │    ├→ AutoAttack.StopAttack     (enabled = false)
       │    ├→ BossBrain.OnPlayerDead
       │    └→ BossSkillController.StopAllSkills
       ├→ deathParticle Instantiate
       └→ anim.Play("Die")

  [애니메이션 이벤트] → PlayerStats.EndingDieAnim()
       └→ DeathSequence 코루틴: WaitForSeconds(3)
            └→ GameEvents.OnPlayerDeadEnd → GameOverUI.Open

  GameOverUI 버튼 → GameEvents.OnPlayerDead
       └→ GameAppManager.OnPlayerDead → Destroy(Player)
```

> 3단계(`DeadStart` → `DeadEnd` → `Dead`)로 나뉜 사망 이벤트는 의도는 명확하나, 중간 단계가 **애니메이션 이벤트**에 의존한다는 점이 취약점이다(02 문서 M-3 참조).

## 3. 이벤트 계약 (`GameEvents`)

Player 모듈이 관여하는 이벤트만 정리했다.

| 이벤트 | 발행자 | 구독자 |
|---|---|---|
| `OnPlayerSpawned(Transform)` | `GameAppManager:81` | `PlayerStatsUI`, `CameraController`, `EnemyManager`, `BossBrain`, `UpgradeManager` |
| `OnCameraReady(Camera)` | `GameAppManager:49` | `PlayerMove.SetCamera` |
| `OnPlayerDeadStart` | `PlayerStats:84` | `PlayerMove`, `AutoAttack`, `BossBrain`, `BossSkillController` |
| `OnPlayerDeadEnd` | `PlayerStats:118` | `GameOverUI` |
| `OnPlayerDead` | `GameOverUI:25` | `GameAppManager` |
| `OnBulletDamageChanged(float)` | `Gun:16, 52` | `PlayerStatsUI` |
| `OnBulletSpeedChanged(float)` | `Gun:58` | `PlayerStatsUI` |
| `OnMoveSpeedChanged(float)` | `PlayerMove:31, 37, 171` | `PlayerStatsUI` |
| `OnStageProgress(int,int)` | `StageManager:22, 28` | `PlayerStatsUI` |
| `Player` (static Transform) | `GameAppManager:78` | `BossBrain:20` — **테스트용 훅. 코드 주석에 "꼭 지울것" 표기** |

### 발행 지점의 비대칭

- `Gun.Start()`는 `OnBulletDamageChanged`만 발행하고 `OnBulletSpeedChanged`는 발행하지 않는다. 초기 표시는 `PlayerStatsUI.SetPlayer`가 `gun.bulletSpeed`를 직접 읽어 메꾸고 있어 우연히 동작한다.
- `PlayerMove.AddSpeed`는 `CurrentSpeed`가 아닌 `baseSpeed`를 발행한다 (02 문서 M-1).

## 4. 인터페이스 사용 현황

| 인터페이스 | 정의 | 구현체 | 호출부 |
|---|---|---|---|
| `IDamageable` | `Interfaces/IDamageable.cs` | `PlayerStats`, `Enemy`, `BossHealth` | `Bullet.OnTriggerEnter`, 적/보스 공격 |
| `IStatusReceiver` | `Interfaces/IStatusReceiver.cs` | `PlayerStatus` | `BossSlowSkill:26`, `StunZone:24` |
| `IPoolable` | `FrameWork/IPoolable.cs` | `Bullet`, `ExpOrb` 등 | `PoolManager` |
| `IWeapon` | `Player/IWeapon.cs` | **없음** (인터페이스가 아니라 빈 MonoBehaviour) | 없음 |

`DamageInfo`는 `damage / isCritical / hitPoint / hitDirection / cameraShake` 5필드 구조체다. `Bullet`은 `cameraShake`를 채우지 않으므로(기본값 0) 적 피격 시 카메라 흔들림이 없고, 플레이어 피격 시에만 적/보스 쪽에서 값을 채워 흔들린다.

## 5. 설계상 잘 잡힌 부분

1. **씬 간 결합 최소화** — 플레이어는 `DontDestroyOnLoad`이고 각 씬 UI/매니저는 새로 생성되는 구조인데, `OnPlayerSpawned`를 씬 로드마다 재발행해 참조를 다시 잇는다. 씬 로드 순서에 의존하지 않는 좋은 패턴이다.
2. **속도 배율 스택** — `speedModifiers`를 곱셈으로 합성해 슬로우·스턴 중첩을 별도 분기 없이 처리한다. 스턴을 "배율 0"으로 표현한 것도 깔끔하다.
3. **전면적 풀링** — 총알, 머즐플래시, 탄피, 피격 이펙트, EXP 오브까지 전부 `PoolManager` 경유. 자동공격 게임 특성상 필수적인 선택이다.
4. **`MaterialPropertyBlock` 사용** — `Bullet.ApplyDamageVisual`, `ExpOrb.Initialize`가 머티리얼을 직접 건드리지 않아 인스턴스 복제가 발생하지 않는다.
5. **업그레이드의 ScriptableObject 분리** — `UpgradeEffect`를 SO 다형성으로 구성해 새 업그레이드 추가 시 매니저를 수정할 필요가 없다.
