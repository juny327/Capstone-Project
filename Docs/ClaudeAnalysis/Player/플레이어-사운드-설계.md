# 플레이어 사운드 설계

> 작성 2026-09-23 · 대상 브랜치 `main`
> 짝 문서: [플레이어-시스템-정리.md](플레이어-시스템-정리.md) · [주무기-확장-후보.md](주무기-확장-후보.md)

플레이어 파트에 사운드를 입히기 위한 문서다.
**어디에 무슨 소리가 필요한지 · 어디서 구하는지 · 어떤 순서로 넣는지**를 정리했다.

## 1. 현재 상태

먼저 확인한 사실이다. 추정이 아니라 프로젝트를 뒤져 본 결과다.

> **2026-09-25 갱신** — 사운드 팩을 넣고 첫 소리를 붙였다. 아래 표는 그 이후 기준이다.

| 항목 | 상태 |
|---|---|
| 오디오 파일 | **541개** (Kenney 354 · SnakeF8 155 · 음악 29 · 전기 3) |
| 임포트 설정 | 일괄 적용됨 (`Tools/Audio/오디오 임포트 설정 일괄 적용`) |
| 라이선스 기록 | `Assets/AUDIO_LICENSES.md` — 전부 CC0 |
| **업그레이드 카드 소리** | **연결됨** (성공 `confirmation_001` · 실패 `error_001`) |
| `AudioMixer` | **있음** — `Assets/Audio/GameAudioMixer.mixer` (Master → BGM · SFX · UI) |
| `SoundManager` | **있음** — 4개 스테이지 씬. `GameEvents` 9종 구독 |
| 이벤트 소리 | 레벨업 · 처치 · 사망 · 스왑 · 무기 획득 · 카드 · 클리어 · 보상 · 보스 |
| **무기 발사 · 장전** | **8종 전부 연결** — 실총(Snake) + 전자음 · 검(Kenney) |
| **플레이어 몸 소리** | **연결됨** — 발소리 10종 · 구르기 4종 · 점프 · 착지 · 스태미나 |
| **명중 · 치명타** | **연결됨** — 각 5종. 프레임당 1회로 묶음 |
| **배경음** | **연결됨** — 씬별 6곡, 1.2초 크로스페이드 |
| 볼륨 옵션 UI | **아직 없음** (`SetMusicVolume` · `SetSfxVolume` 는 준비됨) |
| `Player.prefab` 의 `AudioSource` | 없음 |
| `AudioListener` | `Main Camera` 에 1개 (정상) |

### 1-1. 이미 있는 두 가지 선례

**(1) `UpgradeCard.cs` — 선언만 되어 있다**

```csharp
public AudioSource audioSource;
public AudioClip successSound;
public AudioClip failSound;
```

다른 작업자가 자리를 잡아 두고 비워 둔 상태였고, **여기에 첫 소리를 붙였다**(2026-09-25).

> ⚠ **`AudioSource` 를 카드에 달면 안 된다.**
> 카드를 고르면 `UpgradeUI` 가 패널을 끄는데, 패널이 꺼지면 그 아래 `AudioSource` 도
> 같이 꺼져 소리가 즉시 잘린다.
> 그래서 **계속 켜져 있는 `UpgradeUI` 오브젝트**에 하나만 달고 카드 셋이 공유한다.
> 클립(에셋 참조)은 프리팹에, `AudioSource`(씬 오브젝트 참조)는 씬마다 연결했다.
> 도구: `Assets/Editor/UpgradeSoundSetup.cs`

**(2) `DashAttack.cs` — 코드로 소리를 만든다**

몬스터 B의 돌진 예고음은 **외부 파일 없이 사인파를 합성**해 쓴다
(`AudioClip.Create` + `SetData`, 650Hz → 1100Hz 스윕 0.12초).

> 이 방식은 **파일을 구하지 못할 때의 탈출구**다. 특히 UI 삑 소리, 경고음,
> 레벨업 신호음처럼 "단순한 전자음"은 코드로 만드는 편이 라이선스 걱정도 없고 용량도 0이다.
> 실제 `DashAttack` 의 `AudioSource` 설정(`spatialBlend 0.5`, `minDistance 4`,
> `maxDistance 25`, `Linear rolloff`)은 3D 사운드 기준값으로 그대로 참고할 만하다.

## 2. 붙이는 구조 — 먼저 정할 것

`UpgradeCard` 방식(컴포넌트마다 `AudioSource` + `public AudioClip`)을 그대로 확장하면 문제가 생긴다.

- 무기 5종 × 발사 · 장전 시작 · 장전 완료 · 스왑 = 인스펙터 연결이 20개를 넘는다
- 기관단총은 **0.12초 간격**이라 초당 8회 재생된다. 동시 재생 제한이 없으면 소리가 뭉갠다
- 볼륨을 한 번에 줄일 방법이 없다 (옵션 메뉴를 만들 수 없다)

### 2-1. 권장 — 3층 구조

| 층 | 내용 | 이유 |
|---|---|---|
| **AudioMixer** | `Master` → `BGM` · `SFX` · `UI` | 나중에 볼륨 옵션이 반드시 필요해진다. 나중에 넣으면 전부 다시 연결해야 한다 |
| **`SoundManager`** | `AudioSource` 를 여러 개 풀링해 돌려 쓴다. `Play2D(clip)` · `Play3D(clip, pos)` | 매번 `AddComponent` 하지 않기 위해 |
| **데이터** | 무기 소리는 `WeaponData` 에, 플레이어 소리는 `PlayerSoundSet` (SO) 에 | |

### 2-2. 무기 소리는 `WeaponData` 에 넣을 것

```csharp
[Header("Sound")]
public AudioClip fireSound;
public AudioClip reloadStartSound;
public AudioClip reloadEndSound;
public AudioClip equipSound;
```

이렇게 두면 [주무기-확장-후보.md](주무기-확장-후보.md) 의 **"`.asset` 하나로 무기 추가"** 가
소리까지 포함해서 성립한다. 무기를 늘릴 때마다 코드를 고치지 않아도 된다.

### 2-3. 구현됨 — `GameEvents` 구독 (2026-09-25)

`GameEvents` 에 이미 쓸 만한 이벤트가 깔려 있다. **`SoundManager` 하나가 이것만 구독해도
기존 코드를 거의 건드리지 않고** 절반이 해결된다.

| 이벤트 | 쓸 소리 |
|---|---|
| `OnAmmoChanged(int, int)` | 탄약 0 → 장전 시작 신호 |
| `OnWeaponSwapped(IWeapon)` | 무기 교체 |
| `OnWeaponsChanged()` | 무기 획득 |
| `OnPlayerLevelUp(int)` | 레벨업 |
| `OnPlayerDeadStart()` | 사망 |
| `OnEnemyKilled()` | 처치 |
| `OnUpgradeSuccess` / `OnUpgradeFailed` | 카드 선택 결과 |
| `OnOpenUpgradeUI` | 카드 창 열림 |
| `OnStageClear` / `OnGameWin` | 클리어 |
| `OnBossSpawned(BossHealth)` | 보스 등장 |

**실제 구성**

| 파일 | 역할 |
|---|---|
| `Core/Audio/GameSoundSet.cs` | 이벤트별 클립 묶음 (SO). 소리를 바꿀 때 코드를 안 고친다 |
| `Core/Audio/SoundManager.cs` | `GameEvents` 9종 구독 + `AudioSource` 12개 풀링 |
| `Editor/SoundManagerSetup.cs` | 믹서 · 소리 묶음 · 씬 배치 생성 (멱등) |

- `AudioSource` 는 **미리 12개 만들어 돌려 쓴다.** 놀고 있는 것부터 쓰고,
  전부 바쁘면 가장 오래된 것을 끊는다
- 클립을 여러 개 넣으면 **무작위로 고른다.** 처치음은 `impactMetal_light` 5종을 돌린다
- 피치를 매번 0.96~1.04 로 흔든다 — 같은 클립이 반복되면 기계음처럼 들린다
- **`minInterval`** — 처치음은 0.06초. 초당 여러 번 죽는 게임이라 없으면 소리가 뭉갠다
- 솎아 내기 기준은 `Time.unscaledTime` 이다. `timeScale = 0` 인 카드 창에서도 소리가 나야 한다

> **`DontDestroyOnLoad` 로 씬을 넘어 살아남는다** (BGM 을 넣으면서 바꿨다).
> 로비 · 스테이지 4개에 하나씩 놓여 있고, 두 번째부터는 `Awake` 에서 스스로 사라진다.
>
> **배경음**은 `MusicSet`(씬 이름 → 곡)으로 고른다. 씬을 추가해도 코드를 고치지 않는다.
> 같은 곡이면 다시 시작하지 않고, 곡이 바뀔 때만 1.2초 크로스페이드한다.
> 페이드는 `unscaledDeltaTime` 으로 센다 — 씬 전환 직후 `timeScale` 이 0 일 수 있다.

## 3. 파트별로 필요한 사운드

"시점"은 실제로 코드를 넣을 자리다.

### 3-1. 이동

| 소리 | 시점 | 우선 | 메모 |
|---|---|---|---|
| 발소리 (걷기) | `PlayerMove.FixedUpdate` 에서 **이동 거리 누적** | ★★★ | 아래 주의 참고 |
| 발소리 (달리기) | 같은 곳, 간격을 짧게 | ★★★ | 걷기와 **같은 클립 + 피치/볼륨 상향**으로 충분 |
| 점프 | `OnJump` | ★ | |
| 착지 | `!wasGround && currentGround` ([PlayerMove.cs:323](../../../Assets/Scripts/Player/PlayerMove.cs#L323)) | ★★ | |
| 구르기 | `StartRoll()` | ★★★ | 옷 스치는 소리 + 바람 |
| **스태미나 소진** | `exhausted = true` ([PlayerMove.cs:370](../../../Assets/Scripts/Player/PlayerMove.cs#L370)) | ★★★ | 숨 헐떡임. **HUD 색 변화만으로는 약하다** |
| 스태미나 회복 완료 | `exhausted = false` (:390) | ★ | 다시 달릴 수 있다는 신호 |

> **발소리는 이동 거리로 잰다** (`PlayerMove.TickFootstep`, `stepDistance` 2.2m).
> 애니메이션 이벤트를 쓰지 않은 이유: `Run_gunMiddle_AR.anim` 의 `m_Events` 가 비어 있고,
> 클립을 교체하면 이벤트가 전부 날아간다. `MeleeWeapon` 이 `hitDelay` 를 쓴 것과 같은 이유다.
>
> 거리로 재면 **걷기와 달리기가 저절로 구분된다** — 빠르면 같은 시간에 더 멀리 가므로
> 발소리도 그만큼 잦아진다. 속도 업그레이드를 받아도 따로 손댈 것이 없다.
>
> ⚠ 기준점(`lastFootstepPos`)은 **멈춰 있을 때도 갱신**해야 한다.
> 갱신을 건너뛰면 다시 걸을 때 그동안의 이동이 한꺼번에 쌓여 발소리가 즉시 터진다.

### 3-2. 무기 — 발사

| 무기 | 소리 성격 | 주의 |
|---|---|---|
| 소총 (0.3초) | 짧고 건조한 발사음 | |
| 기관단총 (0.12초) | 더 가볍고 짧게 | **초당 8회.** 피치 랜덤 ±5% 없으면 기계음처럼 들린다 |
| 스나이퍼 (1.6초) | 묵직 + 잔향 김 | 발사 간격이 기니 클립이 길어도 된다 |
| 검 (0.7초) | `knifeSlice` 2종 **연결됨** | Kenney RPG Audio. **타격음이 섞이지 않아** 허공을 갈라도 어색하지 않다 |
| 드론 (0.8초) | 가늘고 전자음 | 3D로 — 드론 위치에서 나야 한다 |

### 3-3. 무기 — 탄창 · 장전

| 소리 | 시점 | 우선 | 메모 |
|---|---|---|---|
| 장전 시작 | `ProjectileWeapon.OnReloadStarted(duration)` | ★★★ | **`duration` 이 인자로 들어온다.** 애니메이션을 `ReloadSpeed` 로 맞춘 것처럼 `AudioSource.pitch` 로 클립 길이를 맞출 수 있다 |
| 장전 완료 | `WeaponBase.OnReloadFinished()` | ★★ | 찰칵 — "이제 쏠 수 있다"는 신호 |
| 장전 취소 | `OnReloadCanceled()` | ★ | 스왑 · 구르기 시. 소리도 끊어야 한다 |
| 탄 떨어짐 | `Fire()` 에서 `ammo` 가 0이 되는 순간 | ★★ | 자동 장전이라 빈 총 클릭음은 불필요 |
| 무기 교체 | `SetActive(true)` 또는 `SwapTo` | ★★ | |

> 장전 소리는 **장전 시간이 무기마다 다르다**(소총 2.0 · 기관단총 1.6 · 스나이퍼 2.6초).
> 클립 하나를 피치로 늘리고 줄이면 세 무기를 다 덮을 수 있다.
> `OnReloadStarted` 가 이미 `duration` 을 주므로 계산이 필요 없다.

### 3-4. 피격 · 생존

| 소리 | 시점 | 우선 |
|---|---|---|
| 피격 | `PlayerStats.TakeDamage` | ★★★ |
| 저체력 경고 | 체력 30% 이하로 **진입할 때 1회** | ★★ |
| 사망 | `PlayerStats.Die()` 또는 `OnPlayerDeadStart` | ★★★ |
| 회복 | `AddHP` | ★ |
| 무적 중 피격 | `IsInvulnerable` 일 때 피해가 무효화되는 지점 | ★★ |

> **무적 중 피격음은 생각보다 중요하다.** 구르기 무적(1.5초)이 실제로 작동했는지
> 지금은 화면에서 전혀 알 수 없다. "튕겨 냈다"는 소리가 있으면 구르기를 쓸 이유가 분명해진다.

### 3-5. 타격 피드백

| 소리 | 시점 | 우선 | 메모 |
|---|---|---|---|
| 일반 명중 | `Bullet.OnTriggerEnter` | ★★★ | |
| **치명타** | 같은 곳, `isCritical == true` | ★★★ | `Bullet` 이 이미 `isCritical` 을 들고 있다. 소리를 다르게 하면 치명타가 체감된다 |
| 처치 | `GameEvents.OnEnemyKilled` | ★★ | |
| 폭발 | 유탄 계열 추가 시 | — | [주무기-확장-후보.md](주무기-확장-후보.md) 4-5 |

> **관통 · 광역은 한 프레임에 여러 번 맞힌다.** 그대로 재생하면 같은 소리가 겹쳐 뭉갠다.
>
> `SoundManager.ReportHit(isCritical)` 로 **모아 두었다가 `LateUpdate` 에서 한 번만** 낸다.
> 맞은 수만큼 볼륨을 조금 올려(최대 ×1.35) 광역이 닿았다는 느낌을 준다.
>
> **즉시 재생하지 않고 미루는 이유**: 한 프레임에 일반 명중과 치명타가 섞일 수 있다.
> 먼저 온 일반 명중을 바로 틀면 뒤따라온 치명타를 표현할 방법이 없다.
> 프레임 끝까지 모으면 **치명타가 하나라도 있을 때 치명타 소리로** 낼 수 있다.
>
> 호출 지점 4곳: `Bullet` · `MeleeWeapon` · `ChargeBeamWeapon` · `ChainBeamWeapon`.

## 4. 처음 10개만 넣는다면

전부는 나중 일이고, **이 10개면 "소리가 없는 게임"에서 벗어난다.**

| # | 소리 | 이유 |
|---|---|---|
| 1 | 발사 (소총) | 가장 자주 난다 |
| 2 | 명중 | 맞았는지 안 맞았는지가 지금 안 보인다 |
| 3 | 피격 | 체력이 닳는 걸 놓친다 |
| 4 | 장전 시작 | 왜 안 쏘는지 알려 준다 |
| 5 | 장전 완료 | 다시 쏠 수 있다는 신호 |
| 6 | 구르기 | 조작에 반응이 있어야 한다 |
| 7 | 스태미나 소진 | 왜 안 달려지는지 알려 준다 |
| 8 | 레벨업 | 보상감 |
| 9 | 카드 선택 | **필드가 이미 있다 — 클립만 넣으면 끝** |
| 10 | 사망 | 마무리 |

**9번부터 시작하는 걸 권한다.** 코드를 한 줄도 안 쓰고 클립만 끼우면 되므로,
소리 하나가 실제로 들리는지 확인하는 가장 빠른 길이다.

## 5. 사운드를 구하는 곳

### 5-1. 무료 — 추천 순

| 출처 | 라이선스 | 평가 |

### 5-4. ⚠ 에셋 스토어를 쓸 때 주의

| **폴더 규칙** | 가져온 위치 그대로 둔다. 종류별로 재배치하면 브랜치 병합에서 충돌한다 (기존 규칙) |

### 5-6. ⚠ 라이선스 — 지금부터 기록할 것

**받은 파일이 20개가 넘어가면 어디서 받았는지 절대 기억나지 않는다.**
캡스톤 제출물에 출처 표기가 필요한 라이선스(CC-BY)가 섞여 있으면 나중에 전부 다시 찾아야 한다.

→ 첫 파일을 받는 날 **`Assets/Audio/LICENSES.md`** 를 만들고 아래를 같이 적을 것.

```
| 파일 | 출처 | 라이선스 | 원작자 | 받은 날 |
|---|---|---|---|---|
| footstep_01.wav | Kenney - Impact Sounds | CC0 | Kenney | 2026-09-23 |
```

주의할 라이선스

- **CC0** — 아무 제약 없음. 가장 안전하다
- **CC-BY** — **출처 표기 필수.** 게임 크레딧에 반드시 넣어야 한다
- **CC-BY-NC** — **비상업 한정.** 캡스톤 과제로는 괜찮지만, 나중에 상용화하면 쓸 수 없다.
  지금 편하다고 넣어 두면 나중에 통째로 교체해야 한다
- **Unity Asset Store** — 좌석(seat)당 라이선스. 파일을 팀원에게 전달하는 것이 아니라
  **각자 자기 계정으로 받아야 한다** (이 프로젝트의 기존 규칙과 동일)

## 6. Unity 임포트 설정

| 용도 | 포맷 | Load Type | 채널 | 비고 |
|---|---|---|---|---|
| 짧은 효과음 (1초 미만) | `.wav` | `Decompress On Load` | **Force To Mono** | 3D로 쓰려면 모노여야 방향이 산다 |
| 중간 (1~5초) | `.wav` / `.ogg` | `Compressed In Memory` | 모노 | |
| BGM | `.ogg` | **`Streaming`** | 스테레오 | 메모리에 통째로 올리지 않는다 |

- `Load In Background` 를 켜면 로딩 중 끊김이 줄어든다
- 짧은 효과음은 **22.05kHz 로 낮춰도 거의 티가 안 난다.** 용량이 절반이 된다
- 3D 설정은 `DashAttack` 값을 기준으로: `spatialBlend 0.5` · `minDistance 4` ·
  `maxDistance 25` · `Linear rolloff`

**2D 와 3D 구분**

| 대상 | 방식 | 이유 |
|---|---|---|
| 플레이어 발사 · 장전 · 발소리 · 피격 · UI | **2D** (`spatialBlend 0`) | 항상 같은 볼륨이어야 한다. 카메라가 탑다운이라 거리 감쇠가 어색하다 |
| 드론 · 적 · 폭발 | **3D** | 어디서 났는지 알아야 한다 |

## 7. 자주 걸리는 함정

| 함정 | 대처 |
|---|---|
| 같은 클립 반복 → 기계음처럼 들린다 | **피치 랜덤 ±5~10%.** 또는 변형 3종을 돌려 쓴다. 기관단총(0.12초)은 필수 |
| 관통 · 광역이 같은 프레임에 5개를 재생 | 프레임당 1회로 묶고 볼륨만 올린다 |
| `AddComponent<AudioSource>()` 를 매번 호출 | `SoundManager` 에서 풀링 (프로젝트가 투사체 · 이펙트를 이미 풀링하고 있다) |
| 동시 재생이 쌓여 소리가 뭉갠다 | 같은 클립은 **동시 N개까지**로 제한 |
| 볼륨 옵션을 나중에 넣으려 한다 | **AudioMixer 를 처음부터** 끼운다. 나중에 넣으면 전부 다시 연결해야 한다 |
| 장전 소리가 장전 시간과 안 맞는다 | `OnReloadStarted(duration)` 의 인자로 `pitch` 를 계산한다 |
| 사망 후에도 소리가 난다 | `OnPlayerDeadStart` 에서 플레이어 계열 소리를 멈춘다 |
