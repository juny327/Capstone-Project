## 0. 한눈에

- 보상 3번만으로는 무기 · 부품을 만날 기회가 적다 → 스테이지 사이에 **상점**을 둔다
- 경험치 구슬을 먹을 때 **크레딧**도 같이 얻는다 (브로테이토 방식) — 적 코드를 건드리지 않는다
- 크레딧으로 무기 · 부품 · 회복을 산다. 새로고침 · 잠금 · 판매가 있다
- 한 판에 고르는 순간이 **3번 → 12 ~ 15번**으로 는다 (6장)
- 1단계는 보상 카드 뒤에 뜨는 **상점 창**, 2단계는 걸어 다니는 **정비 구역 씬**(테스트 룸 재사용) (4장)
- `GameManager`(Core 폴더) 몇 줄과 빌드 순서는 **팀 협의**가 필요하다 (4장 · 8장)

## 1. 문제 — 무기 · 부품을 만나는 순간이 3번뿐이다

**한 판의 길이** (`Stage/Data`)

| 스테이지 | 처치 목표 | 적이 떨어뜨리는 경험치 |
|---|---|---|
| Stage1 | 15 | 적 A 1 · B 2 · C 3 · D 2 |
| Stage2 | 20 | 〃 |
| Stage3 | 25 | 〃 |
| 합계 | **60마리** | 약 120 (평균 2로 가정) |

- 레벨업은 10 · 13 · 17 · 22 · 29 … 경험치마다 오르므로 한 판에 **6 ~ 7번**이다

**지금 한 판에서 고르는 순간**

| 무엇 | 횟수 | 무엇을 고르나 |
|---|---|---|
| 레벨업 카드 | 6 ~ 7번 | 모든 무기 공통 수치 · 스킬 |
| 스테이지 보상 | **3번** | 무기(새 무기 / 레벨업), 부품을 넣으면 부품까지 |

부품(4 ~ 5장)을 보상에만 섞으면 **한 판에 많아야 3개**다. 무기와 부품이 같은 3장을 나눠 쓰기 때문에 실제로는 더 적다.

## 2. 레퍼런스 — 상점과 재화

| 게임 | 방식 | 가져올 점 |
|---|---|---|
| **Brotato** (같은 장르) | 웨이브마다 **상점 4칸**. 재료를 먹으면 **경험치와 골드를 동시에** 얻는다. 새로고침은 할 때마다 비싸지고 상점마다 기본값이 오른다. **잠금**은 무료, 다음 상점까지 값째 유지. 가격은 웨이브마다 +10%. 4개를 다 사면 새로고침 1번 무료 | 재화를 따로 떨어뜨리지 않는다 · 새로고침 · 잠금 · 가격 상승 |
| **Hades — 카론** | 구역 중간과 **보스 직전**에 상점 방. 3개 중 산다. 재화(오볼)는 **죽으면 사라진다**. 가끔 나오는 우물에서도 3개 | 보스 직전 상점 = 마지막 정비 |
| **Risk of Rain 2 — 시간 사이의 시장** | 텔레포터 옆 **푸른 포털 → 별도 상점 스테이지**. 시장에 있는 동안 **시간 · 난이도가 멈춘다**. 달 아이템 5개가 각 2코인. 도가니에서 흰 템 3개 → 초록 1개 교환 | **"다른 스테이지로 이동하는" 상점**, 아이템 교환 |
| **Slay the Spire — 상인** | 카드 · 유물 · 물약 + **카드 제거**(75 + 제거 횟수 × 25 골드) | 쓰는 서비스는 쓸수록 비싸진다 |
| **Enter the Gungeon** | 판 안 재화(탄피, 적 처치) · 판 밖 재화(헤게모니 크레딧, 보스) 를 **나눈다**. 판 밖 재화로 새 총 · 아이템을 풀어 둔다 | 판 안 / 판 밖 재화 분리 |
| **Vampire Survivors** | 골드가 **판 사이에 남아** 영구 강화(파워업) · 캐릭터 해금에 쓰인다 | 메타 진행 (9장) |

**가져올 것**

1. 재화는 **경험치 구슬과 같이** 얻는다 (Brotato) — 적 코드를 건드리지 않고, 구슬을 줍는 행동에 의미가 더해진다
2. 상점은 **스테이지 사이, 시간이 멈춘 곳**에 (RoR2 · Brotato)
3. **새로고침 · 잠금 · 판매**가 있어야 운이 나빠도 방법이 있다 (Brotato)
4. **보스 직전 상점**이 가장 중요한 정비 시간이다 (Hades)
5. 재화는 기본적으로 **판이 끝나면 사라진다** (Hades · Brotato). 판 밖 재화는 선택 (9장)

## 3. 재화 — 크레딧

| 항목 | 제안 |
|---|---|
| 이름 | **크레딧** (SF 설정. 다른 후보: 스크랩 · 부품 조각) |
| 판이 끝나면 | 사라진다 — 죽거나 로비로 돌아가면 0 |
| 보관 | 플레이어 오브젝트에 붙인다. 플레이어가 씬을 넘어 살아 있으므로 **따로 저장할 필요가 없다** (주무기-확장-후보 8-3) |
| HUD | 경험치 바 옆에 숫자 하나 |

**얻는 법**

| 출처 | 양 | 구현 |
|---|---|---|
| **경험치 구슬** | 먹은 경험치와 **같은 양** | `PlayerStats.AddExp` (Player 폴더)에서 같이 더한다 — **적 · 구슬 코드는 그대로** |
| 스테이지 클리어 | 10 / 15 / 20 | 클리어 이벤트를 받는 새 스크립트 |
| 무피격 보너스 (선택) | 스테이지 동안 안 맞으면 +5 | 〃 |

> ⚠ 마지막 몇 마리가 떨어뜨린 구슬은 줍기 전에 스테이지가 끝날 수 있다.
> Brotato 처럼 **클리어 순간 남은 구슬을 모두 끌어당기면** 손해가 없다.
> 다만 구슬(`Items/ExpOrb`)은 Player 폴더 밖이라 협의가 필요하다. 아니면 남은 구슬의 크레딧만 대신 더해 주는 방법도 있다.

**한 판 수입 추정** — 평균 경험치 2, 구슬 90% 수집으로 가정

| 스테이지 | 처치 | 구슬 크레딧 | 클리어 | 합계 |
|---|---|---|---|---|
| Stage1 | 15 | ≈ 27 | 10 | **≈ 37** |
| Stage2 | 20 | ≈ 36 | 15 | **≈ 51** |
| Stage3 | 25 | ≈ 45 | 20 | **≈ 65** |
| 한 판 | 60 | ≈ 108 | 45 | **≈ 153** |

적 구성(A ~ D 비율)에 따라 달라지므로 실제 플레이에서 잰 뒤 가격을 맞춘다.

## 4. 상점 방식 — 세 가지

| | A. 상점 창 | B. 정비 구역 씬 | C. 스테이지 안 보급 터미널 |
|---|---|---|---|
| 모습 | 보상 카드 뒤 화면에 상점 창 (시간 멈춤) | 스테이지 사이 **걸어 다니는 별도 씬** (우주 정거장 · 보급선) | 클리어 뒤 그 자리에 터미널이 내려온다. 걸어가서 열고 출구 포털로 |
| 느낌 | 빠르다 | **"다른 곳으로 이동해 정비"** — 요청에 가장 가깝다. RoR2 시장 | 중간 |
| 무기 시험 | 없음 | **훈련용 해골로 바로 시험** — 테스트 룸 재사용 | 없음 |
| 씬 | 그대로 | 새 씬 + 빌드 순서 | 그대로 |
| 스테이지 흐름 코드 (`GameManager`, Core 폴더) | 보상 뒤에 상점 단계 추가, **상점 동안 60초 제한 끄기** | 다음 씬을 기억하는 방법 필요 (아래) | A 와 같음 + 남은 적 처리 |
| 비용 | **작다** | 크다 | 중간 |

**추천**: **A 로 먼저** 경제(가격 · 수입)를 맞춘다 → 여유가 되면 **B** 로 옮긴다. 상점 창 UI 는 B 의 터미널에서 그대로 쓴다.

**A 가 고칠 곳** — 지금 흐름은 `클리어 UI 3초 → 보상 카드 → 다음 씬` 이다.

- 보상이 적용되자마자 다음 씬으로 넘어간다 → 그 사이에 **상점 단계**를 넣어야 한다
- 보상 창에는 **60초 강제 진행**(`rewardTimeout`)이 있다. 상점에 같은 제한을 걸면 구경하다 튕긴다
- 둘 다 `GameManager`(Core 폴더) 몇 줄이라 **팀 협의**가 필요하다
- 이벤트 2개(`OnShopOpen` · `OnShopClosed`)를 보상 카드와 같은 방식으로 추가하면 된다

**B 의 씬 순서 문제**

- 다음 씬을 `빌드 순서 + 1` 로 고른다. 정비 구역 **한 씬**을 세 스테이지 사이에 끼울 수 없다
- 해결 ① `GameManager` 가 정비 구역을 부르면서 **돌아갈 스테이지 번호를 기억**하고, 정비 구역 출구가 그곳을 연다 (Core 협의)
- 해결 ② 정비 구역을 **프리팹 하나**로 만들고, 작은 씬 3개(`StageShop1 ~ 3`)에 놓아 빌드 순서 사이에 끼운다
  - 출구는 "빌드 순서 + 1" 을 여는 새 스크립트
  - 흐름 코드는 그대로다
  - 씬 이름을 `Stage` 로 시작하면 `GameAppManager` 가 플레이어 배치 · 카메라를 **자동으로** 해 준다. 단, 스테이지 매니저(처치 목표)는 넣지 않는다
- 어느 쪽이든 **빌드 순서가 바뀐다** — 보스 직전 흐름(주무기-확장-후보 8-6)과 함께 확인한다

## 5. 진열 · 가격

**진열 5칸** — 캐릭터 · 들고 있는 무기에 맞는 것만 나온다 (`CanOffer`)

| 칸 | 나오는 것 |
|---|---|
| 1 · 2 | 부품 — 들고 있는 무기에 달 수 있는 것 (4 ~ 5장) |
| 3 | 무기 — 새 무기 또는 가진 무기 레벨업 |
| 4 | 생존 — 수리 · 장갑 판 |
| 5 | 무작위 — **전용 개조**도 여기서 (무기 레벨 3 이상일 때) |

검사는 무기 칸 후보가 3종뿐이라 부품이 더 자주 나오게 된다. [무기-커스터마이징-조사.md](무기-커스터마이징-조사.md) 1-1 의 "카드가 매번 같다" 문제도 함께 풀린다.

**가격** (Stage1 기준, 스테이지마다 +10%)

| 상품 | 가격 | 메모 |
|---|---|---|
| 부품 — 기본 (초록) | 12 | |
| 부품 — 균형 (노랑) | 18 | |
| 부품 — 개조 (빨강) · 전용 개조 | 30 | |
| 새 무기 | 28 | 슬롯 4칸이 차면 나오지 않는다 |
| 가진 무기 레벨업 | 14 | |
| 수리 (체력 30% 회복) | 8 | |
| 장갑 판 (최대 체력 +15) | 20 | |

**규칙**

| 규칙 | 내용 |
|---|---|
| 새로고침 | 3 → 한 번 할 때마다 +2. 다음 상점은 기본값 +1 (Brotato) |
| 잠금 | 무료. 잠근 칸은 새로고침 · 다음 상점에서도 **값째** 남는다 |
| 판매 | 산 값의 50%. 무기 슬롯이 꽉 찼을 때 · 부품을 바꿀 때 |
| 다 샀을 때 | 5칸을 다 사면 새로고침 1번 무료 |
| 무료 보급 | 지금의 **보상 카드 3장 중 1장은 그대로** 둔다 — 크레딧이 없어도 하나는 얻는다 |

- 목표: 한 번 들러 **2개 안팎**을 산다. Stage1 수입 37 = 부품 두 개(12 + 18) + 새로고침 한 번(3) 정도
- 크레딧을 모아 **보스 직전(Stage3 뒤)에 크게 쓰는** 선택지가 생긴다

## 6. 한 판의 예

**사수** (시작: 소총)

| 때 | 크레딧 | 한 일 |
|---|---|---|
| Stage1 클리어 | 37 | 보상 카드: 샷건. 상점: 소총 **레이저 조준기**(12) + **확장 탄창**(18) → 7 남음 |
| Stage2 클리어 | 7 + 51 = 58 | 보상 카드: 샷건 레벨업. 상점: 새로고침 2번(4 + 6) · 새 무기 기관단총(31) · 수리(9) → 8 남음 |
| Stage3 클리어 (보스 직전) | 8 + 65 = 73 | 보상 카드: 스나이퍼. 상점: 소총 전용 개조 **지정사수**(36) · 장갑 판(24) · 새로고침(5) → 8 남음 |

**검사** (시작: 검)

| 때 | 크레딧 | 한 일 |
|---|---|---|
| Stage1 클리어 | 37 | 보상 카드: 대검. 상점: 검 **연장 방출기**(18) + **반응 손잡이**(12) → 7 남음 |
| Stage2 클리어 | 58 | 보상 카드: 창. 상점: 대검 **아크 코어**(20) · 창 **예리한 날**(13) · 수리(9) → 16 남음 |
| Stage3 클리어 | 81 | 보상 카드: 검 레벨업. 상점: 검 전용 개조 **검기**(36) · **반사 증폭기**(22) → 23 남음 |

가격은 스테이지 배율(×1.1 · ×1.2)을 곱해 반올림했다.

**고르는 순간**: 보상 3번 → **보상 3번 + 구매 7번 + 새로고침 · 잠금 · 판매** — 한 판에 12 ~ 15번.

## 7. (선택) 스테이지 안에서 쓰는 곳 — 보급 상자

상점까지 기다리지 않고 **전투 중에도** 크레딧을 쓰게 한다 (Risk of Rain 2 의 상자처럼).

- 처치 진행이 50%가 되면 맵 어딘가에 **보급 상자**가 떨어진다
- 15 크레딧으로 열면 들고 있는 무기의 **무작위 부품 1개**
- "지금 열까, 모아서 보스 전에 쓸까"라는 고민이 생긴다
- 처치 진행 이벤트(`OnStageProgress`)를 받는 새 스크립트로 만든다 — 적 코드는 그대로

## 8. 구현 구조 (초안)

```
CreditWallet (Player, 새 파일)
  └ 잔액 · Add · TrySpend · 바뀌면 알림      ← PlayerStats.AddExp 가 같은 양을 더한다

ShopItem (새 파일) = StageReward + 가격
  └ 무기 보상(WeaponReward) · 부품 보상(AttachmentReward, 커스터마이징 7장)을 **그대로 상품으로** 쓴다
    ─ 상품 제목 · 아이콘 · CanOffer · Apply 가 이미 있다
  + 수리 · 장갑 판 같은 소모품은 StageReward 를 새로 상속

ShopStock (새 파일)   — 진열 5칸 뽑기 · 새로고침 값 · 잠금 · 스테이지별 가격 배율
ShopUI (새 파일)      — 진열 · 구매 · 판매 · 새로고침 · 잠금 · "출발"
```

**고칠 파일**

| 파일 | 폴더 | 내용 |
|---|---|---|
| `PlayerStats.AddExp` | Player | 크레딧도 같이 더한다 |
| `PlayerStatsUI` | Player | 크레딧 숫자 |
| `WeaponController` | Player | 무기 **판매**(빼기) — 지금은 얻기만 있다 |
| `GameManager` · `GameEvents` | **Core — 협의** | 보상 뒤 상점 단계, 상점 동안 60초 제한 끄기, 상점 이벤트 2개 |
| 빌드 순서 · 새 씬 (B 만) | **프로젝트 설정 — 협의** | 4장 |

- **보상 시스템과 상점이 같은 상품을 쓴다.** 부품([무기-커스터마이징-조사.md](무기-커스터마이징-조사.md) 7장)을 만들어 두면 보상 카드 · 상점 · 보급 상자 세 곳에서 모두 나온다
- 상점 UI 는 설정창 · 테스트 룸과 같은 색 · 글꼴을 쓴다. 글꼴 기본 재질은 글자를 하얗게 포화시키므로 전용 재질을 쓴다 (플레이어-사운드-설계 1-4)

## 9. (선택) 판을 넘어 남는 재화

Enter the Gungeon 의 헤게모니 크레딧, Vampire Survivors 의 골드처럼 **판 밖 재화**를 둘 수도 있다.

| 항목 | 제안 |
|---|---|
| 이름 | 데이터 코어 |
| 얻는 법 | 보스 처치 · 스테이지 클리어마다 조금, 판이 끝날 때 남은 크레딧의 10% |
| 쓰는 곳 | **로비**에서 무기 · 부품을 상점 · 보상 후보에 **풀어 두기** (처음에는 일부만 나온다) |
| 저장 | `PlayerPrefs` (설정창 음량과 같은 방식) |

- 장점: 다시 할 이유가 생긴다. 새 부품이 "해금"으로 천천히 드러난다
- 단점: 해금 화면 · 저장 · 초기화가 필요해 범위가 커진다
- 캡스톤 시연(한두 판)에는 효과가 작다 → **판 안 상점을 먼저**, 판 밖 재화는 마지막에

## 10. 단계별 추천

| 단계 | 내용 |
|---|---|
| 1 | 크레딧(경험치와 같이) + HUD 숫자 + **상점 창(A)** — 무기 · 수리 · 장갑 판만. 가격 · 수입을 플레이로 맞춘다 |
| 2 | 부품(커스터마이징 9장 1단계)을 상품에 추가 + 새로고침 · 잠금 · 판매 |
| 3 | 보급 상자(7장), 전용 개조 |
| 4 | **정비 구역 씬(B)** — 테스트 룸을 바탕으로, 상품이 받침대 위에 놓이고 해골로 시험 |
| 5 | (선택) 판 밖 재화 |

## 11. 결정이 필요한 것

| 질문 | 선택지 |
|---|---|
| 상점 방식 | 상점 창(A) 먼저 → 정비 구역(B) (추천) / 처음부터 B / 터미널(C) |
| 보상 카드와의 관계 | 무료 보급 1장 유지 + 상점 (추천) / 보상 카드를 상점으로 대체 |
| 재화 출처 | 경험치 구슬과 같이 (추천) / 적이 크레딧을 따로 떨어뜨림 (적 코드 협의) |
| 남은 구슬 | 클리어 때 끌어당김 (구슬 코드 협의) / 크레딧만 대신 지급 / 그대로 |
| `GameManager` 수정 | 상점 단계 · 60초 제한 — Core 폴더 협의 |
| 빌드 순서 (B) | 다음 스테이지 기억 (Core) / 작은 씬 3개 (프로젝트 설정) |
| 판 밖 재화 | 없음 (추천, 시연 기준) / 데이터 코어 |
| 보스 뒤 | 지금처럼 엔딩 / 결과 화면에 남은 크레딧 표시 |
