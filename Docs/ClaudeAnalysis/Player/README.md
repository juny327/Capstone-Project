### 긍정적으로 평가되는 부분

- `GameEvents` 정적 이벤트로 씬 간 결합도를 낮춤 (플레이어가 `DontDestroyOnLoad`인 구조에 적합)
- `IDamageable` / `IStatusReceiver` / `IPoolable` 인터페이스로 책임 분리
- 총알·이펙트·탄피·EXP 오브 전부 `PoolManager` 경유 (GC 압력 억제)
- `PlayerMove.speedModifiers` 리스트 방식으로 슬로우·스턴 **중첩**을 자연스럽게 처리
- `Bullet` / `ExpOrb`가 `MaterialPropertyBlock` 사용 → 머티리얼 인스턴싱 회피

## 우선 조치 Top 3

1. **C-2 · `EnemyDetector`가 보스 카운트를 반환하지 않음** — 보스전 전체에 영향. 보스가 감지 범위를 벗어나거나 죽어도 자동공격이 허공에 계속 발사되고 공격 애니메이션이 고착됨.
2. **C-1 · 사망 처리 중복 실행** — `isDead` 가드 부재로 사망 후 추가 피격 시 `Die()`가 반복 호출됨. 파티클 중복 생성 + `OnPlayerDeadStart` 다중 발행.
3. **H-4 · 플레이어 스폰 시스템 이원화** — `GameAppManager`와 `RunManager`가 각각 플레이어를 생성. 구조적 리스크가 가장 크고, 방치할수록 정리 비용이 커짐.

## 확장을 시작한다면

확장 설계서(04·05)는 기존 이슈와 **수정 지점이 겹치는 항목**을 각 문서 서두에 선행 조건으로 명시했다.

| 확장 방향 | 선행 조치 | 이유 |
|---|---|---|
| 이동 (대시·회피) | C-1 · M-6 | 무적 프레임 가드가 사망 가드와 같은 진입부. 속도 배율 스택 재설계가 M-6를 흡수 |
| 무기 (다중 무기·슬롯) | **C-2 · C-3 · M-9** | `ITargetProvider`가 `EnemyDetector`를 다시 쓴다. 위 Top 3의 1번과 동일 작업 |

두 방향은 서로 독립이므로 병렬 진행이 가능하다. 다만 무기 쪽은 `EnemyDetector` 재작성이 **선행 필수**다.
