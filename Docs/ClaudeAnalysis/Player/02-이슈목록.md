## 🔴 Critical

### C-1. 사망 처리가 중복 실행됨

- **증상**: 사망 파티클이 여러 개 생성되고, `OnPlayerDeadStart`가 반복 발행되며, `Die` 애니메이션이 처음부터 다시 재생된다.
- **원인**: `currentHp`가 0으로 clamp되므로 사망 이후 추가 피격이 들어와도 `currentHp == 0` 조건이 계속 참이 된다. `isDead` 같은 가드가 전혀 없다.
- **위치**: `Assets/Scripts/Player/PlayerStats.cs:61-79` (특히 `:65-66` clamp, `:75` 조건)
- **재현**: 다단 히트 스킬(보스 폭탄, 자폭 몹 다수) 또는 여러 적에게 동시에 맞으며 사망. 사망 시점 이후 도착한 총알/장판 틱마다 `Die()`가 재호출된다.
- **참고**: `OnPlayerDeadStart`의 구독자에는 `BossSkillController.StopAllSkills`, `AutoAttack.StopAttack`이 포함되어 있어 중복 호출 시 부작용이 예측하기 어렵다.

### C-2. 보스는 감지 카운트를 절대 반환하지 않음

- **증상**: 보스가 감지 범위를 벗어나거나 사망해도 `Count`가 0으로 돌아오지 않는다. 자동공격이 적이 없는 방향으로 무한 발사되고, `isAttack` 애니메이션 파라미터가 true로 고착된다.
- **원인**: `OnTriggerEnter`는 `Boss` 태그에 대해 `Count++`를 하지만, `OnTriggerExit`의 `Count--`는 `Enemy` 태그 블록 **안에만** 있다. Boss 태그를 처리하는 exit 분기가 아예 없다.
- **위치**: `Assets/Scripts/Player/EnemyDetector.cs:18-21` (enter) vs `:28-41` (exit)
- **재현**: 보스 스테이지에서 보스에게 접근한 뒤 멀어진다. 이후 일반 몹이 없어도 계속 사격한다. 보스 처치 후에도 동일.

### C-3. 적이 감지 범위 안에서 죽으면 카운트 이중 감소 + 애니메이션 고착

- **증상 A (이중 감소)**: `Count`가 실제 적 수보다 작아져, 주변에 적이 남아 있는데도 자동공격이 멈춘다.
- **증상 B (애니메이션 고착)**: 범위 안 마지막 적이 죽어 `Count`가 0이 되어도 `isAttack`이 true로 남는다.
- **원인**:
  - A: `HandleEnemyDeath`가 `Count--` 한 뒤, 적 오브젝트가 풀로 반환되며 콜라이더가 비활성화되는 순간 Unity가 `OnTriggerExit`를 한 번 더 호출해 또 `Count--` 한다.
  - B: `HandleEnemyDeath`에는 `Count == 0`일 때 `OnEnemyEnter?.Invoke(false)`를 발행하는 코드가 없다. 해당 발행은 `OnTriggerExit` 안에만 존재한다.
- **위치**: `Assets/Scripts/Player/EnemyDetector.cs:43-49`
- **재현**: 감지 범위 안에서 적을 사살한다. `Count`를 로그로 찍어보면 1마리 사망에 2가 감소한다.
- **부가**: `Count < 0` 클램프가 있어 음수로는 안 가지만, 이것이 오히려 불일치를 조용히 감춘다.

## 🟠 High

### H-1. 상태이상 코루틴이 중단되면 슬로우/스턴이 영구화

- **증상**: 슬로우나 스턴에 걸린 상태로 특정 상황을 거치면 이동 배율이 원복되지 않고 영구히 남는다. 머리 위 스턴 이펙트도 계속 붙어 있다.
- **원인**: `target.GetComponent<MonoBehaviour>()`는 GameObject에 붙은 **임의의 첫 번째** MonoBehaviour를 반환한다(컴포넌트 순서 의존, 결정적이지 않음). 하필 `AutoAttack`이 반환되면, 사망 시 `StopAttack()`이 `enabled = false`로 만드는 순간 코루틴이 중단되어 `RemoveSpeedModifier`가 실행되지 않는다. 컴포넌트가 비활성화·파괴되는 모든 경로가 동일한 위험을 갖는다.
- **위치**: `Assets/Scripts/Player/SlowEffect.cs:18-20`, `Assets/Scripts/Boss/BossSkill/StunEffect.cs:16-18`
- **재현**: 슬로우 상태에서 사망 → (플레이어가 파괴되지 않는 경로가 생기면) 배율 잔존. 컴포넌트 순서에 따라 재현 여부가 달라진다는 점 자체가 문제다.
- **비고**: `PlayerStatus`가 이미 코루틴 호스트로 적합한 위치에 있으나 활용되지 않고 있다.

### H-2. `CameraShakeManager` 싱글턴이 파괴된 객체를 가리킴

- **증상**: 스테이지 전환 후 플레이어가 피격당할 때 `MissingReferenceException` 발생 가능.
- **원인**: 두 겹의 문제.
  1. `Awake`에서 중복 검사 없이 `Instance = this`만 하고 `DontDestroyOnLoad`도 없다. 씬이 바뀌면 기존 객체가 파괴되지만 `Instance`에는 파괴된 참조가 남는다(새 씬에 매니저가 있으면 덮어쓰지만, 없거나 순서가 어긋나면 그대로 남는다).
  2. 호출부가 `CameraShakeManager.Instance?.Shake(...)`인데, C#의 `?.`는 **Unity가 오버로드한 `==` 연산자를 우회한다**. 즉 파괴된 Unity 객체(fake null)를 null로 걸러내지 못하고 그대로 `Shake`를 호출한다.
- **위치**: `Assets/Scripts/Player/CameraShakeManager.cs:6-13`, 호출부 `Assets/Scripts/Player/PlayerStats.cs:70-73`
- **재현**: Stage1 → Stage2 전환 후 피격. `impulseSource` 미할당 시에도 동일하게 NRE.

### H-3. `PlayerStatsUI`의 이벤트 중복 구독

- **증상**: 스테이지를 넘어갈수록 HP바 애니메이션이 2번, 3번... 중첩 재생된다. HP 텍스트 갱신도 중복 호출된다.
- **원인**: 플레이어는 `DontDestroyOnLoad`로 유지되는데 `OnPlayerSpawned`는 스테이지 로드마다 발행된다. `SetPlayer`는 매번 `stats.OnHpChanged += ...`만 하고 이전 구독을 해제하지 않는다. `OnDisable`의 해제 코드는 UI 오브젝트가 파괴될 때만 동작하므로, **동일한 `stats` 인스턴스에 핸들러가 누적**된다.
- **위치**: `Assets/Scripts/Player/PlayerStatsUI.cs:56-64` (구독), `:38-43` (해제 — 시점이 맞지 않음)
- **재현**: Stage1 → Stage2 → Stage3 진행 후 피격. 각 스테이지의 UI 오브젝트가 파괴되며 해제되긴 하지만, 동일 씬 내에서 `OnPlayerSpawned`가 두 번 발행되는 경로가 생기면 즉시 재현된다.

### H-4. 플레이어 스폰 시스템이 두 개 공존

- **증상**: 설정에 따라 플레이어가 2개 생성되거나, 반대로 UI·카메라·업그레이드가 플레이어를 전혀 찾지 못한다.
- **원인**: 두 매니저가 각각 `playerPrefab`을 `Instantiate` + `DontDestroyOnLoad` 한다.
  - `GameAppManager.SetupPlayer` — `sceneLoaded` 훅에서 자동 실행, `OnPlayerSpawned` 발행함
  - `RunManager.SpawnPlayer` — `PlayerSpawnPoint.Start()`가 호출, **`OnPlayerSpawned`를 발행하지 않음**
  - 두 매니저는 서로의 존재를 모르고, 각자 별도의 싱글턴 `Instance`를 갖는다.
- **위치**: `Assets/Scripts/Core/GameAppManager.cs:60-82`, `Assets/Scripts/Core/RunManager.cs:29-36`, `Assets/Scripts/Core/PlayerSpawnPoint.cs:5-8`
- **재현**: 씬에 `PlayerSpawnPoint`와 `GameAppManager`가 함께 있으면 플레이어 중복. `RunManager` 경로만 살아 있으면 HUD가 전부 비고 카메라가 따라오지 않는다.
- **부가**: `GameAppManager`는 스폰 위치가 `new Vector3(0,1,0)` 하드코딩(`:13`)이고, `RunManager`는 `PlayerSpawnPoint`의 위치를 쓴다. 스폰 위치 정책도 이원화되어 있다.

## 🟡 Medium

### M-1. 이동속도 UI 값이 실제와 불일치
`AddSpeed`가 `CurrentSpeed`가 아닌 `baseSpeed`를 발행한다. 슬로우/스턴 상태에서 속도 업그레이드를 획득하면 HUD가 실제보다 빠른 값을 표시한다. `AddSpeedModifier`/`RemoveSpeedModifier`는 올바르게 `CurrentSpeed`를 발행하고 있어 더 눈에 띈다.
→ `Assets/Scripts/Player/PlayerMove.cs:167-172` (`:171`)

### M-2. 사망 파티클 누수
`deathParticle`에 `ParticleSystem` 컴포넌트가 없으면 `Destroy` 호출 자체가 `if (ps != null)` 블록 안에 있어 실행되지 않는다. 파티클 오브젝트가 씬에 영구 잔류한다. 또한 `float delay = 5f` 기본값은 `ps`가 없으면 아무 데도 쓰이지 않는 죽은 값이다.
→ `Assets/Scripts/Player/PlayerStats.cs:86-99`

### M-3. 사망 대기 시간 하드코딩 + 애니메이션 이벤트 의존
파티클 길이로 `delay`를 계산해놓고 정작 `DeathSequence`는 `WaitForSeconds(3)` 고정값을 쓴다. 더 중요한 건 `EndingDieAnim()`이 **애니메이션 이벤트로만 호출**된다는 점 — Die 클립에 이벤트가 누락되거나 클립이 교체되면 `OnPlayerDeadEnd`가 영원히 발행되지 않아 게임오버 UI가 뜨지 않고 게임이 멈춘다. 코드상 호출부가 0개라 IDE 검색으로는 죽은 코드처럼 보인다.
→ `Assets/Scripts/Player/PlayerStats.cs:94`, `:109-119`

### M-4. `PlayerInput` 인스턴스 미해제
`Awake`에서 `new PlayerInput()`으로 생성하지만 `OnDestroy`에서 `Dispose()`를 호출하지 않는다. Input System의 네이티브 리소스가 인스턴스마다 누수된다. 플레이어가 재생성되는 구조라 반복 누적된다.
→ `Assets/Scripts/Player/PlayerMove.cs:55`

### M-5. `Update`의 null 미검증
`cam.ScreenPointToRay(Mouse.current.position.ReadValue())` — `cam`과 `Mouse.current` 모두 무방비. 카메라가 미할당된 씬이나 마우스 미연결(패드 전용) 환경에서 매 프레임 NRE가 발생한다. `Awake`의 `cam = Camera.main` 폴백도 씬에 MainCamera 태그가 없으면 null이다.
→ `Assets/Scripts/Player/PlayerMove.cs:94-103`

### M-6. `speedModifiers` 초기화 경로 없음
사망, 씬 전환, 스테이지 클리어 어디에서도 리스트를 비우지 않는다. 플레이어가 `DontDestroyOnLoad`로 유지되는 구조라, 슬로우가 걸린 상태로 스테이지를 클리어하면 배율이 다음 스테이지까지 넘어갈 수 있다(H-1과 결합하면 영구화).
→ `Assets/Scripts/Player/PlayerMove.cs:13`, `:28-38`

### M-7. 총알이 지형을 관통
`OnTriggerEnter`가 `Enemy`/`Boss` 태그만 처리하므로 벽·바닥·장애물을 그대로 통과한 뒤 수명(3초)까지 날아간다. 엄폐 개념이 성립하지 않고, 벽 너머 적을 맞힐 수 있다.
→ `Assets/Scripts/Player/Bullet.cs:62-85`

### M-8. 크리티컬 수치가 하드코딩
`critMultiplier = 2f`, `critChance = 0.05f`가 `Bullet` 내부 상수라 `Gun`이나 업그레이드에서 조정할 수 없다. `[SerializeField]`도 아니어서 인스펙터 조정조차 불가능하다. 크리티컬 관련 업그레이드를 추가하려면 데이터 경로부터 새로 만들어야 한다.
→ `Assets/Scripts/Player/Bullet.cs:8-10`

### M-9. `EnemyDetector`의 `GetComponent<Enemy>()` 무검증
`Enemy` 태그가 붙었으나 `Enemy` 컴포넌트가 없는 오브젝트(자식 콜라이더, 히트박스 전용 오브젝트 등)가 트리거에 들어오면 `enemy.OnDeath` 접근에서 NRE. enter/exit 양쪽 모두 해당된다.
→ `Assets/Scripts/Player/EnemyDetector.cs:14-16`, `:32-35`

### M-10. `AutoAttack` / `Gun`의 참조 무검증
`detector`, `gun`, `muzzle`, `bulletCase`, 각종 프리팹, `PoolManager.Instance`까지 어느 것도 null 체크가 없다. 인스펙터 할당 누락 시 매 프레임 NRE가 발생하며, 원인 파악이 어렵다.
→ `Assets/Scripts/Player/AutoAttack.cs:5-6`, `Assets/Scripts/Player/Gun.cs:19-47`

### 추가로 검토할 만한 사항 (버그는 아님)

- **무적 시간(i-frame) 없음** — `TakeDamage`에 쿨다운이 없어 다단 히트 판정이 겹치면 한 프레임에 HP가 순삭될 수 있다.
- **`ExpandHP`가 `currentHp`를 올리지 않음** — 최대 HP만 증가시키는 것이 의도라면 문제없으나, 업그레이드 카드 설명과 체감이 어긋날 수 있다. 의도 확인 필요.
- **스탯이 전부 MonoBehaviour 인스펙터 필드** — `maxHp`, `baseSpeed`, `attackRate`, `bulletDamage`, `bulletSpeed`가 프리팹에 흩어져 있어 밸런싱 시 여러 컴포넌트를 오가야 한다. `EnemyData`, `StageData`의 ScriptableObject 패턴이 이미 프로젝트에 있으므로 동일하게 적용 가능하다.
- **`UpgradeManager.TryUpgrade`의 `playerStats` null 미검증** — `OnPlayerSpawned`보다 먼저 업그레이드 UI가 열리는 경로가 생기면 NRE (`Upgrade/UpgradeManager.cs:36`).
- **`UpgradeManager.GetRandomUpgrades`가 `count > upgradePool.Count`를 검증하지 않음** — `Random.Range(0, 0)` 후 빈 리스트 인덱싱으로 예외 (`Upgrade/UpgradeManager.cs:49-62`).
