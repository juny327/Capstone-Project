## 2. 보스 등장 연출

등장 연출은 **보스 스테이지가 아니라 따로인 인트로 씬(`IntroScene`)에만** 있다. 빌드 순서가 Stage3 다음이 IntroScene 이라 정비 창을 닫으면 여기로 온다. 플레이어는 숨겨지고 배경음은 없다 (배경음 목록 `AUDIO/MusicSet` 에 IntroScene 이 없어 앞 곡이 페이드아웃).

**인트로 타임라인 (`Timeline/TimeLineIntro`, 약 9.3초)**

| 시간 | 일어나는 일 |
|---|---|
| 0 ~ 1.3초 | 골렘 GetHit 동작 — 깨어나는 느낌 |
| 1.5 ~ 4.0초 | 등장 이펙트(`BossSpawnEffect`) 두 개 · 1.6 ~ 3.9초 걸어 나옴 (Walk) |
| 3.9 ~ 6.6초 | 포효 (Victory 동작) · 4.0 ~ 6.1초 등장 이펙트 두 개 더 |
| 6.6 ~ 9.3초 | 대기 (Idle) · 문구 **"Boss Spawn"** 이 뜨는 애니메이션 |
| 끝 | **"Start"** 버튼이 나타나고, 누르면 보스 스테이지 (`SequenceController`) |

- 카메라: Cinemachine 카메라 + 녹화한 애니메이션 트랙
- 문구 · 버튼이 영어 임시 글자다 ("Boss Spawn" · "Start" — 버튼은 Space Exploration GUI Kit 보라 버튼)

**보스 스테이지 (`StageBoss`)**

1. 플레이어가 시작 자리에 서고, 보스는 꺼진 채로 있다
2. **2초 뒤 보스가 켜진다** (`BossTestSpawner` — 이름은 시험용이지만 실제로 쓰임). 등장 이펙트 · 카메라 연출 없이 그 자리에 나타남
3. 켜지는 순간 보스 등장 소리 (Kenney forceField_000) · 배경음은 Torone action-1
4. 보스 체력바는 **처음 맞을 때** 뜬다 — 빨강 · 주황 · 초록 막대 3개로 3등분 (페이즈는 없다)
5. 보스는 플레이어가 15m 안에 들어오면 움직이기 시작, 스킬은 켜진 뒤 2초부터

**끝** — 체력 0 → Die 동작 1.2초 → 동작 끝 이벤트로 승리 → 엔딩 씬 (타임라인 뒤 "You Win" 패널 · 로비 버튼). 클리어 보상 · 판 결과 화면은 없다.

| 체력 | 1000 (정수) | `BossHealth.maxHp` |

| 근접 피해 | 20 | 손 뼈의 `L_Box` · `R_Box` — `BossAtkCol.damage` |
| 판단 주기 | 0.2초 | `BossBrain.tickInterval` |
| 바위 던지기 | 표식 1.2초 · 바위 30 · 반경 2m · 높이 5m · 비행 1.2초 | `BossBombSkill` (`warningTime`) · `Prefabs/Projectile` (`BossProjectile`) |

## 6. 문제점 · 개선 제안

먼저 할 것은 **① 등장 연출을 보스 스테이지 안으로 · ② 체력바 3등분에 맞춘 페이즈 · ③ 근접 공격 예고**다. 세 가지가 들어가면 보스전이 "큰 몬스터 하나"에서 "마지막 클라이맥스"가 된다.

**지금 문제**

| # | 문제 | 내용 |
|---|---|---|
| 1 | 등장이 떨어져 있다 | 인트로 씬에서만 걸어 나와 포효하고, 실제 전투에서는 2초 뒤 그 자리에 그냥 켜진다. 버튼을 눌러야 넘어간다 |
| 2 | 임시 글자 · 소리 | "Boss Spawn" · "Start" · "You Win" 영어 · 인트로 배경음 없음 · 공격 · 스킬 · 피격 · 사망 소리 없음 |
| 3 | 패턴이 단조롭다 | 근접 2종 번갈아 + 스킬 3종 고정 순서 · 페이즈 · 분노 없음 (체력바만 3등분) |
| 4 | 근접 예고가 없다 | 바닥 표시 없이 0.8 ~ 1.5초 뒤 손 판정 — 동작을 보고 피해야 한다 |
| 5 | 맞아도 반응이 없다 | 큰 한 방(공성포 · 태양창 · 붕괴)에도 그대로 · 보스용 피해 숫자 없음 |
| 6 | 정수 피해 | 피해를 정수로 잘라 받아 1 미만은 0 (보조 샷건 탄 등) |
| 7 | 군중 제어가 안 먹힌다 | 경직 · 둔화 · 끌기는 일반 몬스터만 — 의도라면 괜찮지만 알리는 표시가 없다 |
| 8 | 클리어 보상 없음 | 쓰러뜨리면 바로 엔딩 — 판 결과 화면 없음 |
| 9 | 정리 | `BossTestSpawner` (시험용 이름인데 실제 등장) · `BossBrain` "테스트용 반드시 지울것" 주석 · 쓰지 않는 `trackingTime` |

## 8. 패턴 · 연출 개선 계획 (2026-11-20 — 같은 날 구현했다: 9 · 10절)

## 9. 패턴 개선 구현 (2026-11-20 — 0 ~ 3단계, 커밋 전)

계획(8절)대로 넣었다. 측정 표와 계획에서 달라진 점은 Claude 문서 「보스 패턴 개선 계획」 끝의 "진행 기록"에 있다.

**난이도별 값 묶음** — `DragonBossSettings.Tuning` (`Resources/Dragon/DragonBossSettings` 의 `easy` · `hard`). 보스가 깨어날 때 `LoadTuning(Difficulty.Current)` 로 읽는다. `DragonBossSettings.Legacy()` 는 고치기 전 움직임 (측정 · 옛 시험용).

| 값 | 이지 | 하드 | 하는 일 |
|---|---|---|---|
| `tempo` | 0.85 | 1 | 패턴 진행 속도 — 예고에만 곱한다 (불 뿜는 시간 · 꼬리 회전은 실제 시간) |
| `recoverScale` | 1.4 / 1.4 / 1.4 | 1 / 0.85 / 0.7 | 패턴 사이 빈틈 (1 · 2 · 3페이즈) |
| `cooldownScale` | 1.25 | 1 | 패턴 쿨타임 |
| `comboChance` | 0 / 0 / 0.25 | 0 / 0.35 / 0.55 | 연계 확률 |
| `lateLock` · `biteLock` · `chargeLock` | 끔 | 켬 · 0.75 / 0.57 / 0.46초 · 0.7초 | 물기 · 지연 물기 · 돌진이 플레이어를 따라오다 굳는다. 돌진은 "플레이어 자리에 닿기 0.7초 전" (멀수록 늦게 굳힘) |
| `leadFireballs` | 끔 | 켬 | 불덩이 2발째는 갈 자리, 3발째는 그 절반 |
| `breathTrack` | 0 | 15°/s | 2페이즈부터 뿜는 동안 따라 돈다 |
| `sweepMeets` · `sweepTime` | 끔 · 2.3초 | 켬 · 1.9초 | 휩쓸기 브레스가 가는 쪽에서 마주 온다 |
| `rainRing` · `rainCount` | 끔 · 5 | 켬 · 7 | 불비가 둘레를 먼저 막고 가운데가 마지막 |
| 부하 · 불 장판 | 2 / 3 (최대 4) · 4초 8개 | 3 / 4 (최대 6) · 6초 14개 | |
| `newPatterns` | 끔 | 켬 | 새 패턴 3종 |
| `enrageTempo` | 1 | 1.1 | 남은 체력 10%(`Staging.enrageAt`) 아래에서 진행 속도 |

굳는 순간에는 예고 테두리가 흰색으로 바뀌고 짧은 경고음이 난다 (`LockAim` → `DragonTelegraph.Lock`).

**새 패턴 3종 (하드 2페이즈부터)** — `DragonBoss.NewPatterns.cs` · `DragonHazards.cs` (`DragonFireWall` · `DragonRingWave`). 값은 보스 프리팹에 적혀 있다.

| 패턴 | 하는 일 | 시험 키 |
|---|---|---|
| 불의 벽 `FireWall` | 포효 0.8초 뒤 플레이어 양옆 5m 에 길이 12m 불 벽 두 줄(3.4초, 0.5초마다 8) → 그 사이로 돌진 (6.5m 보다 가까우면 브레스) | B |
| 퍼지는 고리 `RingWave` | 몸에서 고리가 0.7초 간격으로 퍼진다 (2겹 · 3페이즈 3겹, 초속 9m, 15 피해). 틈 70° 는 플레이어가 가던 쪽의 반대편 | G |
| 도약 내려찍기 `Leap` | 멀리 있으면 뛰어올라 플레이어 자리로 떨어진다. 표시가 초속 3.5m 로 따라오다 0.9초 전에 굳는다 (범위 3.45m · 25 피해 · 착지 뒤 빈틈 1.2초) | J |

연계 — 불의 벽 → 돌진(패턴 안) · 도약 → 꼬리 휩쓸기(3페이즈, 절반) · 퍼지는 고리 → 불비(3페이즈).
시험 키는 테스트 룸 보스 구역에서: F1 ~ F12 기존 패턴 · B · G · J 새 패턴 · **H 보스 값만 이지 ↔ 하드** (왼쪽 아래에 지금 값이 보인다).

**측정** — `Logs/evo_resume/kept_BossDodgeBot.cs` (봇: 서 있기 · 한쪽으로만 걷기 · 예고를 읽고 피하기). 패턴마다 6번:

| | 고치기 전 | 이지 | 하드 |
|---|---|---|---|
| 한쪽으로만 걷기 — 1페이즈 패턴 5개 | 20% 맞음 | 20% | 90% |
| 한쪽으로만 걷기 — 기존 패턴 11개 | 64% | 64% | 95% |
| 읽고 피하기 | 0% | 0% | 0% (새 패턴 포함 1/90) |

- 난이도 기준(봇이 몇 % 맞아야 한다 등)은 두지 않는다 — 사용자가 직접 플레이하며 조정한다 (2026-11-20 결정). 위 수치는 "옆걸음으로 피해지던 패턴이 하드에서는 맞는다"를 확인한 것.
- 측정할 때는 보스 스테이지 맵의 함정 구역(`DeepSpaceHazard` 4개 — 초당 4 피해 · 감속)을 끈다. 실제 보스전에서는 켜져 있다.
- **새 값은 프리팹에 적는다** — 프리팹에 없는 새 `[SerializeField]` 는 코드 기본값을 고쳐도 반영되지 않는다 (partial 클래스라 프리팹이 다시 들여와지지 않는다). `python -I Logs/evo_resume/sync_dragon_prefab.py` 가 빠진 값을 코드 기본값으로 추가한다 (이미 적힌 값은 안 건드린다).

## 10. 연출 구현 (2026-11-20 — 흔들림 · 공격 이펙트 · 압박감, 커밋 전)

8절의 연출 계획 세 묶음을 넣었다. 판정 · 피해 · 예고 시간은 그대로다. 전후 영상: https://claude.ai/artifact/DEUDchzki7gsDEQ74bwRW9

**화면 흔들림** (`DragonBoss.Staging.cs`) — 세기만 다른 충격 하나였던 것을 세 단계로.

| 단계 | 함수 | 쓰는 곳 | 모습 |
|---|---|---|---|
| 작게 | `Jolt` | 발걸음 · 불덩이 발사 · 불비 한 발 · 부르는 포효 | 짧은 떨림 |
| 중간 | `Shove` | 물기 · 연속 물기 · 꼬리 · 돌진 출발 · 브레스 시작 | 공격이 간 쪽으로 화면이 밀렸다 돌아온다 |
| 크게 | `Quake` | 땅 물어뜯기 · 벽 충돌 · 도약 착지 · 전환 포효 · 첫 고리 | 아래로 쿵 + 줌 + 가장자리 불빛 |

`Tremor` = 브레스 · 돌진 · 포효 동안 이어지는 떨림 · `Hush` = 큰 한 방 직전의 정적 · `Near` = 거리 감쇠(8m 안 그대로 → 16m 밖 절반) · `StepFx` = 가까울수록 큰 발걸음. 모두 설정 창의 '화면 흔들림'을 따른다.

**공격 이펙트** — 패턴 14개(기존 11 + 새 3)에 무기 연출의 입자 재료(`FxKit`)를 입혔다. 불덩이는 보스가 쏜 탄에만 `DragonFireballFx`(불 꼬리 · 착탄 폭발)를 붙인다. 예고는 다 차기 직전 테두리가 깜박인다(`DragonTelegraph.Blink`). 2페이즈부터 입가에 불티, 3페이즈는 몸 둘레의 열기, 큰 한 방(최대 체력 1.2% 넘게)을 맞으면 몸이 번쩍이고 움찔한다.

**압박감** (`DragonPressure.cs` — 보스가 깨어날 때 붙인다) — 보스전 동안 시야 ×1.1 · 큰 공격 준비 때 시야 당김 · 페이즈별 가장자리 어둡기(0 / 0.28 / 0.5 — 검정만) · 큰 공격 준비 때 맥박 · 배경음 잠깐 줄이기 · 예고 안에 서면 발밑 고리가 붉어짐 · 화면 밖 보스가 공격하면 가장자리 화살표 · 페이즈가 바뀔 때 체력바 번쩍임(`BossHPUI` 는 건드리지 않는다). `ImpactFx` 의 시야는 한 곳에서 다룬다: 원래 값 × `Widen` × (1 − `Zoom` − `Lean`).

**값** — `DragonBossSettings.Staging` (설정 에셋의 '연출'): `enabled` 전체 · `shakeScale` · `attackFx` · `fxScale` · `bodyMarks` · `flinch` · `telegraphBlink` · `pressure` · `cameraWide` · `windupLean` · `edgeDark` · `dangerRing` · `edgeArrow` · `barBreak` · `enrageAt`. 코드에서 `DragonBoss.StagingOff = true` 면 예전 그대로 (전후 캡처의 '전').

**확인** — `Logs/evo_resume/kept_DragonFxCapture.cs` 가 패턴 14개를 전 · 후로 찍고, 압박감 10항목(시야 · 가장자리 · 발밑 고리 · 화살표 · 체력바 · 움찔)을 본다.

- 보스전 카메라는 멀다 (1m 가 14px 쯤, 일반 스테이지는 33px) — 2m 아래 이펙트는 점으로 보인다.
- 안 넣은 것: 소리(낮은 울림 · 3페이즈 심장 박동 — 사운드 작업 보류 중) · 아슬한 회피 슬로 · 휘청 게이지.
