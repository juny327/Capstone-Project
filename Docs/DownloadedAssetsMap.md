# Stage1 — Asteroid Mining Outpost

## Assets

- 3D Asteroid Pack, Entian-Astea: the URP asteroid meshes and materials form the surrounding asteroid field.
- Rocks FREE pack, DEXSOFT: rock meshes form four mining outcrops and four short cover banks. Original Standard materials are preserved; new URP copies live under `Assets/OrbitMap/AssetEdition/Materials`.
- Terrain Textures Pack Free, Objective Environment: GroundCracked diffuse and normal textures cover the lunar soil between metal transit lanes. `OrbitGroundUV` applies continuous world-sized UVs after runtime map generation.

All three are user-owned Asset Store downloads. Keep their original paths, metadata and applicable license terms with the project. The repository includes the map dependencies and editor-builder dependencies only; unused grass/leaf textures and vendor demo scenes are omitted.

## Scene and backup

The lobby still loads `Assets/Scenes/Stage1.unity`, keeping its existing GUID and build index. Stage2, Stage3, and StageBoss now have distinct space environments using the same downloaded assets; see [CampaignMaps.md](CampaignMaps.md). The previous orbital map is copied to `Assets/Scenes/MapBackups/Stage1_BeforeDownloadedAssets.unity` before the asset edition is built.

The former procedural decoration root is disabled in Stage1. The replacement is grouped under `Orbit Asset Edition`. `Stage1_Orbit` remains the old design scene and is not the source of truth for this edition.

## Layout and navigation

The 70 × 70 orbital map keeps the central arrival pad, cross-shaped metal lanes, four 5 × 9 obstacle islands, and four 5 × 3 cover banks. Rock geometry is fitted inside these existing wall footprints. Decorative asteroids are outside the playable area and excluded from the existing NavMesh layer mask. Gameplay floor and wall colliders remain generated by MapRenderer.

The setup command is `OrbitAssetMapSetup.Build()` through Unity Editor eval. It creates a backup, refuses to run over an existing asset edition, checks connected ground and four navigation routes, then saves Stage1. For later tuning, edit the grouped scene objects. Changing gameplay footprints also requires updating OrbitalMapLayout.
